# 保存済み画像の参照復旧

## 対象と責務

REQ-CREATION-RECOVERYは、保存済み画像があるのに、プリセットが競合失敗した別操作を参照している記録を復旧する。キャラクター代表画像とストーリーバナーを対象とする。通常の完了照合や古い結果の適用条件は変更しない。

公開APIのClient.inspect_image_linksが候補を記録し、Client.repair_image_linksがその確認IDを適用する。CLIのrepair-imagesも同じ処理を呼ぶ。HTTPの通常取得や起動時に参照を書き換えない。LLM、画像生成、GPU確保は行わない。

## 確認と適用

候補確認では既存DBを読み取り専用で開く。同じ対象・版・用途・描画入力の生成操作が一意で、保存済みRun、画像のSHA256・サイズ・寸法と実ファイルが対応する場合だけ修復可能とする。過去の入力全体を保存した記録も型を検証して描画入力を照合する。この解釈は明示的な復旧に限定する。

適用時は使用中プロセスと監視の停止を確認する。不明な場合は停止する。既存DBのSQLiteバックアップ、行の一覧ハッシュ、バックアップのSHA256を保存した後、確認時の内容と現在の候補を再照合する。対象と操作が変わっていない場合だけ、操作完了と画像・操作参照を同じトランザクションで確定する。

更新・削除、複数候補、入力不一致、ファイルの欠落・破損は適用しない。対象外の記録、会話開始時の設定、元の画像・Run・要求・評価を変更しない。再実行では適用済みを識別し、結果記録の保存だけが失敗した場合もDBを戻さずに記録を復旧する。

## 操作

アプリを閉じてから、対象の作業フォルダーで実行する。

```console
komaquill repair-images
komaquill repair-images --apply <inspection-id>
```

候補確認の結果に表示されたIDを指定する。修復件数、適用済み件数、保留件数を確認する。適用で保留が残る場合、CLIは終了コード1を返す。保留した対象は設定と画像を確認し、条件を推測して別の画像を選ばない。

確認、バックアップ、修復結果は.artifacts/records/image-link-repairs配下に操作ごとに保存する。原本の記録と分け、Gitと配布物には含めない。
