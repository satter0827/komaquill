# 基本動作と保存境界の再レビュー

## 対象と判定

確認日は2026年11月6日（JST）。基準版は`506dc42e03f071793c3b5ae1ebff095693a8d44b`です。修正後の製品コードのSHA256は`760f7b8b9801ceb220ed49e942da677ef73459e2b6719ba877d2b2f8f57a6789`です。Windows ARM64上のPython 3.12.15、Node 24.15.0で確認しています。検査全体の対象版・入力ハッシュ・環境・成否は、各実行の`checks.json`と[PRのCI](https://github.com/satter0827/komaquill/pull/47/checks)を正本とします。

業務上の生成品質とは分けて、保存済み状態を失わず、基本操作が予期しない例外や無制限待機で止まらず、失敗を特定して再検証できることを受入条件にしました。コードと設定だけで判断せず、隔離したDB、実プロセス、HTTP、配布物の画面操作で確認します。

## 発見と修正

| 対象 | 原因 | 修正と回帰検証 |
|---|---|---|
| DBの喪失と初期化 | SQLiteが既存接続でもファイルを作成する。設定検証より先に保存フォルダーを作る | 明示作成と既存接続を分離。設定を保存準備より先に検証し、初回の設定修正と既存DBの保全を両立。ファイル喪失・版情報欠損・再初期化を検証 |
| 実行上限 | 接続済み台帳の喪失を新規予算として扱う | 新規予約枠の作成と復元を分離。ファイル・行の喪失、再指定、並行予約、期限切れを検証 |
| DBの移行排他 | 公式Saverの接続が共有リースを取得しない | キャッシュ接続と短い接続の全てで同じリースを保持し、閉じた後だけ移行を許可 |
| LANの失敗応答 | 端末判定がルート用の例外処理の外にある | 外側のHTTP境界で型付き失敗と予期しない失敗を処理。登録上限、保存失敗、情報漏洩、ヘッダーを検証 |
| 検査プロセス | 親終了後に子を列挙できない | WindowsのJob ObjectとLinuxの専用プロセスグループで回収。正常終了・期限切れ・設定失敗・別プロセスの保全を検証 |
| LLM記録の追記 | 前の応答をハッシュ照合せずに読む | 不変オブジェクトの検証済み読み取りへ統一。破損した原本を保持し、追記を拒否することを検証 |
| 予算の接続情報 | JSONの形を検証せず添字で読む | 既存のPydanticで型・必須項目・範囲を検証し、安全な設定失敗へ変換 |
| 診断ログ | 排他待機に期限がない | 待機を有限にし、保存不能を返す。ログを占有しても処理が戻ることを検証 |
| 検査の範囲 | TypeScriptテストの配置検査漏れと、Nxのスクリプト推論による重複実行 | `.test.ts`も配置を検証し、Nxの実効グラフでテスト担当と依存を検証 |
| 型検査 | 並列実行でキャッシュを共有する | 対象ごとにキャッシュを分離 |
| E2EのAPI照会 | 期限切れ接続を再利用する | 応答ごとに接続を閉じ、再試行は無効のまま維持 |
| 実行期限 | 全体と個別検査が同じ上限を使い、親が先に終了する | 全体用と個別用の期限を分離。不整合な設定を拒否し、個別検査の上限を維持 |
| 検査の記録 | 予期しない例外で未完了のまま残り、タイムアウト時は取得済みログも表示しない | 安全な終端記録を原子的に確定。失敗時も取得済み出力を表示し、適用した期限を記録 |

各障害は修正前の失敗を確認し、修正後に再実行しています。初期化に伴ってDBが作成される契約も見直し、移行元を作るfixtureは対象版のDBを明示的に用意するようにしました。初期化前に利用者が用意した設定は保持し、既存の保存フォルダーでDBだけを失った場合は空のDBへ置き換えません。

[Windowsのタイムアウト記録](https://github.com/satter0827/komaquill/actions/runs/42097340578)では、Python全件と画面E2Eの57件が成功した後、残るケースの開始時に親の期限へ到達していました。取得済みログと各ケースの時刻を照合し、準備時間を含む親の期限と個別検査の期限を分離しました。各ケースの上限は維持し、PythonとPlaywrightの実効設定から期限の階層も検証します。

## 要件の達成範囲

構成、保存の正本、依存方向、文言、配布物、通常検査と実機検証の分離は、[要件台帳](../../requirements/catalog.toml)と[検証方針](../strategy.md)で管理しています。新しい汎用層は追加せず、SQLAlchemy・公式SQLite saver・Pydantic・pywin32とOS標準機能を使いました。

保存済みの会話11件、画像132件を現在の公開APIで読み直しました。作品の再変換、追加推論、追加画像生成は行っていません。実LLMと画像生成の既存の確認結果は[再設計の検証結果](reliability-redesign.md)を参照してください。今回の自動検査の成功を、新しい実機実行の成功として扱いません。

修正後は保存、上限、排他、HTTP、実行管理を再レビューし、関連検査を再実行します。最終の受入は、同じ対象版のformatter・lint・型・行と分岐のカバレッジ・画面E2E・隔離導入・WindowsとLinuxのquality・securityで判定します。修正途中の全体検査の失敗も証跡に保持し、成功へ置き換えません。

## 依存監査で追加検出した問題

最終文書を含む`40d1ef267ea11e997dc0d57912624de0a6f28af5`の[CI](https://github.com/satter0827/komaquill/actions/runs/42136275039)で、Colab CLIの間接依存OAuthLibにCVE-2026-49272を検出しました。以前の監査成功でこの失敗を置き換えず、監査JSONを保持しています。[公式勧告](https://github.com/oauthlib/oauthlib/security/advisories/GHSA-3jp2-3mrg-2vxc)はdevice codeを検証しない認可サーバーの問題を説明しています。

OAuthLibを公式修正版へ更新し、Colab用extraにも安全な最低版を指定しました。lockだけではuv以外の導入を制限できないため、wheelの依存条件にも含めています。公式Colab CLIの固定版とアダプターは維持し、脆弱性の除外は追加していません。変更後の検査対象と成否は、実行記録とPRのCIを正本とします。T4標準画面の結果は実行時の対象版を維持し、この依存更新後の新規GPU確保として扱いません。
