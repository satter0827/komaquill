# 統合時の保存保護の検証

## 対象

2026年10月24日。保存構成・プリセット・操作の再編をPR #16からmainへ統合します。PR #14と#15の変更も同じ統合に含めます。[再編の検証記録](repository-rebuild.md)は変更前の対象コードに対する結果として保持します。

## 修正

Linuxの仮想環境ではPython実行ファイルが外部インタープリターへ解決されるため、実行ファイルの配置だけでは使用状況を判定できません。起動引数、Pythonの作業場所、PATH・VIRTUAL_ENVなどの作業環境、開いているキャッシュ・一時ファイルを併せて確認します。Pythonプロセスの情報を取得できない場合も保守的に保持し、プロセスの引数や環境変数をログへ保存しません。

初期化前の作業ツリーから単独でpytestを実行するときも、テスト用の一時フォルダーを準備します。

## 検証

使用中の環境、シンボリックリンク経由の起動、作業場所、ファイル、プロセス終了、権限不足を検査します。Windows上の対象検査は35件、全体では533件が成功し、行94.66%・分岐86.20%でした。Linuxでは標準venvのシンボリックリンク型Pythonを別の作業場所から絶対パスとPATH経由の両方で起動し、cleanがキャッシュと一時ファイルを保持することをCIで確認します。

整形・lint・strict mypyとGPUなしの品質ゲートを使用します。通常の隔離buildとwheel E2E、Linuxの実プロセス試験は[PR #16のチェック](https://github.com/satter0827/komaquill/pull/16/checks)の対象コミットで判定します。通常buildと配布物検査は成功し、隔離wheel E2Eは初回のinitが30秒でタイムアウトした後、再試行で成功しました。その後、Windowsアプリ制御が既存Pythonの起動も拒否しました。単独工程の再試行成功を全体ゲートの成功へ置き換えず、記録を保持してCIで同じ対象版を確認します。OSの保護設定は変更していません。

この修正はローカルの整理とテスト初期化が対象です。GPU転送コードは変更していません。
