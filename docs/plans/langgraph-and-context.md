# LLM処理・文脈管理・画像反映の改善計画

対象: REQ-LLM-BOUNDARIES、REQ-LLM-EFFICIENCY、REQ-CREATION-RECOVERY、REQ-CREATOR-ACCEPTANCE。

## 到達点

設定共有、共通LLM実行、文脈予算、原文参照による記憶、API取得の生成、文書解析、画面の機械検査は実装済みである。[現在の分担](../current/library-delegation.md)を正本とする。保存済み画像の参照復旧は公開APIとCLIへ実装し、停止・バックアップ後に実DBの1件を修復した。契約と操作は[画像参照の復旧](../current/image-recovery.md)を参照する。

指定チャットの変更を同じ作業フォルダーの差分と照合し、新ブランチへ集約する。旧roleplay-chatの構成を一括マージせず、既存ブラウザー、App Mode、Node Graph、単発画像生成を維持する。

## 実LLMの確認と採用条件

通常モデルは設定済み4B、日本語を既定とし、画像の基準はWAIとする。日常検査はFakeと擬似APIで行う。実モデルでは入力、条件、モデル、対象コードを固定し、日英の短い会話、移動と予定を含む長い会話、記憶作成を伴う会話を段階的に比較する。上限は[scriptsの設定](../../scripts/evaluation/llm/budget.toml)、収集は[比較処理](../../scripts/evaluation/llm/compare.py)を正本とする。

公式SDKによる文脈の計数、予算超過時だけの原文選択、状態の差分回答、履歴の投影を実装する。自由文の再要約は廃止し、原文への参照を保存する。採用した仕組みと実機で確認できた品質を区別する。判断は[原文を根拠にした会話](../decisions/0018-source-backed-conversation.md)を参照する。

人物の役割、現在状態、所有関係、生成言語、重要事項と自然さを、総使用量・呼び出し回数・待ち時間と分けて評価する。記憶作成・修正・英訳を合計から除外せず、不明値をゼロとしない。限定した比較だけで品質維持や長期の削減効果を断定しない。

## 残る受入

REQ-LLM-EFFICIENCYは進行中とする。保存成功や実行完了を、意味の正しさと全体の効率化へ広げない。今回の比較でも、訂正前の事項、無関係な情報、行動の取り違えが残った。専用の事実回答、候補モデルへの切替、WAIの人物別領域指定は不採用とし、再実験は新しい条件と上限を承認してから行う。結果と残存課題は[会話とWAIの受入検証](../verification/results/llm-acceptance.md)を参照する。

新しい最適化は、失敗した条件と原本を残し、必要な情報を維持した同一入力比較で採否を決める。語句の置換や特定の発言への分岐で意味の誤りを隠さない。常時二段のLLM、モデルの自動切替、ベクトルDB、追加キャッシュ、汎用agentは導入しない。

## 実行の永続化とコンテンツ設定

公式チェックポイント、履歴の分離、NSFWの表示切替、固定メモ、場面の保存と分岐、共有用出力を実装する。現在の構成は[実行とコンテンツの契約](../current/execution-and-content.md)を正本とする。実装の成否と実LLMの品質を分ける。[実4Bの比較](../verification/results/execution-and-content.md)では待ち時間は減ったが総トークンは微増し、行動解釈の課題も残った。

残る受入では、日英の短い会話、記憶作成を伴う会話、設定変更、中断からの再開、二人のWAI画像を同じ条件で比較する。記憶作成・修正・英訳を含む全呼び出しの使用量と待ち時間を集計し、意味の正確さを維持した範囲だけを採用する。実機は明示許可後に上限を定めて実行する。

## mainへの反映

変更と検証資料を同じPRへ揃え、最新の先頭SHAでqualityとsecurityを確認する。今回のチャットでは、利用者の明示許可に基づきPRからmainへのマージも実施する。
