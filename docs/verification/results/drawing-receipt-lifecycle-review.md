# 描画の受付確認と画面遷移

対象: REQ-CONVERSATION-ALBUM-UX、REQ-WEB-ACCESSIBILITY。

## 対象と方法

2026年11月5日、Windows、Node v24.15.0で確認した。基準版はcf225864dea80d3027e27c64ed5b30fc156b1425。会話とアルバムの要件、現在設計、コード、保存済みの検査ログを照合し、今回の画面操作と通信障害の再現で確認した。

今回の対象は画面・操作・状態管理であり、実LLM・GPUの生成品質は対象外とする。画面検査は隔離した作業フォルダーとlocalhostの固定応答だけを使う。生成品質の追加試行は中止し、そこで取得した出力は今回の達成判定へ含めない。起動していたT4は終了し、割当0件、GPUなし、監視停止を確認した。ローカルLLMもアンロードし、サーバーを停止した。停止記録は`.artifacts/records/reports/generation-quality-20261105T025200/shutdown.json`へ保存した。

## 発見と修正

| 問題                                                               | 根本原因と修正                                                                                                                    | 検証                                                                                                |
| ------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------- |
| 受付応答を失った直後に別画面へ移動すると、描画の確認と回収が止まる | 受付不明の要求IDと照会がページの寿命に依存していた。今回送信したIDをアプリ直下へ引き継ぎ、同じIDのGETで確認できた処理だけ回収する | 修正前のReact検査は、画面遷移後の回収が0件のままで失敗。修正後は送信1回・回収1回で同じRunを保存した |
| 人物・場面の描画も画像IDの発行前に受付確認を失う                   | 同じく作成処理の受付不明をページ内だけで保持していた。既存の作成処理の監視へ同じ操作IDを引き継ぐ                                  | 画像IDがまだない受付不明から画面を移動し、受付確認後に生成済み画像を1回回収した                     |
| 画像表示のたびに取得関数がないというQueryの警告を出す              | 監視の失敗を読むためだけに、取得関数のないQuery observerを登録していた。キャッシュの購読だけへ変更した                            | 保存済み画像の追加取得と監視を開始せず、画像検査の警告が消えた                                      |

受付確認専用の画像キャッシュを削除し、通常のRunのQueryへ統一した。監視対象は今回送信した要求だけであり、過去の未完了履歴から確認・回収を開始しない。受付前の明示的な拒否では監視へ追加しない。確認と回収から生成POSTを再実行しない。

共通の受付照合は、新しい応答の購読だけでなく、すでにキャッシュへ届いた同じIDの結果も一度だけ取り込む。照合の成功でキャッシュを更新しても同じ確認を繰り返さない。返答が失敗する前にページを離れた場合も、送信時のIDから確認を継続する。

## 画面確認

1. ホームと開始: 保存済みの要約から開始でき、変更項目は折りたたみにまとまる。
2. 会話と行動: 情景、台詞、自分の発言を区別できる。行動を追加すると発言欄へ戻り、発言と一度だけ反映される。相手不在の案内と保存状態を確認した。
