# 受付・保存・接続条件の分離

状態: 採用

## 背景

行動だけを即時実行する受付と発言の送信が分かれ、発言を書いている途中で行動と応答が進んでいた。本文の保存にも画像生成が結び付いていた。接続状態は画面の説明に使われる一方、必要な操作の有効条件には共有されていなかった。

LLMの場面変更では、JSON Schemaが許可した値をモデル検証で拒否する組合せがあった。一般的な修正要求だけでは同じ値が繰り返され、有限の試行を消費していた。

## 判断

- 発言と任意の型付き行動を一件の送信として受け付け、行動の保存と応答操作を同じ短いトランザクションで確定する。過去の記録型は新しい入力契約から分離する。
- 本文保存から生成を外し、生成は保存済みの対象・版に対して明示実行する。旧画像は設定変更でも保全する。
- 必要接続は処理の入力から決め、画面と受付で同じ観測を使用する。LLM・ComfyUI・GPU所有状態を同一視しない。接続の観測は推論や資源の確保を行わない。
- 場面変更の値は項目を判別子とする型付きUnionで表す。Schemaで表現できる制約を受信後だけの検査へ隠さず、残る検証課題を安全な構造化情報で修正要求へ渡す。
- 保存物は固定NSFWとし、切替と個別分類の仕組みを廃止する。過去の生成条件は当時の事実として保持する。
- 受付済み入力と生成済み応答を区別して表示する。応答が失敗した入力も保存済み要求から読み、成功ターンの複製や保存形式の変更を避ける。
- 接続確認は読取りに限定し、並行する観測は開始順で比較する。ネットワーク通信後には対象の版を再確認する。HTTPの失敗にも安全な段階を含め、受付前の拒否と受付不明を区別する。
- 読取り用のサービス構築では初期データを保存しない。既定プリセットの初期化は通常のライブラリ利用に分け、観測時の暗黙の書込みを避ける。
- HTTPの受付後に起きた既知の保存失敗は、送信済みの応答とは分けて扱う。実行ロックを解放し、保持した操作とチェックポイントを状態照会で復旧する。未知の例外の抑制や推論の自動再送は追加しない。
- 人物の同一性と現在状態を役割別の入力へまとめ、確定行動には行為者を明示する。Schemaの言語指定は入れ子の可視出力にも適用し、原文と名前は保持する。
- Native計数は標準トリマーが扱う部分履歴にも対応する。空履歴はゼロ、systemだけの候補は計数専用の空のuserターンを添えて保守的に見積もる。実際に送信する完全な履歴は変更せず、最終確認ではその履歴を計数する。

## 制約と結果

接続の観測は推論成功の保証ではない。観測後の切断や処理段階の失敗は、保存済み状態を後退させず、操作IDと安全な段階で記録する。実モデルの意味理解、反復、人物や小物の描画品質は、自動テストと分けて評価する。

LM Studioの観測は[公式RESTのモデル一覧](https://lmstudio.ai/docs/developer/rest/list)を使い、モデルの一覧掲載と読み込み済みインスタンスを区別する。内部SDK関数やモデルの自動読み込みは使用しない。

この判断は、[行動の確定](0016-player-actions-and-visual-state.md)の独立実行と、[コンテンツ設定](0017-durable-conversations-and-content.md)の切替・分類部分を置き換える。履歴と原本保全の判断は維持する。
