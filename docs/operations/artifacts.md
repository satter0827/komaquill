# 保存と生成物の整理

## 保全するもの

dataは作品・モデル・履歴・入力・保存ワークフローの正本、recordsはログと検証・移行・削除記録です。stateは所有と復旧のために必要です。これらはcleanで削除しません。

runtimeは再作成できる環境ですが、削除するとCLIやエディターの実行環境を失います。通常の整理対象には含めません。

## 整理する

セッションをstopで終了した後、同じ作業フォルダーで実行します。

```powershell
komaquill clean --dry-run
komaquill clean
```

プレビューには候補の論理容量と除外理由を表示します。実行結果には前後の件数・論理容量と実際の削除量を記録し、処理成功と削除実績を分けます。キャッシュのハードリンクやuvのpruneがあるため、実際の解放容量とは一致しません。

uvは公式pruneを使います。その他のキャッシュと一時データは、実行環境・Pythonの起動引数・作業フォルダー・使用中のファイルから利用状況を確認します。LinuxでPythonが仮想環境外へのシンボリックリンクになっていても検出します。Pythonプロセスを確認できない場合も保守的に保持します。配布物は品質検査が作成した実行IDフォルダーだけを対象とし、最新成功が参照するものを保護します。一時データは製品・検査が所有するものだけ対象とします。

リンク・ジャンクションを含むもの、用途不明のファイル、未完了の所有記録は削除しません。部分失敗では終了コードが非ゼロになり、records/reports/cleanupに削除結果を保存します。使用中のプロセスを自動終了しません。

## 移行

旧配置からdataとrecordsへの移行では、停止、一覧とSHA256の記録、移動、照合の順に作業します。既存ファイルの内容は書き換えません。state/storage-migration.jsonが完了するまで起動とcleanを止めます。旧配置への自動フォールバックはありません。


## ストーリーの保全

data/storiesは作品の正本です。原文、計画、指示、可視出力、生成試行を保持します。画像はdata/runsへの参照なので、作品を移す場合は参照先も保全します。planningの失敗記録も再現と調査に使うため自動削除しません。通常のcleanの対象ではありません。[ストーリーの操作](../guides/stories.md)を参照してください。

## 作品配置の移行と復旧

`migrate --dry-run`は移動対象の件数・論理容量・配置先を確認します。監視・所有GPU・未完了の生成が残る場合は移行しません。作品に属するファイルだけを移し、モデル・一般画像・素材・取得済みログは再配置しません。

`migrate`はコピーとハッシュ照合を完了してから配置表を確定し、元ファイルを削除します。各工程をチェックポイントへ記録するため、中断後は同じコマンドで再開します。移行中の作品操作は停止しますが、状態確認とGPU停止の入口は維持します。

配置表だけを失った場合も、停止後の`migrate`で記録から再構築します。ID重複や移動先の異なる内容を推測で解決しません。原本の一覧・SHA256・移動結果・不足していた画像検証情報の観測はrecords/reports/migrationsへ保存します。観測した日時と、過去の保存日時を区別します。


配置表の破損で終了時の履歴確定に失敗した場合、所有記録は残ります。GPUと接続の終了が記録で確認でき、監視が停止している場合に限り、migrateで配置表を再構築できます。その後stopを再実行して履歴と所有記録を確定します。終了が不明なGPUや実行中の要求を、移行のために停止済みとは扱いません。
