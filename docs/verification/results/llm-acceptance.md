# 会話とWAIの受入検証

対象: REQ-LLM-EFFICIENCY、REQ-CHAT-MEMORY、REQ-CHAT-CHECKPOINT、REQ-CONTENT-MODE、REQ-SCENE-TOOLS。

## 対象と判定

2026-11-03、Windowsのcodex/llm-acceptanceで、mainの01096b1を基点に検証した。実モデルはLM StudioのCPU実行、画像は専用T4のWAIを使用した。採用した変更は[設計判断](../../decisions/0018-source-backed-conversation.md)、設定と固定版は[既定設定](../../../src/backend/src/komaquill/resources/conversations/defaults.toml)と[ロック](../../../src/backend/uv.lock)を正本とする。

意味の正確さを維持した総トークン削減は未達である。実行・保存の成功、原文の引用検証、計数の成功を、文章や画像の品質合格として扱わない。既定モデルとWAIの生成セットは維持する。

## 採用した変更

- 読込済みモデルのテンプレートと文脈上限で入力を数え、概算、送信前の計数、応答の使用量を分ける。
- 履歴の件数による自由文要約を廃止し、予算を超える場合だけ原文を選ぶ。引用のターン・項目・内容と履歴ハッシュを照合する。
- 自分の行動案と相手・環境の変更差分を分け、未変更の確定状態を再生成しない。状態を変えない身振りも保持する。
- 履歴の同一内容は位置と連続回数を保持して投影し、状態やメモが異なる境界はまとめない。
- 旧要約を原本へ退避する明示的な移行を追加する。本文、ターン、画像、過去のハッシュは変更しない。
- NSFWと共有用出力のチェックボックスを共通の配置へ揃える。設定画面での切替、受付時の設定固定、現在の設定による閲覧制御を維持する。

## 実LLMの比較

承認済みの追加枠を含む288呼び出しを使用した。基点の診断、候補の診断、日英の短い会話と長い履歴、訂正、行動確認後の反応、画像用英訳を含む。呼び出し上限は送信前に記録し、SDKの自動再試行と外部トレースを無効にした。候補モデルは取得元・固定版・SHA256・ライセンスを非公開の記録へ保存した。

同じ候補モデルで基点と変更案を三組比較したが、訂正前の箱を答える、無関係な年齢や服装を選ぶ、例示した行き先を流用する、複数の質問の一部を落とす問題が残った。後続の原文参照IDと専用の事実回答でも解消しなかった。これらの実装と候補モデルへの既定の切替は不採用とし、ソースを固定したZIPと元の応答を保持した。候補の数値は最終構成の改善率に使用しない。

原文を引用する記憶では、合言葉、描いた形、訂正を保持して再起動後に読む例を確認した。一方、原文を正しく渡しても回答の意味を保証できない。試作を取り下げた最終構成の品質全体を、この部分成功から合格へ進めない。

過去の[永続化とコンテンツ設定の記録](execution-and-content.md)にあった英語の合言葉想起の成功判定は誤りだった。元の応答と評価を保持し、訂正を追記した。

## WAIの実画像

最初に六場面を二つのseedで基点・候補に分けて24枚、追加枠では単独人物、二人の客観・主観、閉じた傘を8枚生成した。32枚すべて保存済みで、条件、実行グラフ、画像ハッシュ、モデル資源のハッシュを保持した。年齢・性別・座った姿勢に改善する例はあったが、二人の髪や服の対応、人物数、主観の視点、傘の形状と開閉には問題が残った。

標準の領域指定ノードを使う試作でも人物の対応を満たさなかったため、領域指定と追加の品質タグは採用しない。単独人物の成功や全画像の保存を、二人の人物同一性や作品品質の合格として扱わない。

専用T4は二回とも終了し、プロバイダーの割当数ゼロ、GPU不在、回収監視の停止を確認した。確保開始から終了確認までの累計は49.91分で、承認された90分以内だった。App Modeの操作画面を確認したが、終了後の標準Node Graphの接続確認は完了していない。実行グラフの保存と画面の接続確認を区別する。

## 自動検査と移行

最終構成のlint、Python型検査、API契約の照合が成功した。原文の改変検出、旧要約の原本退避、履歴の境界を含む関連26件も成功した。全体ゲート、配布版、CI、既存DBへの移行結果は実施後の検証記録に対応付ける。

全件の読み戻しで、旧履歴の省略項目を現在の型で補った後にハッシュを計算し直す問題を発見した。保存されたJSONを使う照合へ修正し、記憶の範囲ハッシュも保存アダプターから取得する。保存済みの本文とハッシュは書き換えない。省略された既定値、原文・状態・動作の改変、記憶と復旧を含む関連51件が成功した。運用DBの会話10件・全16ターンも、生成や分類変更を行わず読み戻せた。

既存DBの複製での予行後、運用DBも0008から0010へ明示的に移行した。プロセスと進行中の操作がないことを確認し、ファイル一覧とSHA256、DBバックアップ、移行後の照合を保存した。会話10件、操作28件、画像110件、プリセット9件、作成ジョブ20件の件数を維持し、DB以外の保存ファイル892件のSHA256が一致した。移行の記録は.artifacts/records/migrations/99e0e82b-e0ec-4771-b107-90b370b7432aに保持した。既存の内容は自動判定せず未分類として扱う。

## 証跡と残存課題

非公開の.artifacts/records/reports/llm-acceptance-20261103081454102に、全呼び出しのbudget.json、各比較のresults.jsonと対象ソースのハッシュ、移行の予行、画像条件と実行グラフ、終了記録、不採用ソースのZIPを保存した。元の文章や画像は公開資料へ転載しない。後の分析と採否は追記し、原本を上書きしない。

REQ-LLM-EFFICIENCYは進行中を維持する。残る課題は、事実と訂正の選択、行動と行為者、文章と状態の整合、二人の人物属性と視点、主要な小物の正確さである。次の比較では、この失敗集合を固定して品質を先に判定し、合格した条件の総呼び出し・使用量・時間を評価する。新しいモデルや工程の自動採用、常時二段の生成は追加しない。
