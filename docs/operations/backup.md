# バックアップと復元

## 退避する

`stop`後に`status`で所有GPUと監視の停止を確認し、Webサーバーと会話を送信するCLIも終了します。SQLiteへ書き込むプロセスがない状態で、DBと同じフォルダーの関連ファイルを一式で保全します。.artifacts/data、.artifacts/records、komaquill.toml、利用者が追加したpresetsを、利用者が管理する保存先へコピーします。ファイル一覧とSHA256を記録し、コピー後に照合します。stateは復旧用の秘密情報を含むため、安全な保存先へ分けて保管します。

runtime・cache・tmpは再作成できます。data/modelsの台帳は作品とともに保全します。画像生成用のモデル本体はGPUで再取得するため、PCへの保存をバックアップの前提にしません。cleanはバックアップの代わりにはなりません。

## 復元する

空の作業フォルダーへ設定とdata・records・presetsを戻し、一覧とSHA256を照合します。CLIを導入して同じ作業フォルダーを指定します。保存済み画像、モデル台帳、入力素材、ワークフローの記録を確認してから起動します。古いstateを別PCへ無条件で戻して起動しません。

停止確認が取れていない所有記録がある場合は、同じGoogleアカウントでstatusとstopによりGPUの残存を確認します。秘密情報はGitや配布物に含めません。

保存フォルダーが残っているのにDBがない場合は、initで空のDBを作らず停止します。元の作業フォルダーを保全し、照合済みのバックアップから復元してください。新しい作品を始める場合は別の空フォルダーを初期化します。呼び出し上限の台帳が失われた場合も、台帳と接続情報を保全・復元し、上限の再指定で消費を取り消さないでください。
