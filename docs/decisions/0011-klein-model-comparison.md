# Kleinの規模を明示選択し、画像生成を分けて比較する

## 判断

新しい負プロンプト入力とCFG設定を廃止し、標準BasicGuiderへ正条件だけを渡す。生成セットは4B・9Bそれぞれの生成・編集へ分け、資源の規模が混在する設定を受け付けない。既定は4Bを維持する。

CLIとPython APIは既存の処理を共有する。GPUとHigh RAMは起動時に明示指定し、アカウントの使用量は公式Colabアダプターから取得する。実行中に別GPUや量子化モデルへ切り替えない。

## 保存と削除

旧入力の読み取り契約を新規生成の受入条件から分離する。過去の条件、画像、グラフ、ハッシュを再計算して置き換えない。旧プリセット名の別名、空の負入力を受け付ける処理、使用しない負条件の枝を削除する。

共通文と編集指示の結合は一つの関数を使う。空の共通文から区切り記号が追加される原因を取り除き、利用者が書いた句読点は変更しない。

## 比較の解釈

比較するのは本体、対応するエンコーダー、LoRAを組み合わせた生成構成である。本体のパラメーター数だけの効果とは扱わない。LoRAを両方外した比較も、個々のLoRAの寄与は分離できない。

画像比較には原文と照合した固定場面仕様を使う。人物・小物の追加外見は演出条件として明示し、原文の必須条件と分ける。計画LLMの成功率へ含めない。同じseedを両構成へ渡すが、構成が異なるため同じ画像になるとは仮定しない。

保存成功、選択、画質合格、比較の勝敗を独立して記録する。確認できない画像を合格にせず、予算で未実施となった比較も分母へ残す。

## 実行制約

時間・枚数・CU・容量の正本は[比較設定](../../tests/fixtures/klein-comparison/config.toml)とする。CUの基準残高は次のセッションと再開へ引き継ぐ。照会の失敗、陳腐化、アカウントや割当の不一致、残高の増加では追加送信を停止する。

大容量転送の前に、同じ経路で速度を測る。停止用の時間とCUを予約し、期限に収まらない場合は転送を始めない。再利用はファイルの存在ではなくGPU上のSHA256一致で判定する。

9Bの優位性と実機の完了状況は[検証記録](../verification/klein-comparison.md)で扱う。
