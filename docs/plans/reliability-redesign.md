# 標準画面の最終実機確認

構造整理、保存・DBの再設計、既存データの変換、基本的な接続保護、自動検証、実LLMと画像生成の確認は[検証結果](../verification/results/reliability-redesign.md)を参照してください。未完了なのは、通信判定の修正後に標準ComfyUIをT4で再確認する工程です。

## 残る確認

WAIとimg2imgのApp Mode・Node Graphについて、読込、操作可能な表示、想定外のページ例外・console.error・HTTP失敗・送信中断がないことを確認します。固定版の仕様で空の結果になる任意ファイルの404だけを、接続元・経路・方式・状態・件数・観測期間に限定して区別します。

保存済みの会話と画像を使い、追加推論と画像要求は送りません。元の台帳と失敗記録を保持し、予算や期限をリセットしません。上限は[予算設定](../../scripts/acceptance/budget.toml)と[作業設定](../../scripts/acceptance/workspace.toml)を正本とします。残りの累積時間では再起動から終了確認まで完了できないため、追加時間の明示許可を待っています。

## 実施手順

1. 追加時間が許可された場合だけ、同じ台帳へ許可IDと秒数を追記します。CU制限、画像上限、既使用時間と予約は維持します。
2. 所有GPUが停止済みで割当0件であることを確認し、`--resume`で保存済み結果を開きます。停止期限は残りの累積時間から決めます。
3. 標準画面の4表示と通信を確認し、画面・DOM・時系列イベントを保存します。
4. 今回確保したGPUだけを停止し、割当の終了と所有記録の解消まで確認します。
5. 対象版、内容ハッシュ、期待結果との差、追加推論0回、使用時間、終了確認を検証結果へ追記します。

この工程が成功するまで、実機の全体受入を完了扱いにしません。マージは所有者が行います。
