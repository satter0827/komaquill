# 個人設定・プリセット・二言語対応

対象: REQ-PLAYER-PROFILE、REQ-APP-PREFERENCES、REQ-CHARACTER-PRESETS、REQ-STORY-PRESETS、REQ-PLAY-COMPOSITION、REQ-LOCALIZATION、REQ-IMAGE-TRANSLATION、REQ-ARTIFACT-LAYOUT。

## 責務と保存

製品コードは `src/frontend`、`src/backend`、`src/contracts` に分ける。Pythonの `library` が再利用する設定と会話開始を扱い、HTTPと公開Python APIは同じサービスを呼ぶ。Reactは入力、選択、画像の配置、保存結果と進捗の表示を担当する。API契約はOpenAPIを正本とし、TypeScriptクライアントを生成する。

自分は1件のPlayerProfileとして取得・更新する。年齢と性別は自分・キャラクターの独立した項目として保存する。キャラクターとストーリーは複数のプリセットとして管理する。共通部分はID、版、画像参照、保存操作に限定する。表示と生成の好みはプロフィールから分けて保存する。型と制約の正本は [library/models.py](../../src/backend/src/komaquill/library/models.py)。

Reactのプロフィール取得は単一のキャッシュ定義を共用し、一覧型として扱わない。会話開始から編集して保存すると、選択中の相手とストーリーを保持して戻る。表示設定の更新は、生成プロファイルを変更しない限り生成設定の検証へ依存しない。

`presets`、`preferences`、`creation_jobs` は既存のSQLiteへ保存する。作成後の編集・削除は版を照合する。複製は新しいIDで本文と既存画像の参照を保存する。削除は一覧から外し、既存会話の設定と参照画像を残す。削除したキャラクターがストーリーのおすすめだった場合は、その参照を同じトランザクションで解除する。

会話開始は、相手・ストーリーのIDと版、自分の版を一つの短いトランザクションで解決する。本文と画像IDを会話の定義へ固定するため、後のプリセット編集は開始済み会話へ反映しない。ライブラリから直接渡す `ConversationInput` も同じ会話処理へ進む。

## 作成と画像

画像や下書きの操作はUUID、対象の版、用途、言語、接続プロファイル、明示許可を受付時に保存する。同じID・同じ内容の再確認は保存済みの結果を返し、内容が違う場合は競合として拒否する。実行開始はDBで一度だけ取得し、通信中はDBのロックを保持しない。終了済みの状態を古い観測へ戻さない。

保存行・操作・画像の識別子は取得・実行・一覧の各入口で照合する。不一致の記録を使って外部処理を実行しない。場面との関連・受付日時・原文・確定済み英語入力の差し替えを拒否する。カードの画像失敗は紹介文と分け、編集画面の再生成操作へ案内する。

代表画像とバナーの生成は本文の保存後に独立して実行する。接続を確認できない場合は本文を保持し、接続後に画像を作れるよう案内する。生成中は以前の画像を残す。完了した画像は対象の版と現在の画像操作IDが一致する場合だけ適用する。中断した未確認要求を自動で送り直さない。

画像の送信結果が不明な場合は、生成IDを持つ確認待ちの操作として保持する。再起動後も同じRunを回収し、保存を確認してからプリセットへ適用する。受付や保存を確認できた段階で確認待ちのエラーを解除し、確認済みの生成失敗は失敗として確定する。

下書きは本文を提案する。保存済み人物のIDをLLMに作らせず、おすすめの相手は利用者が一覧から選ぶ。下書きをフォームへ適用しても選択済みの相手は保持し、本文を保存するまでは保存済みと表示しない。

人物の縦長画像とストーリーの横長画像は [用途別の設定](../../src/backend/src/komaquill/resources/library/defaults.toml) を使う。バナーの題名はHTMLで表示し、画像には文字を描かせない。

単発画像、代表画像、バナー、会話画像は同じ `ImageService.submit` へ送る。日本語の説明は明示した実モデルで英語化し、原文・英訳・入力ハッシュ・呼び出し記録を保持する。単発画像の英訳は `data/image-preparations`、作成操作の英訳は `creation_jobs` に固定する。再開で翻訳をやり直さない。未許可・英訳失敗・不正な保存データは画像送信前に停止する。

## 言語とLLM

Reactは `app/locales/ja.json` と `en.json` を読み、保存した好みの言語を使う。既定は日本語。日本語の操作文言には控えめな英語見出しを添え、英語表示は英語へ統一する。保存済みの作品名、人物名、本文は書き換えない。日時は標準の国際化機能で表示する。

モデル・返事の長さ・人物・舞台は会話開始時に固定する。新しい操作には表示言語を含める。処理中の切替は受付済み要求へ影響しない。会話の本文は選択言語、画像説明は英語として検査する。名前を言語不一致として扱わず、英語の返事に日本語本文が混じる場合は既定の修正上限内で再要求し、解消しない場合は失敗を保存する。

会話、下書き、英訳は同じLLM要求処理を使う。systemメッセージは一つとし、モデルIDの照合、入力上限、記録、修正上限、作業場所ごとの排他を共有する。モデルの自動切替、SDKの再試行、外部トレースは行わない。[接続と実行上限](../../src/backend/src/komaquill/resources/conversations/defaults.toml) を正本とする。

要求の実行と修正は[LangGraphの固定グラフ](../../src/backend/src/komaquill/adapters/llm_graph.py)で処理する。呼び出し、型・言語の検証、修正を分け、通信失敗を再送しない。モデル接続とメッセージには既存のLangChain部品を使用する。グラフ全体の外部トレースを無効にし、呼び出し記録へ実行基盤の版を保存する。

履歴の切り詰めは標準のtrim_messagesへ委ね、systemと最新の発言、完全な直近の会話の組を保持する。上限は文字数であり、応答スキーマの分も含めて確認する。保存・操作・応答のチェックポイントは既存のSQLiteを正本とし、グラフには一要求分の一時状態を持たせる。グラフ用DBと業務DBへ会話を二重保存しない。長期要約と人物状態の改善は[後続計画](../plans/langgraph-and-context.md)で扱う。

固定サンプルは二言語それぞれの設定・挨拶・応答を対で持つ。任意の入力や独自プリセットには使わず、通常の会話は設定済みのモデルを使う。通常の自動テストは固定応答とlocalhostの擬似APIを使い、実機検査は `tests/live` に分ける。

## 画面

「遊ぶ」で保存済みストーリーと続きを開き、「キャラクター」「ストーリー」「あなた」で保存内容を管理する。会話開始では自分の内容を確認し、相手とストーリーを選び、設定が足りなければ作成後に選択画面へ戻る。表示・生成の好みと接続は設定にまとめる。

相手を明示していない場合はストーリーのおすすめを初回表示と再読込でも使う。紹介欄が空でも、保存済みの導入や世界観を開始内容へ表示する。ホームの読込失敗は再確認できる。受付前に拒否された入力の訂正と、受付不明の同一要求の確認を区別する。

会話本文を中央、人物と状況を補助欄、ストーリー画像を控えめな帯へ置く。狭い画面では補助欄を開閉する。状況編集は場所・時間・目的などの通常フォームで行う。狭い画面はnative dialogで開閉し、Escapeとフォーカス復帰を扱う。送信結果が不明な場合は同じIDと本文で確認し、編集中の次の本文を消さない。

## 移行と検証

既存DBはアプリと監視を止めて `komaquill migrate` を明示実行する。SQLiteのバックアップ、表ごとの内容ハッシュ、移行後の照合結果を `records/migrations` へ保存する。旧会話の本文を推測でプリセットへ変換しない。通常の起動では未移行の既存DBを拒否する。

検証は [保存と会話](../../tests/integration/test_library.py)、[移行と画像入力](../../tests/integration/test_creator_contracts.py)、[画面E2E](../../tests/e2e/web/workflow.spec.ts)、[実4Bと実画像](../../tests/live/play_acceptance.py) に分ける。実機結果と品質上の課題は検証記録で扱い、JSONの成功を文章・画質の合格へ広げない。

## 会話の場面説明と描画

会話文と場面説明narrationは同じ構造化応答で生成し、別の項目として保存・表示する。場面説明は表示言語であり、画像用の英語説明とは分ける。CLIも同じ保存結果を表示する。

会話送信では画像を生成しない。「今の場面を描く」でconversation_image操作を作成する。対象会話の版、人物設定、現在状態、直近の出来事を受付時に固定し、英語の画像説明と生成結果を操作へ保存する。後続の会話やプリセット編集で受付済みの場面を変更しない。会話画像は対象会話と受付時の最後の返事に関連付け、その返事と一緒に表示する。返事がまだない画像は導入の位置に表示する。再表示でも同じ関連付けを使う。

Reactは既存の回収APIを使って画像の進捗を確認し、通常操作では手動の回収を要求しない。本文保存と画像の失敗は独立し、以前の画像を保持する。

描画は選択したキャラクター1人を対象にする。年齢・性別・髪と、現在の服装・表情・姿勢・場所を画像説明へ渡す。バナーには人物を描かない舞台の眺めを指定する。生成結果の遵守は品質レビューで確認する。補助欄には最新の場面説明と場所などの補助情報を表示する。

廃止した送信オプションは新規入力として受け付けない。既存の操作履歴は保存時の契約で検証し、元の要求・識別子・内容ハッシュを変更せず読み出す。移行済みDBへの再実行では明示設定を変換しない。

現在の見た目と動作は、最新の表示用場面説明を正本とする。画像説明にはその場面と人物設定を使い、補助状態に残った古い服装・姿勢で戻さない。受付時の原文には両方を保存し、送信した画像入力も呼び出し記録へ残す。画像の初回読込が失敗した場合も、再送せず既存の生成IDで回収をやり直せる。

会話の履歴は場面説明と台詞を分けたJSONで渡す。操作で選んだ出力言語は本文・場面説明それぞれの応答スキーマへ固定する。言語の検査に失敗した場合は、既存の修正上限内で対象項目を明示して修正を求める。

LLMへ渡す人物・舞台のJSONオブジェクトは復元して項目として渡す。自由記述は変更しない。最新場面をsystemの同じ文脈へ置き、重複する服装・人物属性の補助記憶を除く。最後の返事の状態と現在状態の差分は、次の場面への明示変更として渡す。[文脈の変換](../../src/backend/src/komaquill/conversations/context.py)は保存済み本文を書き換えない。

会話画像の入力では、画面外の自分の名前・呼ばれ方を人物識別として残し、外見は描画対象へ混ぜない。バナーには舞台の項目を優先し、それらがない場合だけ導入から風景を抽出する。用途別の構図を英語入力へ一度だけ付け、確定した英語入力を再利用する。

バナー用の抽出応答は場所・静止した風景や家具・天候や照明の項目に限定し、自由な物語文として出力させない。抽出後も英語を検査し、同じ有限の修正上限を使う。表示言語で絞った後の一覧が空の場合も、新規作成の案内を表示する。
