# 個人設定・プリセット・二言語対応の再レビュー

確認日: 2026-10-31 JST。対象は [新規9要件](../../requirements/catalog.toml) と、作成・保存・選択・会話・画像表示・再開の一連の操作。実装前の構成を正解とせず、受入条件から保存、生成、画面の責務を確認した。

## 発見した問題と修正

| 問題 | 原因と修正 | 回帰確認 |
|---|---|---|
| ストーリーから開始しても既定の相手が選ばれない | 相手を変更イベントだけで設定し、初回表示と再読込でストーリーの参照を解決していなかった。明示選択を優先し、未指定時はストーリーの相手を解決する | 初回、ホームからの開始、再読込、明示した別の相手、会話の保存 |
| 保存済みのストーリーに「設定がない」と表示される | 紹介欄だけで空状態を判断していた。導入・世界観・場所・目的・題名から紹介を表示する | 紹介なし・導入ありの保存内容を表示 |
| 空の選択肢が重複し、別言語の固定サンプルもおすすめに混ざる | 開始画面の重複要素と、編集画面だけ異なる候補条件を修正した | 存在しない明示ID、開始不可、候補の言語 |
| 会話受付直後に次の操作を送れる | POSTの受付結果を状態キャッシュへ反映せず、最初のGETまで処理中と判断できなかった。受付結果を保持し、既に確定した結果は後退させない | 状態取得を遅延させ、次の本文を入力しても送信できないことを確認 |
| 受付前に拒否された下書きを訂正できない | 入力不正と受付不明を同じ再送状態にしていた。受付前の既知の拒否は訂正でき、通信結果が不明な要求は元のIDと入力を保持する | 拒否後の訂正と新規操作、応答喪失時の同一要求確認 |
| 日本語の人物名が画像説明へ残る | 本文用の固有名の例外を画像説明にも適用していた。画像説明は固有名も英語の検査対象とし、既存の修正上限内で訂正する | 日本語名が残る画像説明を拒否し、英語へ訂正 |
| 英語の下書きで指定した日本語名が不正になる | 下書き全体の言語検査に固有名の例外がなかった。表示本文と同じく名前・呼ばれ方を保持し、説明文の言語は検査する | キャラクターとストーリーの英語下書きで日本語名を保持 |
| 操作の指定とLLMへ渡す定義が矛盾する | 会話開始時の言語・画像設定を要求へそのまま渡していた。操作で確定した言語・画像指定・返事の長さを要求へ反映し、保存済みの会話定義は変更しない。本文と画像説明で固有名の扱いも指示を分ける | 実要求の内容、保存定義の保持、4Bによる言語切替と画像説明 |
| ホームで履歴・ストーリーの読込失敗が分からない | 取得結果だけを表示し、失敗を表示していなかった。安全な説明と再確認を設け、保持した内容を消さない | 失敗表示から再確認して保存済み一覧を復旧 |
| ストーリーの下書きを保存できない | 4Bが存在しない人物IDを生成していた。下書きの型では人物IDを生成できないよう制約し、おすすめの相手は保存済み一覧から利用者が選ぶ | 不正なIDの拒否と上限内の修正、実4Bの下書きのプリセット保存 |
| 下書きの適用で手動選択や保存表示が変わる | 作成結果の全フィールドをそのままフォームへ移していた。本文の編集項目だけを適用し、選択済みの相手を保持する。適用後は未保存として扱う | 選択保持、本文更新、保存済み表示の解除 |

画面の文言配置に関する開発規約も、既存の二言語カタログの配置へ合わせた。API契約、DB形式、GPU経路、画像条件、依存の追加は必要なかった。

## レビューの反復

1. 要件と実装を照合し、ストーリーの保存と開始時の相手の不一致を実画面で再現した。関連する初期選択、空状態、候補条件を修正した。
2. 操作の受付と確定を分けて再確認し、会話受付直後と下書き拒否後の問題を修正した。応答喪失時の重複送信防止は回帰確認した。
3. 表示言語と画像用英語を別の契約として確認し、固有名を扱う二つの検査を修正した。ホームの失敗時の復帰も確認した。
4. 修正後に保存・選択・会話開始・再読込を実画面で通し、関連テストと全体ゲートを受入確認に使う。コードの成功と文章・画像の品質は別に判定する。

## 要件ごとの確認

| 要件 | 確認した範囲 |
|---|---|
| 自分のプロフィール | 型付きCRUD、既定の選択、作成画面から保存後に戻る操作、会話への設定固定 |
| 表示・生成の好み | 保存後の再読込、日英・文字サイズ・間隔、操作受付時の条件固定、明示許可 |

実画像は [初回の検証記録](creators-and-play.md) の代表画像、バナー、会話画像、単発画像と、その原文・英訳・Run・実行グラフを確認対象とした。今回の変更はGPU経路や画像条件を変更しておらず、T4での画像再生成は行わない。前回の生成を今回の新規生成として数えない。

## 残存課題

確認範囲の機能不具合を解消した後も、4Bが設定にない出来事を補うこと、下書きの項目を空欄にすること、現在地などへ不適切な状態値を返すこと、画像の小物の重複、不自然な背景文字、人物同一性の限界は残る。これらは保存や言語契約の失敗と分け、保全した実出力を改善の比較対象とする。長期利用、すべてのブラウザー・支援技術、未知の障害まで問題がないと保証するものではない。
