## 検出した問題と修正

| 対象 | 問題 | 修正と検査 |
|---|---|---|
| 計画と原文 | 完了した計画の消失を未計画と扱い、要求と計画の食い違いも見逃す | 完了結果、要求ID、原文と計画の対応を保存境界で検証する |
| 再試行と配置 | 欠けた過去の履歴を分析から除外し、失われた配置を未送信と誤認する | 全参照を確認し、正当な未送信予約と記録の喪失を分ける |
| 回収 | 配置表にない履歴を新規要求として再回収し、元の記録を更新する | 独立画像と作品内の履歴を生成IDで隔離し、元ファイルを保持する |
| 回収結果 | 最終読込みで見つかった破損情報を捨てる | 読めないIDをその回の回収結果へ含める |
| 閲覧用更新 | manifestの失敗で後続場面も止まる | 同じ再試行処理を使って生成を続け、StoryEvent.publication_failureとCLIの終了結果で別に報告する |
| 配置表の修復 | 不正な保存形式でライブラリ例外が漏れ、欠けた作品登録を作品なしと返す | 再構築に必要な識別情報を型付きで読み、推測して補わず保存エラーを返す |
| 実行条件 | 不正な実行グラフでKeyError・AttributeErrorが漏れる | 分析で使うノードの形式を検証し、生成ID付きの保存エラーへ揃える |
| モデルと評価 | 無関係なモデルの破損が分析を止め、任意の評価の破損を分離できない | 必要なモデルだけを読み、読めない評価はunreadable_evaluation_idsへ列挙する。評価IDも保存キーと照合する |

回帰検査は`tests/integration/stories/test_integrity.py`の22ケースです。各修正後に状態、保存境界、公開API、分析、停止を再確認しました。新しいDB、永続キュー、常駐サービス、汎用CRUD層は追加していません。

## 残る課題と制約

- 保存、再開、部分障害の報告、AI比較の入口は確認できています。人物と画像の一致は別の品質課題です。今回も人間の主人公が猫として描かれ、親子の再会が十分に描写されない結果でした。
- 構造検証とFakeは、物語の意味・人物の同一性・画質を証明しません。描画指示にある傘の所有関係の矛盾など、前回の観測を解決済みと扱いません。
- 不明な履歴や配置を自動で推測・修復しません。配置表の修復は停止を確認して明示的に実行します。読めない任意評価を含む出力は不完全な比較として扱います。
- GPU強制停止、通信断、保存との競合は擬似環境で検査し、今回の実機は通常終了と共有コードの確認に限定しています。長期連続運転や外部GPU全サービスの実証ではありません。
