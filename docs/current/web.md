# React画面とHTTP API

対象: REQ-CHAT-LIBRARY、REQ-REACT-WEB、REQ-PLAY-COMPOSITION。

Reactの画面はFastAPIの `/api/v1` を呼び、CLIと同じ公開Python APIへ接続する。Pythonが保存、LLM、画像、実行状態を管理する。画面を閉じても所有GPUは自動で終了しない。

画面の構成、設定の固定、画像処理、二言語の契約は [個人設定とプリセット](creators.md) を参照する。会話は保存済みの自分・相手・ストーリーから開始する。既存の会話と画像、標準のApp ModeとNode Graph、単発画像生成を利用できる。

OpenAPIは [API契約](../../src/contracts/openapi.json)、TypeScriptの生成先は `src/frontend/src/api/generated`。識別子と保存形式は業務契約に置き、HTTPの失敗は安全なコードを返す。Reactはコードに対応する表示言語の説明を選ぶ。

Viteの開発画面はAPIへプロキシ接続する。配布版はビルド済みReactをwheelへ含め、FastAPIから配信する。配布版の実行にNode.jsは不要。生成・起動・検査の操作は [画面の使い方](../guides/web.md)、検査対象の選び方は [開発手順](../development/workflow.md) を参照する。

## 会話とアルバム

対象: REQ-CONVERSATION-ALBUM-UX。

情景は背景と左境界線のある区画、相手の動作は地の文、台詞は名前付きの吹き出し、自分の発言は右側へ表示する。現在の会話と以前の会話で同じ区別を使い、保存本文を加工しない。

行動は送信欄の「行動を添える」から選ぶ。追加後は編集欄を閉じて発言欄へ戻り、要約から編集・取消できる。持ち物は複数行で編集し、複数項目を含む身支度では変更しない項目と物の識別子を保持する。発言と行動の同時送信、版の照合、受付不明時の操作IDの確認を維持する。描画は確定した状態だけを使う。各返答の操作メニューにしおりと別の展開の開始を置き、物語のメモ・共有用出力は会話のメニューへまとめる。

アルバムは保存済みの受付日時をブラウザーの現地日付へ変換し、日付と描画を新しい順に並べる。日付ごとの枚数は保存済み画像ファイルから数える。日付はすべて閉じて始まり、閲覧中の開閉だけを保持する。閉じた日の画像部品を描画せず、ファイル取得を始めない。人物カードと会話の過去の描画履歴も、表示だけで定期照会を始めない。

描画の受付Runを保持し、進行と結果を同じIDで表示する。今回の描画が保存された場合に一度だけ該当日を開き、完成画像へのリンクを案内する。自動でフォーカスを移さない。会話と作成処理の受付不明では同じ要求IDを取得し、「送信結果を確認」もGETだけを行う。確認操作からPOSTを再実行しない。ローカル保存の再実行は同じ操作IDで行い、「保存を再試行」と表示する。

画像表示は読み取り専用であり、表示した過去の未完了履歴を自動回収しない。アプリ直下の監視は今回受付済みの描画、受付済みの作成処理、現在の接続先で回収可能と確認した進行中IDだけを扱う。画面遷移・日付の開閉では監視を失わない。通常の画像・一覧Queryへ結果を共有し、終端状態と保存済み画像を遅い応答で後退させない。回収の失敗が残る対象を除き、終端に達した監視を解放し、古い実行状態の一覧から登録し直さない。回収失敗は明示的に再試行でき、取得済み画像があっても生成失敗を成功へ変えない。

今回送信した描画で受付応答を失った場合も、アプリ直下で同じ要求IDを照会する。単発描画は既存のRunのQuery、人物・場面の描画は既存の作成処理のQueryを共有し、ページを移動しても受付確認を継続する。Runが確認できるまで回収しない。画像表示側は監視Queryの失敗を購読するだけで、取得関数のないQueryを登録したり監視を開始したりしない。

原画像は既存URLの通常リンクで別タブへ開く。保存はブラウザーの右クリックメニュー、終了はタブの閉じる操作を使う。編集用の名称リンクと画像リンクを分け、専用ビューアー・取得APIは持たない。

画像ファイルを表示できない場合は、同じURLの取得を再試行する。失敗した画像の枠は説明と操作の内容に合わせて伸ばし、人物・ストーリーのカードと編集画面、会話のバナーでも操作を切り落とさない。別の画像IDへ更新された場合は、その画像の表示を試みる。

接続表示はサイドバーが既存の操作別Queryを購読する。表示部品は接続照会を追加せず、操作ボタンの可否を決めない。必要な接続の判定と受付側の再確認は従来の契約を使う。接続を使わない編集・保存・閲覧は止めない。

折りたたみの見出しと内容ラッパーを分け、内容側のgapで間隔を揃える。既存の間隔変数と操作の最小高さを共通規則とし、長文と文字拡大で自然に伸ばす。人物編集では名前と紹介を先に表示し、詳細は必要時に開く。ホームと開始画面は保存済みの自分・相手・ストーリーの要約から開始でき、選択の変更だけを折りたたむ。開始操作ではLLMやGPUを呼ばない。

判断の背景と制約は[会話表示と描画監視の分離](../decisions/0020-conversation-album-ui.md)を参照する。

送信中、受付確認中、応答生成中は別の状態として表示する。受付が不明な段階を応答生成中と案内しない。外見確認など、応答を生成しないローカル操作の待機にも返答の進行文言を使わない。

## 視覚設計と共通操作

対象: REQ-WEB-VISUAL-IDENTITY。配色、文字サイズ、間隔、角丸、操作状態はReactの共通CSSを正本とし、文字サイズと密度の設定を全画面へ適用する。本文と画像は保存済みの内容を使用する。テーマに人物画像を同梱せず、画像がない場合に空枠を出さない。

ボタンの種類は共通のvariantで指定する。Base UIのDialogとPopoverへモーダル、小窓の配置、閉じる操作、フォーカス管理を委譲する。行動・描画設定・しおりなど入力を含む操作はPopoverに置き、入力状態は小窓の寿命から分離する。物語のメモは小窓を閉じても部品を保持し、未保存の入力と保存結果の確認を失わない。単純な詳細とアルバムの日付は標準detailsを使う。入力・選択には標準HTMLを使用する。

状況は閉じて始まり、広い画面では右ペイン、それ以外ではDialogに表示する。必要な外見確認は閉じた状況へ隠さず履歴内へ表示する。古い版の行動を確認する操作は送信待ちの要約に置く。行動追加後の発言欄への復帰はPopoverの公開フォーカス指定を使う。

会話の送信領域は、補助操作と発言フォームを分ける。高さを制限するのは補助操作側とし、発言欄と送信ボタンを画面内に保つ。送信待ちの行動と確認事項は描画・追加操作より先に配置する。行動を追加・更新したときは補助操作の先頭へ戻し、発言欄のフォーカスを保つ。短い画面では標準スクロールで補助操作と見出しへ到達できる。見出しは折り返し、ナビの幅は文字サイズに追従させる。画面寸法の監視や独自の位置計算は追加しない。返答がない会話には末尾へ戻る操作を表示しない。

場面画像は履歴の冒頭で同じ領域をスクロールし、縦横比を保って枠内へ収める。末尾追従はuse-stick-to-bottomへ委譲し、読み手が過去を閲覧するときは追従を止める。新しい返答への操作で末尾へ戻れる。自分の送信時も末尾へ進む。保存・監視・回収の責務は変更しない。

画面の非表示は完全不透明なDialogでポータルを含む画面全体を覆う。復帰ボタンだけで解除し、入力とスクロールを持つ画面はマウントしたままにする。非表示による高さの変更や再マウントで位置を失わない。非表示の状態はナビゲーションより上位で保持し、画面幅の切替でも解除しない。採用判断は[共通操作の委譲](../decisions/0021-visual-identity-and-ui-primitives.md)を参照する。
