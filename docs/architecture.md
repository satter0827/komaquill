# 構成と設定

## 処理の分担

WindowsのCLIが要求の記録、画像回収、ローカル保存を担当し、GPU側のComfyUIが画像を生成します。Colabの認証とランタイム操作は公式Colab CLI、接続はOpenSSH、生成はComfyUI標準APIを使用します。startが一つのSSH転送と自動回収を維持し、ほかのコマンドとブラウザーがループバックの接続先を共有します。

| モジュール | 責務 |
|---|---|
| cli | 引数、入力、結果表示 |
| runtime | 起動、監視、再接続、終了の調整 |
| colab / colab_entry | 所有確認、公式CLI、SSH、最終ログ回収 |
| deployment / provenance | パッケージからの転送物作成とコード識別 |
| service / storage | 要求の照合、画像検証、原子的保存 |
| client | ComfyUI標準APIへの通信 |
| settings / models | 設定、保存データの検証 |
| events | 安全な状態変化・失敗の記録 |
| bootstrap / worker | GPU側の環境導入とComfyUI起動 |

生成・保存はColab制御へ依存しません。外部ComfyUIでも同じAPIと保存処理を使います。循環参照と開発用コードへの逆依存は構造検査で禁止します。

## 設定の優先順位

対応するCLI引数、KOMAQUILL_項目名の環境変数、作業フォルダーのkomaquill.toml、パッケージ内のresources/defaults.tomlの順に優先します。接続先・画面・生成条件は対応するCLI引数で指定します。待機時間、ポート、GPUは設定ファイルまたは環境変数で変更します。

startは検証済み設定を接続情報と所有記録へ保存します。生成、回収、終了は同じ設定を使います。ファイルの変更は終了後の次回startから反映します。接続情報が壊れていても、所有記録の設定で終了を試みます。

| 項目 | 既定値 | 用途 |
|---|---:|---|
| gpu | T4 | 新規確保するGPU |
| local_port | 18188 | ローカルの接続ポート |
| remote_port | 8188 | GPU側のComfyUIポート |
| poll_interval | 2秒 | 監視間隔 |
| request_timeout | 30秒 | API通信 |
| preparation_timeout | 900秒 | 環境とComfyUIの準備 |
| generation_timeout | 600秒 | 生成コマンドの待機 |
| shutdown_timeout | 600秒 | 終了前の生成待機 |
| control_timeout | 90秒 | 公式CLI、SSH、ログ取得 |
| execution_timeout | 86400秒 | GPU側のComfyUI実行上限 |

## 配布とGPU転送

initはGitのないフォルダーでも設定と保存先を準備します。既存設定は上書きしません。wheelには製品コード、既定設定、固定したGPU依存、ワークフローを同梱します。開発環境と同じコードから転送物を作るため、Gitへのコミットやpushは起動条件に含めません。

GPU確保前に転送内容とSHA256を確定し、GPU側でも検証して展開します。モデル、作品、環境、資格情報、Git履歴は転送物に含めません。Gitのコミットは確認できる場合だけ補助情報として記録し、実際のコードはコードとリソースのSHA256で識別します。

Pythonは.python-versionと配布設定、ComfyUIのコミットとフロントエンドはresources/runtime.tomlで固定します。依存の正本はpyproject.tomlとuv.lockです。GPU用pylock.worker.tomlはロックから書き出し、品質検査で一致を確認します。配布物のURLとハッシュを固定するため、複数インデックスに同名・同バージョンの配布物があっても選び直しません。[uvのロック出力](https://docs.astral.sh/uv/concepts/projects/export/)を使用し、独自の依存解決は行いません。ローカルのcolab-client依存とGPUのworker依存は分離します。

モデルは双方で配布元の固定リビジョンから取得してSHA256を確認します。ローカルが正本で、Colabの保存はランタイム内の一時キャッシュです。

## 要求と終了の整合性

CLIは送信前、画面の要求はキューまたは履歴を観測した時点で条件を記録します。受付不明の場合は再送せず、実行IDとComfyUI生成IDで照合します。要求ごとに回収し、一つの取得・検証・保存失敗で残りを省略しません。保存は同じフォルダーの一時ファイルから置き換え、状態更新を排他制御します。

画像のSHA256、サイズ、寸法は保存時に計算します。観測時刻、状態更新時刻、保存時刻、ComfyUIが報告した生成時刻を区別し、不明な時刻はnullにします。保存済みの全画像を監視ごとに検査しません。

終了は回収、最終ログ取得、GPU終了確認、ローカル接続終了、履歴確定、終了結果保存、所有記録削除の順に進めます。各結果を分けて記録し、前段の失敗でもGPU終了を試みます。Colabの終了確認後に残った要求をlostへ確定します。未確認の終了や後始末の失敗では所有記録を保持します。

外部接続は開始前のキュー・履歴を取得し直して除外します。記録済みの未回収要求は再照合します。専用の識別情報は要求せず、確認できないモデル・コード情報はnullです。外部サーバーの停止や要求のlost化は行いません。同じURLのサーバーが入れ替わったことを標準APIだけで完全には識別できません。

## ログと認証

保存用途は[README](../README.md#保存場所)の配置に従います。Google認証と公式CLIのセッション管理は標準のユーザーフォルダー、外部認証はOSの資格情報ストアを使用します。

状態変化と失敗は排他制御付きJSON Linesへ追記します。正常なポーリング、プロンプト全文、認証情報、HTTP応答本文、例外の本文・変数は記録しません。取得済みログは個別に原子的に更新し、取得に失敗した場合は前回の内容を保持します。自動削除は行いません。各ファイルの意味と障害対応は[操作](usage.md)を参照してください。
