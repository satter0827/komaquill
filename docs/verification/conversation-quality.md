# 会話と描画の固定評価ケース

対象: REQ-PLAYER-ACTIONS、REQ-SCENE-TOOLS、REQ-CHAT-CHECKPOINT。

評価ケースの版は`conversation-quality-v2`とする。現在地の共有、移動と質問の同時入力、情報の物体化、台詞と応答形式の分離を対象に含める。自動テストの保存・型検証とは分け、実LLM・GPUを操作別に許可した受入検証で使用する。モデルやLoRAをこの評価のために自動変更しない。過去のv1の結果は当時の基準として保持し、v2を実行した結果へ変更しない。

## 共通条件

自分は28歳の旅人Akariで赤いコートと青い封筒を持ち、相手は60歳の古書店主Miraで黒いエプロンを着ている。開始場所は二人とも古書店とする。日本語と英語で同じ意味の入力を使用し、名前・原文を表示言語へ合わせて改変しない。各ケースは新しい会話から始め、操作ID・対象版・初期状態・実際に送った入力を保存する。

## ケースと判定

| ID              | 入力と操作                                                                                                          | 確認する結果                                                                                                                      |
| --------------- | ------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------- |
| identity        | 「あなたの名前と年齢、私とあなたが着ているものを教えてください」                                                    | 自分と相手の名前・年齢・服装を取り違えない。相手として返答し、利用者の台詞を代筆しない                                            |
| remove-clothing | 自分の服装を空文字へ変更する行動を選び、「コートを脱いで、隣に置きました」と同時送信する                            | 自分の服装だけを解除する。相手のエプロンを解除せず、コートを手に持つと勝手に変更しない                                            |
| location        | 行き先を海辺とする行動を選び、「海辺に着きました。景色を見ています」と同時送信する                                  | 共有する現在地は海辺になり、二人は同行する。台詞・場面の描写も同じ場所を使い、古書店の情景を現在の海辺として描かない              |
| natural-move    | 「一緒に公園へ行こう。読書会の相談も続けたいです。初めての人にどう声をかけますか？」と一度に送る                    | 移動を一度だけ確定し、移動後の状態で質問に答え、一つのターンへ保存する。追加確認や空の途中ターンを挟まない                        |
| conditional     | 「雨が降ったら古書店へ戻りましょう。今はここで話しましょう」と送る                                                  | 現在地を維持し、条件付きの相談に答える。将来の予定も即時移動として適用しない                                                      |
| information     | 合言葉を伝えた後にその言葉を質問する                                                                                | 原文の言葉を正確に答え、合言葉を物理的な持ち物へ追加しない。以前の持ち物一覧を質問への回答だけで復元しない                        |
| dialogue        | 非技術的な相談の最後に決定事項の要約を頼む                                                                          | 最新の予定の日時と場所を維持し、未完了の準備を完了済みへ変えない。通信形式のJSON断片を台詞へ混ぜず、保存本文を後処理で削らない    |
| people          | 同じ確定場面で「相手のみ」「自分と相手」「風景」をそれぞれ明示描画する                                              | 人物数は順に1人・2人・0人となる。二人の場合は人物ごとの服装と持ち物が入れ替わらない。入力JSONの正しさと実画像の判定を別に記録する |
| objects         | 自分の持ち物を`blue-envelope`の青い封筒だけに変更し、「青い封筒を持ったまま、おすすめの本を聞きます」と同時送信する | 封筒は自分の持ち物として保持する。同じ物の識別子が相手にも現れず、約束や知識を物理的な持ち物へ追加しない                          |
| topic           | 「景色の話はここまでにして、好きな音楽について教えてください」と送る                                                | 音楽の話題へ移り、場所・服装・持ち物を理由なく変更しない。以前の質問への回答だけを繰り返さない                                    |
| repetition      | 「好きな本は？」「その本のどこが好きですか？」「今度は苦手な食べ物を教えてください」を順に送る                      | 質問に応じて情報が進み、同じ台詞・動作・擬音・締めの質問を機械的に繰り返さない。文面の完全一致と意味の反復を分けて評価する        |

## 記録と採否

日時、ケース版、対象コードの内容ハッシュ、設定・モデル・指示の識別情報、実行回数、修正回数、使用量、不明値、拒否・失敗を含む全件を記録する。判定には評価者と根拠のターン・画像を対応付ける。好みと条件違反を分け、採用した結果だけで成功率を算出しない。

本文・画像・要求・応答は`.artifacts/records`と作品データへ保持し、公開資料には匿名化した観測だけを記載する。訂正は追記し、原本を変更しない。実画像を見ていない判定を画質や人物数の達成として扱わない。

## 実LLMの保存・復旧

移動と返答の停止境界は[共有する場面の回帰テスト](../../tests/backend/integration/conversations/test_shared_scene.py)、保存失敗と再起動は[会話の永続性テスト](../../tests/backend/integration/conversations/test_conversation_durability.py)、HTTP受付応答の喪失は[画面の復旧E2E](../../tests/system/e2e/web/recovery.spec.ts)で検査する。通常ゲートは実モデルを呼ばない。

実モデルの会話・行動検証は[現在の検証手順](strategy.md)に従い、明示許可と既使用分を保持する台帳を指定する。初回の実生成と復旧を分けて計数し、保存済みの再確認で追加推論がゼロ、行動が一度だけ適用されることを確認する。過去の実モデルの障害注入は[実LLM・T4の再検証](results/live-ui-operations.md)、同行仕様の結果は[同行する会話の検証](results/shared-location-and-retention.md)を参照する。過去の結果を現行版の実機成功へ昇格させない。
