# 使い方と障害対応

## 起動と接続

環境を有効にして `komaquill start` を実行します。初回のGoogle認証は公式Colab CLIに従います。
認証コードは認証用の端末だけに入力します。Colabの有料プランであっても、GPUの確保は利用枠と空き状況に依存します。

`start` はフォアグラウンドでSSH転送と自動回収を維持します。この端末を開いたまま、別の端末から生成や画面の起動を行います。
GPUを新しく確保する操作は `start` だけです。`status`、`doctor`、`collect`、`stop` はGPUを作成しません。

Colabへ送るソースはローカルのHEADコミットです。変更をコミットしてから起動してください。GitHubへの送信は不要です。
同じソースの残存ランタイムには再接続します。ソースを切り替える場合は `stop` 後に起動します。

## 生成と画面

```powershell
komaquill generate --prompt "a small cabin" --negative "text, watermark" --seed 42
komaquill open --view app
komaquill open --view graph
```

プロンプトを省略すると入力を求めます。日本語も記録できますが、初期モデルへの画像説明には英語が適しています。
日本語ストーリーの翻訳・分割は含みません。

両画面はComfyUIの標準機能です。画面から生成した画像と使用したワークフローも `start` が回収します。
外部ComfyUIでは画面を開き、表示されたローカルのワークフローJSONを読み込んでください。画面の対応状況は接続先のComfyUIに依存します。

## 回収と保存

`artifacts/runs/実行ID/` に画像、run.json、workflow-api.json、画面用のworkflow.jsonを保存します。
画面用JSONは生成履歴に含まれる場合に保存します。送信結果が不明な要求は自動再送せず、キューと履歴を実行IDで照合します。

```powershell
komaquill collect
komaquill collect 実行ID
```

既に保存した画像は重複取得しません。部分的な取得失敗は、同じランタイムが残っている間に再回収できます。
外部接続では、接続前に存在したキューと履歴を自動回収しません。Komaquill自身の未回収要求は照合対象です。

## 終了

`komaquill stop`、または `start` の端末のCtrl+Cで生成と回収を待ち、所有するColabを終了します。
待機上限は既定10分です。上限に達した場合は回収可能な結果を保存し、未完了・未回収のIDを表示して終了します。

`stop --force`、または2回目のCtrl+Cでは生成完了を待ちません。完了済みの結果の回収と終了確認は行います。
外部ComfyUIのプロセス、キュー、ランタイムは停止・削除しません。

強制的なプロセス終了やPCの電源断では、Colabの終了を保証できません。次回は `status` と `stop` で残存ランタイムを確認・終了します。
終了を確認できない場合は管理記録を残します。Colabが失われると、未回収の画像は復元できません。

## 接続できない場合

1. `status` で所有するColab、自動回収、接続、未回収を確認します。
2. `doctor` でGPU、モデル、標準ノードを確認します。
3. `artifacts/logs/ランタイムID/` の準備ログと実行ログを確認します。
4. 起動に失敗した場合は `stop` で終了を確認してから、改めて `start` を実行します。

接続ポートが使用中の場合は、別の `start` を終了するか設定を変更します。SSHのホスト鍵が変わった場合は接続を拒否します。
認証の失敗や利用枠の不足は、GoogleアカウントとColabの利用状態を確認してください。

別フォルダーから使う場合は `komaquill --project 作業フォルダー コマンド` と指定します。
