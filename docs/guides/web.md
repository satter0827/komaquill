# 会話画面の使い方

## 起動

開発環境のPython依存は `bootstrap/setup.ps1`、Node依存は `node bootstrap/setup-node.mjs` で準備する。既存DBを使う場合は、アプリと監視を停止して `komaquill migrate` を実行する。移行前の内容は `.artifacts/records/migrations` に保存される。

開発時は `pnpm dev` を実行し、Viteが案内するローカルURLを開く。APIと画面は別のポートで動く。`pnpm build` で作成したwheelを導入した環境では、`komaquill --project 作業場所 web` を実行して案内されたURLを開く。ブラウザーを自動で開く場合だけ `--open` を付ける。

## 作って遊ぶ

画面の項目はTabで移動できる。会話の履歴にフォーカスすると、PageUp・PageDownで履歴をスクロールできる。狭い画面では「今の状況を開く」から詳細を表示し、Escapeで閉じると開いたボタンへ戻る。

1. 「自分のプロフィール」で、物語の中で使う名前・呼ばれ方・外見・立場を保存する。一つのプロフィールに年齢・性別も保存できる。
2. 「キャラクター」で会話する相手を作る。性格、話し方、背景、自分との関係を保存できる。
3. 「ストーリー」で舞台、導入、最初の場所、当面の目的とおすすめの相手を保存する。
4. 「物語を始める」で、自分のプロフィールを確認し、相手1人とストーリーを選んで開始する。選択中に作成画面へ移動した場合は、保存後に選択画面へ戻る。
5. 会話を送り、「遊ぶ」の「続きから」で保存済みの会話を開く。後からプリセットを編集・削除しても、開始した会話の設定と画像は保持される。

会話は設定済みのモデルを使う。モデルの起動と接続を済ませてから話しかける。手元のモデルIDと接続先を変更する場合は [接続設定](../../src/backend/src/komaquill/resources/conversations/defaults.toml) を作業設定で上書きする。別モデルへ自動では切り替わらない。

更新後の開発環境では `bootstrap/setup.ps1` でLLM用依存を同期する。会話・下書き・英訳の実行はLangGraphを使い、保存済みの会話と画像は既存の保存処理で扱う。状態の保存形式を更新した環境では、起動前にmigrateを実行する。元の本文と画像を保持し、変換できない会話は「以前の会話」から読む。

ストーリーの「これを使う」から始めると、おすすめの相手が選ばれる。別の相手へ変更することもできる。ホームで保存内容を読み込めない場合は、表示された説明を確認して一覧を更新する。

開始画面の「編集する」で自分のプロフィールを保存すると、選んだ相手とストーリーを保持して開始画面へ戻る。

## 下書きと画像

キャラクター・ストーリーの「下書きを作る」では短いアイデアから下書きを生成し、内容を確認してから保存する。内容を生成するには、設定で会話の接続先を準備する。

接続済みの画像サーバーがある場合は、保存後に人物画像やバナーを生成する。画像を作れなくても本文は保存される。日本語の画像説明は生成時に英語へ整える。接続がない場合は設定の画像接続で準備する。未保存の変更がある場合は、先に「保存する」を押してから画像を生成する。所有GPUの新規確保はCLIの `start` で明示的に行う。

一覧で画像の作成に失敗した場合は「絵を描く」から編集画面を開き、説明を確認して再生成する。紹介文や保存済みの会話は失われない。

単発の描画は「アルバム」の「場面を描く」から作成する。受付後は作成欄の近くに進行を表示し、保存できると該当日が開く。「描いた場面を見る」で今回の絵へ移動できる。日付はすべて閉じて始まり、保存済みの枚数を示す。生成中に以前の画像がある場合はその画像を表示する。画像の受け取りに失敗した場合は回収を再実行し、受付が不明な要求は新しい操作として送らず、同じ要求を確認する。

## 表示と生成の好み

「設定」で日本語・英語、文字サイズ、表示の間隔、返事の長さを保存する。言語は次の操作へ適用し、返事の長さは新しい会話へ適用する。保存済みの作品名や本文を自動翻訳しない。会話の途中でも、次の返事から言語を変えられる。

人物画像と状況は会話の補助欄に表示する。狭い画面では右上のボタンで開閉する。「場所を変える」で行き先を入力し、発言欄と同じ「送信」で確定する。行動だけでも送信できる。待機や服装などは「その他の行動」から追加する。

## 会話と画像

会話には、相手の言葉に加えて背景や動作の説明を表示する。絵を見たいときは入力欄の近くにある「この場面を描く」を押す。押した時点の服装・表情・動作・場所で描き、生成中も会話を続けられる。会話の送信だけでは絵を作らない。

送信や描画の受付応答が途切れた場合は、保存された操作を確認する。受付済みと分かれば結果を表示し、続けて入力していた文章は保持する。受付を確認できない場合は「送信結果を確認」を押す。この操作は同じ要求IDの結果を読み取り、新たな会話や描画を送信しない。

「自分のプロフィール」は1件のプロフィールを直接編集する。年齢・性別も保存できる。キャラクターの代表画像とストーリーのバナーは、接続済みなら保存後に作成する。接続がなくても入力内容は保存される。

CLIでは `komaquill chat create 名前` で日本語の会話を作り、`chat send ID 本文 --allow-real-llm` で話しかける。`--locale en` で英語を指定できる。絵は `chat draw ID --allow-real-llm` で保存し、出力されたパスから開く。

会話がモデルの文脈予算を超える場合は、古い部分から原文を引用して記憶し、元の本文はそのまま表示する。忘れたくない事項は「物語のメモ」にも保存できる。

LM Studioの既定接続では、モデルを先に読み込んでから利用する。公式SDKで読込済みモデルのテンプレートと文脈上限を使って入力を数える。別の接続では、作業設定のtoken_countingとschema_in_contextを接続先の挙動に合わせる。直近の履歴を保持する範囲はrecent_turns、選択処理の上限はmemory_max_batchesで扱う。設定項目と既定値は[接続設定](../../src/backend/src/komaquill/resources/conversations/defaults.toml)を参照する。起動中に設定を変更した場合はサーバーを再起動する。

発言と行動の受付後は相手の反応を生成する。返答が失敗しても、受付済みの発言と行動を会話の履歴へ表示する。行動を取り消したり同じ発言を自動再送したりしない。結果が分からない場合は「送信結果を確認」を使う。旧データで見た目の確認が表示された場合は、身体的な特徴と開始時・現在の服装を分けて入力する。保存済みの文章と画像は変更しない。

主人公とキャラクターは常に同行する。「公園へ行こう。相談を続けよう」のような自然文でも、一度の送信で移動と返答が完了する。移動後の返答に失敗した場合も、受付済みの入力と移動は保持される。「会話の続きを再開」が表示された場合は、保存済みの段階を再利用して続きを実行できる。受付不明の要求は再送しない。

「会話の続きを再開」の受付応答が途切れた場合も、同じ操作の確認を続ける。「送信結果を確認」は保存状態の読み取りだけを行う。下書きを消さず、再開が受理されたと確認できれば、その結果を表示する。読み取りに失敗した場合は確認をやり直せる。現在も再開可能な中断だと確認できれば、「会話の続きを再開」を改めて選べる。通信の期限切れだけで会話を送り直さない。

読み込み直しに失敗しても、表示済みの会話と書きかけの文章は保持する。「読み込み直す」で最新の状態を取得してから送信や保存を続ける。初回の履歴を読み込んでいる間は、空の会話として表示しない。

見た目の確認は、画面に出た人物だけを入力する。服装が未指定の欄は、編集せず確認すれば未指定のまま残る。確認済みの別の人物は変更しない。確認前に入力していた会話も保持する。

保存に失敗した処理は、同じ操作の結果を確認する。保存済みの返答があれば、サーバーの再起動や再生成をせずに表示へ復帰できる。返答が保存されていなければ中断として表示する。アプリの更新では、旧プロセスを停止してから起動する。

## 保存物と画面の非表示

保存物は過去の作品を含めてNSFWとして扱う。区分の切替や作品ごとの分類操作は提供しない。実LLMは設定したローカル接続を使用する。

サイドバー下部の「画面を隠す」で表示を隠し、「画面を表示する」で戻す。書きかけの文章と行動は保持される。絵をクリックすると原画像を別タブで表示する。保存は画像の右クリックメニュー、閉じるときはタブの「×」またはCtrl+Wを使う。

## 保存と接続確認

「保存」は文章と設定だけを保存する。代表画像やバナーを更新する場合は、変更を保存してから「絵を描く」を選ぶ。描画や送信は、必要な接続が確認できるまで操作できない。接続が不要な編集、保存、閲覧、ダウンロードは利用できる。

処理中の画像は自動で取得する。取得に失敗した場合は「画像の取得を再試行」を使う。保存済みの画像ファイルを表示できない場合も、同じURLの取得をやり直す。どちらも新しい画像は生成しない。文章や設定のローカル保存に失敗した場合の「保存を再試行」は、同じ操作IDで保存をやり直す。

描画の受付結果が分からないときは、同じ要求の確認を続ける。同じブラウザー内で別の画面へ移動しても確認を継続し、受付が分かった処理を回収する。確認のために新しい描画を送信する必要はない。ブラウザーを閉じた後の常駐監視とは異なる。

## 物語のメモ・しおりと共有用の出力

会話のメニューから「物語のメモ」を開いて編集する。関係や忘れたくない約束などを1行に1件入力する。会話開始時には文体、扱う話題、避けたい内容も指定できる。

各返答の操作メニューから「しおりを付ける」または「ここから別の展開を始める」を選ぶ。会話はしおりの有無にかかわらず保存される。別の展開にはその時点までの履歴、状態、メモを引き継ぐ。元の会話は変更しない。

共有用のZIPは会話のメニューから取得する。画像と生成条件を含めるか個別に選べる。共有用画像はメタデータを除いたコピーとし、生成条件を含めるとプロンプトなどもZIPへ入る。

描画ボタンの近くで相手、自分と相手、風景を選び、視点を指定する。二人の描画にはWAIを使用する。画像の生成には接続済みのComfyUIが必要となる。

旧DBで移行が必要と表示された場合はサーバーと監視を停止し、`komaquill migrate`を実行してから起動する。移行前のバックアップと照合記録を保持する。詳細は[現在の契約](../current/execution-and-content.md)を参照する。

接続確認の表示はサイドバー下部にまとまる。「状態を確認する」で現在使う操作の接続を確認し、詳しい接続先は設定で確認する。スマートフォンではメニューの印から状態を確認する。外部の画像サーバーとの接続解除は、そのサーバーの終了とは異なる。

人物作成では名前と紹介を先に入力し、必要に応じて「詳しく決める」を開く。未保存・保存済み・画像の未更新を分けて表示する。ホームの要約からすぐに物語を始めるか、要約を開いて相手とストーリーを変更できる。

## 会話を読む・操作を開く

場面の絵は会話の冒頭にあり、会話と一緒にスクロールする。過去を読んでいる間は新しい返答が届いても移動しない。「新しい返答へ」で最新の発言へ戻れる。

「今の状況」は必要なときに開く。「その他の行動」「絵の描き方」「この場面の操作」は小窓で開き、Escapeや外側のクリックで閉じられる。途中まで入力した行動は閉じても保持される。行動を送信待ちへ追加すると発言欄へ戻る。場面が変わって確認が必要になった場合は、送信待ちの行動のそばに表示される確認操作を使う。

「今の状況」を開いたまま画面幅を変えると、開いた状態を保って表示先が切り替わる。閉じた状態も画面幅の変更で戻らない。

文字を大きくした画面や高さの短い画面でも、発言欄と送信ボタンは画面内に表示する。送信待ちの行動は補助操作の先頭にあり、編集・取消できる。入りきらない補助操作はその領域をスクロールして使う。

「画面を隠す」は絵や小窓も含めて覆う。Escapeでは解除せず、「画面を表示する」で復帰する。書きかけの発言と閲覧位置は保持される。
