# 操作と接続確認

対象: REQ-OPERATION-AVAILABILITY、REQ-PLAYER-ACTIONS、REQ-CONTENT-MODE、REQ-CREATOR-ACCEPTANCE、REQ-WEB-ACCESSIBILITY。

## 受付と依存

会話は発言と任意の行動を一つのSendInputで受け付ける。発言、操作ID、期待する版は必須とする。提案IDを渡す場合はその行動との一致も確認する。既存の同一要求は接続確認より先に照合し、再送や二重適用を防ぐ。接続の観測はDBトランザクションの外で行い、確定時に版・提案・実行中の操作を再確認する。

行動の確定と応答操作の受付は同じトランザクションで保存する。応答が失敗しても確定した行動を戻さない。受付不明では保存済み操作を同じIDで確認する。独立した行動実行の公開APIは提供しない。過去の行動だけの要求は保存記録型で読み、新規入力の検証から分離する。

未完了の操作は、保存済み要求から発言と行動を読み、HTTPのOperationView.inputへ返す。画面は成功したターンと時刻順に表示し、返答の失敗で入力を消さない。完了済みの本文はページ取得するターンを正本とし、操作一覧へ重複させない。PythonではClient.operations.inputで受付内容を取得できる。過去の行動IDは記録済みイベントを参照し、原本を書き換えない。

HTTPの受付応答と、その後のバックグラウンド実行を分ける。受付後の既知の保存失敗を、送信済みのHTTP応答へ再送出しない。操作は保持し、状態照会でチェックポイントから確定する。会話、再開、下書き、描画に同じ境界を使い、受付済みの要求を自動再送しない。未知の例外を成功へ変換しない。

本文の保存は画像生成を呼ばない。画像は保存済みの対象と版をCreationRequestへ固定して生成する。視覚条件の変更では旧画像を保持し、未更新であることを表示する。無関係な人物設定の変更で実行中の画像入力を変更しない。

## 観測の契約

Client.availability.checkとPOST /api/v1/availabilityは同じ判定を呼ぶ。要求のkindはconversation、creation、image、collection、resumeとする。会話・回収・再開にはidentity、作成にはcreation、単発画像にはprompt・subjects・negative・llm_profileを渡す。

結果にはreadyと、必要接続ごとの対象、状態、確認日時、有効期限、理由コードを含める。画像入力の依存は実際の入力準備と同じ処理から求める。日本語の英訳や背景の構成ではLLMを必要とし、翻訳不要の入力では要求しない。画像の回収は元のruntime_idを照合し、保存済み画像の再確認には接続を要求しない。

確認中に対象の版が進んだ描画や、完了して再開できなくなった操作は、HTTP 200のready=falseと理由コードで返す。観測の対象は変更せず、画面は新しい入力の確認結果を使う。実際の描画受付では版を再照合し、古い要求の競合拒否を維持する。保存失敗や未知の例外を未準備へ置き換えない。

観測は対象ごとに共有し、期限内だけ再利用する。既定値は[会話設定](../../src/backend/src/komaquill/resources/conversations/defaults.toml)を正本とする。Reactは未確認・確認中・期限切れ・失敗で実行を非活性にし、理由と再確認の操作を表示する。入力の編集、本文保存、履歴閲覧、ダウンロードは継続できる。

同じ接続の確認が重なった場合は、新しく開始した確認の結果を優先する。画面の結果は確認した入力へ対応付け、途中で変わった入力の結果として扱わない。受付後の接続失敗でも再確認する。再開可否の観測には副作用のない操作スナップショットを使い、保存済み返答の確定を行わない。描画の受付は接続確認後の短いトランザクションで対象の版を再確認する。

サービスの組立てと初期データの保存を分ける。既定プリセットと好みは通常のライブラリ利用時に初期化し、接続確認の入力準備では作成しない。初回の下書き・会話描画の接続確認も、保存済みのライブラリ記録を変更しない。

観測では推論、モデル読み込み、ダウンロード、GPU確保を行わない。LM StudioのNative計数を使用する接続では、公式のモデル一覧から読み込み済みインスタンスと文脈長を確認する。観測直後の切断も起こり得るため、受付・実行の失敗を安全なコードと段階で保持する。

## 表示と原本

入力・選択・ボタンの役割ごとに寸法を揃え、間隔は共通CSSの変数から指定する。ページ幅は利用可能幅に対して安定させ、詳細欄の開閉やエラーの長さで変えない。画像はブラウザーの原画像表示とダウンロードを利用する。取得失敗の再試行と、新しい画像の生成は別の操作とする。

保存済み画像の表示に失敗した場合は同じファイルURLを再取得する。画像の生成やComfyUIからの回収は呼び出さない。完了・保存済みの状態は遅れて届いた失敗通知で後退させず、明示的な再開の受付時は古い中断状態を破棄して観測し直す。

利用者が保存した場面の原文と生成した台詞・動作を分ける。原文の言語や人物名を表示言語に合わせて改変しない。Schema上の成功や画像の保存成功を、作品品質の保証として扱わない。

## 移行

固定NSFWへの変更は停止確認を伴う明示移行で行う。旧設定とDBを保存し、テーブル・ファイルの一覧とハッシュを照合する。個別分類表は廃止するが、過去の操作条件、本文、イベント、画像、グラフ、チェックポイントは保持する。互換用の入力APIや旧パスへのフォールバックは設けない。

設計判断は[受付・保存・接続条件の分離](../decisions/0019-operation-acceptance-and-availability.md)を参照する。
