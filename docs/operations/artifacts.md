# 保存と生成物の整理

## 保全するもの

dataは作品・モデル台帳・履歴・入力・保存ワークフローの正本、recordsはログと検証・移行・削除記録です。stateは所有と復旧のために必要です。これらはcleanで削除しません。

runtimeは再作成できる環境ですが、削除するとCLIやエディターの実行環境を失います。通常の整理対象には含めません。

## 整理する

セッションをstopで終了した後、同じ作業フォルダーで実行します。

```powershell
komaquill clean --dry-run
komaquill clean
```

プレビューには候補の論理容量と除外理由を表示します。実行結果には前後の件数・論理容量と実際の削除量を記録し、処理成功と削除実績を分けます。キャッシュのハードリンクやuvのpruneがあるため、実際の解放容量とは一致しません。

uvは公式pruneを使います。その他のキャッシュと一時データは、実行環境・Pythonの起動引数・作業フォルダー・使用中のファイルから利用状況を確認します。LinuxでPythonが仮想環境外へのシンボリックリンクになっていても検出します。Pythonプロセスを確認できない場合も保守的に保持します。配布物は品質検査が作成した実行IDフォルダーだけを対象とし、最新成功が参照するものを保護します。一時データは製品・検査が所有するものだけ対象とします。

リンク・ジャンクションを含むもの、用途不明のファイル、未完了の所有記録は削除しません。部分失敗では終了コードが非ゼロになり、records/reports/cleanupに削除結果を保存します。使用中のプロセスを自動終了しません。

## 検証後の大幅な容量整理

通常のcleanで保護することは、個別の検証データを永久保存するという意味ではありません。利用者が作品・検証記録の削除範囲を指定した場合は、次の順序で一括整理します。通常のcleanの削除範囲は変更しません。

1. 生成条件、実画像の評価、障害の原因、修正と検証結果を確認し、再利用できる判断と未確認事項を設計書へ残します。個人の原文・画像・プロンプトを公開文書へ転載しません。
2. GPUの停止確認、所有記録の解放、監視と関連プロセスの終了を確認します。対象の絶対パス、リンク、使用中状態、保持資源のSHA256を記録します。
3. 指定された画像・作品・個別履歴・ログ・検証workspaceと、現在の生成セットが参照しないモデルを整理します。画像だけを削除して索引や復元情報を残す状態にしません。
4. 保持資源の一致、通常環境の参照先、実際の空き容量を確認します。削除対象、件数、容量、成否は軽量な整理記録へ保存します。

Explorerのフォルダー容量はハードリンクを重複して数えます。削除量の見積もりではファイルの識別情報とリンク数を使い、削除後は実際の空き容量で回収量を確認します。モデルへの参照だけを削除した場合と、最後の参照を削除して実体を解放した場合を区別します。

検証workspaceは終了後に文書化して整理し、モデルを含むworkspace全体を長期レポートへ複製しません。モデルの用途とSHA256を管理する定義・台帳を残し、本体はGPUで再取得します。PCにある旧モデル本体を削除するときは、明示した対象一覧と停止確認に従います。検証画像を削除した後は、過去の実画像を再確認できないことを検証記録へ明記します。

通常の整理では、SSH鍵などの認証情報を整理のためだけに複製せず、元の保存フォルダーを削除対象から除外します。使用中の一時ファイルも保持し、除外理由を記録します。タスクの主作業場所としてアーカイブできない作業ツリーは、ソースとGitを保持し、生成物だけを整理します。

Windowsで長いパスによりworktreeの削除が一部失敗した場合は、Gitの登録状態と残存フォルダーを別々に確認します。未保存変更がないこととコミットの保持を確認し、検証済みの範囲に残る生成物を整理します。ジャンクションは参照先を削除せず、リンクそのものだけを外します。

## 作業場所を統一する

通常の開発・起動・検証は主作業フォルダーに集約します。Git worktreeは変更を分離する期間だけ使用し、終了後にコード、検証記録、環境をそれぞれ整理します。仮想環境やモデルを含む作業フォルダー全体を別の場所へ複製しません。

1. 各作業場所の未コミット変更、GPU所有、監視、利用中プロセスを確認します。個人設定は内容ハッシュ付きで退避し、主作業フォルダーの設定を優先します。
2. コードは検証済みのPRから反映します。環境は主作業フォルダーで標準のbootstrapを実行して更新し、別の場所のvenvを移動して再利用しません。
3. 原因、設計判断、固定した再現条件、集計、未達を文書へ反映します。非公開の原文、プロンプト、画像は公開文書へ転載しません。
4. 代表作品と未解決の反例は、必要な親画像・実行グラフ・評価・固定入力と一緒に主作業フォルダーのrecordsへ保全します。元の記録を変更せず、移動元・移動先・SHA256と保持理由を別の一覧へ残します。
5. 再描画したPDF、同じ作品の中間版、重複した画面用JSON、過去のHTMLカバレッジ、再作成できるキャッシュと未使用環境を整理します。使わないモデル本体も、用途とSHA256、停止を確認して整理します。
6. 保持したファイルを照合してから元の生成物を削除します。削除した個別画像は再レビューできないことを検証記録へ明記し、保存当時の集計を現在の観測へ書き換えません。

別チャットやエディターが使う作業場所は、先に参照先を切り替えます。参照が残る環境やアプリが主作業場所として保持するチェックアウトを強制削除しません。Google・Hugging Faceの標準認証とOS資格情報ストア、計画用LLMは整理対象にしません。SSH鍵を保全する必要がある場合は秘密情報をログへ出さず、一度だけ移動して照合します。

## 新規記録と旧作品

新規の会話、操作、画像要求、評価はdata/komaquill.sqlite3へ保存します。画像、入力素材、実行グラフはdata配下のファイルとして保持します。DBの移行は同梱するAlembicで管理し、旧作品の原本を変換しません。

data/storiesと旧ファイル形式の履歴は読み取り専用のarchiveで扱います。配置表、原文、計画、試行、画像、失敗記録を一式で保全します。配置表が欠けた場合は生成済み記録を未送信として扱わず、元のバックアップを確認します。旧migrateコマンドと配置表の自動再構築は提供しません。

新規画像の回収とGPU停止は旧作品の配置表へ依存しません。旧作品の破損を、新しい要求を再送する根拠にしません。[バックアップと復元](backup.md)と[archiveの操作](../guides/stories.md)を参照してください。
