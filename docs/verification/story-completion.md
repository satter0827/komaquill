# 短編漫画の完成を検証する

## 対象と準備

既定短編「雨の日の青い傘」の原文と対応するFake応答を使う。任意入力をFakeが理解したとは扱わない。確定済みの4場面の計画、原文参照、人物設定を専用の作業場所へ保全する。モデルと既存の作品は上書きしない。

[完走補助](../../tests/live/story_completion.py)でprepare、start、baseline、improve、screen、stopを実行する。正確な引数は同モジュールの--helpを参照する。モデル準備、生成、レビュー、組版は異なる失敗単位として記録する。問題は再現、原因の切り分け、最小修正、同原因の確認、回帰検証の順に解決する。

## 生成とレビュー

最初に各場面1枚を保存する。画質の不合格では後続場面を止めない。Codexが実画像を見て、原文との一致、対象数、身体、小物、場面間の連続性を評価する。必要な場合だけ明示許可されたローカルVLMを使う。評価者のモデルと指示を記録する。

具体的な問題がある最大2場面を各2回まで、参照画像編集で改善する。主出力の上限は12枚で、基準4枚、改善4枚、画面確認2枚、技術的再試行2枚に分ける。再開で予算を戻さない。受付不明は再送しない。

[レポート処理](../../tests/live/completion_report.py)は有効なLLM選択を優先する。未評価、全候補不合格、不正応答、タイムアウトでは直前の有効選択を保持し、初回は生成順と候補位置で選ぶ。場面の対応、画像ハッシュ、画像の読み取りを検査する。選択理由と評価は別に保存し、人間の判断待ちを設けない。

## 回収と出力

T4は1セッションとし、準備・転送・終了を含め90分を上限とする。70分で新規送信を止め、回収と終了へ進む。LLMとは独立した監視が所有記録の時計を確認する。停止を確認できなければ所有記録を保持する。

追加のセッションが明示的に承認された場合だけ、startに`--allow-additional-session`を指定できる。元の停止確認後に一回だけ起動し、画像の累積予算を維持する。追加分の期限は完走補助の定数を使い、元の開始時刻と追加の開始時刻を別に保存する。

GPU終了後も保存済み画像から選択と組版を行える。[組版処理](../../tests/live/completion_page.py)はA4縦の右上、左上、右下、左下へ4場面を配置し、原文に対応する本文を付ける。文字欠落、はみ出し、参照画像、出力を検査する。有効画像がない場面を仮画像で埋めない。

## 証拠と完了条件

実行版、コードと入力の内容ハッシュ、全資源、実行グラフ、全候補、評価・選択・改善の対応、経過時間、PNG・PDF、未達事項、GPU停止結果を.artifacts/recordsへ保存する。公開文書は原文や作品を転載せず、対象版と結果を要約する。

Fake・localhost、lint、formatter、型検査、累積L2・L3、T4のCLI・App Mode・Node Graphの生成・編集・保存を確認する。漫画の出力完了と画質の達成状況は別に報告する。
