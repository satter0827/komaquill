# 保存・セット・操作の再編の検証

## 対象と環境

2026年10月24日、日本時間。Windows ARM64上のx64 Python 3.12.15、Node.js 24、Colab T4を使用しました。固定したComfyUI・フロントエンド・依存はresources/runtimeの定義に従います。

最終パッケージのコード識別子は`99a8511da56c0c02`、最終T4のGPUコード識別子は`a5c2a3c6e25ec03a`です。完全なSHA256、対象コミット、検査入力、時刻と終了コードは.artifacts/records/reports/rebuild-baselineとqualityへ保存します。検証中の作業ツリーには未コミットの変更があったため、コミット名だけで判定せず内容ハッシュを照合します。

## GPUを使わない検査

Pythonの行・分岐カバレッジは90%・80%を独立判定します。整形・lint・strict mypy・依存・文書参照・Node標準テスト・Pythonテストを検査しました。Python 521件、Node 8件が成功し、行94.62%・分岐86.20%でした。完全な測定値と終了コードは同じコード識別子の品質記録で確認できます。

Windows／LinuxのCIは、通常の隔離buildとwheel E2Eを実施します。リポジトリ外の作業フォルダーで初期化、利用者セットの追加・上書き、外部接続、生成・保存、整理のプレビュー、GPU転送物の作成・importを確認します。[第1段階](https://github.com/satter0827/komaquill/pull/13)、[第2段階](https://github.com/satter0827/komaquill/pull/14)、[第3段階](https://github.com/satter0827/komaquill/pull/15)、[第4段階](https://github.com/satter0827/komaquill/pull/16)の必須チェックで対象版と成否を確認できます。

## 検出した問題と修正

GPU進捗の発行先へローカル用のrecords分類が適用され、取得先と不一致になっていました。GpuPathsを発行・設定・取得・ログ回収で共有し、実際に発行したファイルを取得する回帰検査とT4で確認しました。

過去の同名ワークフローを拾って失敗した実機検査は、ランタイムと入力ハッシュで識別して再検証しました。環境を有効化せずに呼んだcleanが導入済みuvを発見できない問題は、明示指定・作業環境内・PATHの順に探索する形へ修正しました。失敗記録には安全なエラー分類も保存します。

## 環境上の制約

ローカルの通常品質ゲートは、新しい仮想環境のPython実行をWindowsアプリ制御が拒否し、隔離buildで停止します。最新成功は更新しません。既存環境でのbuildと配布内容検査は成功し、隔離build・wheel E2EはCIで別途確認します。OSの保護機能は変更していません。

別のGPUサービスの実機確認、未保存の画面編集、認証必須モデル、動画・音声はこの検証に含みません。使用中のキャッシュと用途不明の一時ファイルは、理由を整理記録へ残して保持しています。
