状態: 画面とAPIの基本版を実装・自動検証済み。詳細な状態制約、ターン限定の方針、実LLM・GPUの受入は継続中。現状確認日: 2026-10-31 JST。

## 目的と完成範囲

React画面を起動し、会話の作成、反復入力、現在状態の確認、保存・再開、画像の生成と表示を一連の操作として確認できることを最初の目標にする。同じPCのブラウザーで利用するローカルアプリを完成させ、応答精度や画像品質の高度化は後続の改善とする。

pipで導入し、呼び出し側のPythonアプリケーションへ組み込める、独立した会話ライブラリを本体にする。CLIとHTTP APIは同じ公開APIを使い、ReactはHTTP APIを呼ぶ。画面だけの模擬実装や、画面とCLIで別々の会話処理を作る構成にはしない。

応答は会話を中心とし、状況が伝わる短い場面描写、必要な擬音・擬態語、画像を添える。長い小説、全場面の事前計画、結末までの自動執筆を初版の目的にしない。擬音を毎回強制しない。まず一貫した会話と状態の保存・再開が動くことを優先し、文章品質や演出の高度化は後から改善する。

日常、SF、中世、ファンタジーなどの世界観、物語の前提、キャラクター、ユーザー、初期状態、応答方針を引数または設定で指定できるようにする。作例の人物、時代、種族、地名、口調を実装へ固定しない。キャラクター設定や画像接続を省略した通常の文章チャットも同じ公開APIで扱う。

画像の標準構成はWAIと対応LoRAへ統一する。ライブラリではモデル資源、LoRA、ワークフロー、入力対応、品質条件を一式で差し替えられるようにする。WAI専用の型やタグを会話処理へ持ち込まない。

現在のApp Mode、Node Graph、ブラウザの起動・再表示、素材と保存ワークフローの保全は維持する。会話を作らずに行う単発画像生成も、CLI・Python API・ブラウザの副機能として維持する。Reactの会話画面は初版へ含め、既存ブラウザモードへの入口も残す。

永続化、重複送信防止、復旧、所有確認、失敗表示を初版の必須要件とする。対象機能は実装・検証・文書まで完結させ、未接続の操作、仮の成功応答、恒久的な互換層を残さない。文章の好み、完全な人物同一性、品質タグの最適化は基本操作の完成後に改善する。

## モノレポの配置と責務

製品コードはルートのsrcへ集約し、その直下をfrontend、backend、contractsに分ける。ReactとPythonを同じ製品ルートの下へ置き、画面、業務処理、通信の責務は内部のモジュールで分離する。既存ソースをそのまま移動するだけでなく、責務、名称、依存、モジュールの粒度を見直す。

```text
src/                         製品コードの共通ルート
  frontend/                  Reactの画面
    src/
      app/                   起動とルーティング
      features/              会話、画像、実行環境
      components/            共有するUI部品
      api/                   生成したクライアントと通信設定
    public/
    tests/
    package.json
    AGENTS.md
  backend/                   Pythonライブラリ・CLI・HTTP入口
    src/komaquill/
      api/                   公開Client、入力型、結果型
      conversations/         会話、状態、コマンド、文脈
      images/                単発・会話共通の画像生成と回収
      runtime/               起動、所有、監視、終了
      domain/                共有する型と契約
      application/           終了調整、準備、評価の判断
      archive/               旧記録を読む型
      adapters/              LLM、DB、保存、ComfyUI、Colab
      cli/                   公開APIを使う入力と表示
      interfaces/http/       FastAPIの組み立て・ルート・HTTP固有の型
      composition.py         設定と具体的実装の組み立て
      worker/                GPU側の準備・起動とComfyUI拡張
      resources/             既定値、文言、モデル、生成セット
    pyproject.toml
    uv.lock
    AGENTS.md
  contracts/                 OpenAPIのスナップショット
tests/                       Pythonの検証、横断E2E、共通ツールの検証
scripts/                     検証の実行管理と配布

docs/
pyproject.toml               共通の開発・検証設定
package.json                 共通JavaScript開発ツール
pnpm-workspace.yaml
```

Pythonはbackend内の一つのパッケージとして管理し、同じ場所のpyproject.tomlとuv.lockで依存を固定する。HTTPサーバーは追加依存とし、通常のライブラリ利用ではFastAPIやUvicornを要求しない。パッケージを分けるためだけのuv workspaceは導入しない。ライブラリだけを導入した隔離環境でも、公開APIの読込みと利用を確認する。

Reactはfrontendのpackage.json、JavaScriptの固定依存と共通開発ツールはルートのpnpm-lock.yamlとpackage.jsonで管理する。製品コードの集約と、導入・ビルド・検証の単位を分けることを両立させる。共通の検証コード、環境導入、文書、実行時データはsrcへ混在させず、それぞれtests、scripts、bootstrap、docs、.artifactsへ置く。

ライブラリは機能を第一の区切りとし、各機能の中でモデル、処理、必要な境界を分ける。分割は責務と変更理由で決め、空の層や一つの処理を過度に細分化したファイルを作らない。汎用utilsや汎用プラグイン機構へ集約せず、共有が必要なエラー、進捗、識別情報だけを明示した契約へ置く。

全製品の配置と責務の対応表を作り、設定ロード、保存、実行制御、表示が混在する箇所と、同じ原因を持つ箇所を整理する。後方互換のための別名、旧パスへのフォールバック、重複するサービス、未使用の設定とテストは削除する。評価と分析は残す機能を新しい画像記録へ接続し、旧記録の読取りだけに必要な処理は隔離する。

責務の整理は機能の実装と同時に行う。新しい処理の隣へ旧サービスを残したまま、最後にまとめて置き換える進め方は採らない。最終段階の全体整理では、移動漏れと未使用の参照を確認する。

- CLIとHTTP入口はkomaquill.apiを使い、ライブラリ内の依存の組み立てをcompositionへ集める。API importでは通信、ファイル作成、認証、出力、プロセス起動をしない。
- conversationsとimagesの業務処理は、LLM SDK、SQLAlchemy、ファイル、ComfyUI、Colab、表示文言へ直接依存しない。Pythonの業務処理からHTTP入口やReactへ逆依存しない。
- conversationsは画像生成の契約を呼び、imagesからconversationsへ逆依存しない。単発生成に会話やキャラクターは必要ない。
- imagesはruntimeの具体的制御へ依存しない。runtimeの終了調整は回収の契約を受け取り、回収失敗でもGPU停止を試みる。
- workerへ会話、DB接続、LLM設定、原文、資格情報を配布しない。標準画面拡張に必要な契約と資源だけを配布する。
- Import Linter、wheel同梱検査、GPU転送物検査を新配置へ更新し、旧パスの再公開や恒久的な別名で循環依存を隠さない。

## 公開APIと実行環境

入口は引き続きkomaquill.apiとする。公開する入力と結果を明示し、内部クラスを一括公開しない。Clientの作業場所と接続設定は呼び出し側から渡せるようにし、CLIのカレントディレクトリ探索や端末入力をPython利用へ要求しない。

| API案 | 責務 |
|---|---|
| Client.initialize | 明示した作業場所と設定から初期化する。既存ファイルを上書きしない |
| client.conversations.create | シナリオ、キャラ、ユーザー、初期状態、応答方針を受けて会話を作る |
| client.conversations.list / get | 保存済みの会話一覧と、選択した会話の確定済み履歴を取得する |
| client.conversations.send | 会話ID、本文、操作IDを受け、一つの入力に対する進捗と結果を返す |
| client.conversations.status | 公開可能な現在状態と処理状況を保存記録から取得する |
| client.conversations.command | 型付きコマンドを検証して適用する |
| client.conversations.resume | 保存済み会話と未完了処理を照合し、元の入力から再開する |
| client.operations.get | 受付済みの操作の進捗と結果を保存記録から取得する |
| client.images.submit / get / collect | 完了を待たずに要求を送信し、状態取得と回収を行う |
| client.images.generate | submitと同じ処理を使い、保存まで待つ同期操作を提供する |
| client.runtime | 起動、稼働状況、再接続、終了を明示操作する |
| client.archive.list / get / export | 旧作品を読取り専用で閲覧・書き出しする |

この表の機能名を公開APIの契約とする。通常の返り値、型付き失敗、進捗イベントを使い、ライブラリがコンソール出力やSystemExit、ブラウザ起動を決めない。文書、CLI、型付きPython引数に同じ意味の設定名を使う。archiveには新規生成・更新・移行の操作を追加しない。

Gitとuvの利用は制限しない。独立したライブラリとしてwheelから利用でき、特定の開発チェックアウト、固定GPU、固定DBサーバー、固定LLMプロセスを前提にしない。現行の[pyproject.toml](../../pyproject.toml)から対応Python・OS・依存を引き継ぎ、再配置後はbackendのpyproject.tomlとuv.lockを正本とする。接続先が必要な処理で未設定や未対応を検出したら、型付きの失敗として返す。

初版のDBはSQLite、LLMは現在のFakeとOpenAI互換プロファイル、画像生成はComfyUIを使う。外部ComfyUIを使う場合にローカルGPUやColab認証を要求しない。画像を無効にした会話は画像接続なしで動く。任意のモデルの自動取得や自動フォールバックは追加しない。

GPUの新規確保は明示的なstartだけで行う。send、単発生成、import、初期化、状態確認からGPUを自動確保しない。接続と所有が不明な場合は記録を保持して失敗を返し、既存の回収・停止の入口を維持する。

## React画面とHTTP API

React、TypeScript、Vite、shadcn/ui、Tailwind CSSを使用する。shadcn/uiの基盤はBase UIへ固定する。画面遷移はReact Router、サーバー状態の取得はTanStack Queryで管理する。assistant-ui、独立した会話ストア、トークン単位の逐次表示は初版へ導入しない。

| 画面 | 操作と表示 | 完了の確認 |
|---|---|---|
| 会話 | 左に一覧、中央に本文と画像、右に現在状態を置く。右側は閉じられ、狭い画面では左右を引き出し表示にする | 一覧から選択し、送信、状態確認、再読み込み、再開できる |
| 新規会話 | シナリオ、キャラクター、ユーザー、応答方針、画像の有無を入力する | 画像とキャラクター設定を省略した会話も作成できる |
| 単発画像 | 生成条件、進捗、保存画像、失敗と再回収を表示する | 会話なしで生成し、保存済み画像を表示できる |
| 実行環境と設定 | 保存された観測と時刻、開始、明示的な再確認、停止、App ModeとNode Graphへの入口を置く | 観測と不明状態を区別し、操作後の結果を確認できる |

専用のキャラクター管理画面、会話の分岐、LAN公開、複数利用者向け認証は初版へ含めない。人物や世界観の入力は利用者データとし、実装へ固定しない。画面の操作案内は英語とし、会話やプロンプトの言語を変更しない。

FastAPIのHTTP入口は公開Python APIを呼び、HTTP入力の検証と結果の変換に限定する。APIは/api/v1配下で会話、操作、入力素材、画像、実行環境を扱う。画面からDBやローカルの任意パスを直接扱わせず、保存物は識別子から取得する。

長時間操作は操作IDと入力内容を記録して受付結果を返し、画面が処理中の操作をポーリングする。本文は検証と保存の確定後に表示し、画像は別の進捗と成否を持つ。同じIDと入力では既存結果を返し、IDが同じで内容が異なる要求は拒否する。更新要求の自動再試行とオフライン送信待ちは無効にし、再接続では状態だけを取得する。

実行権とチェックポイントをDBへ保存し、HTTPプロセス内のバックグラウンド処理だけを正本にしない。CLIとHTTPの並行操作でも確定条件を共有する。サーバー再起動で処理が失われた場合は所有と保存済み結果を照合し、受付不明のLLM・画像要求を自動再送しない。

初版のHTTPサーバーは一つの作業場所を扱う単一プロセスとする。新しい会話送信の実行中は、別の送信をキューへ蓄積せず、処理中であることを返す。同じ操作IDの再照会は既存結果を返す。CLIも同じ処理権を使用し、本文確定後は画像の完了待ちと独立して次の送信を受け付ける。状態取得、画像回収、GPU停止は会話送信の実行枠を共有しない。

HTTPの会話送信と画像送信は受付時に202を返し、操作IDまたは画像要求IDから状態を取得する。会話操作の完了は本文と状態の保存確定を表し、画像の保存成功とは区別する。プロセス終了後の再開は、保存済み応答の再利用と外部要求の照合から始め、追加の実LLM呼び出しには操作ごとの明示許可を要求する。

HTTPの型定義からOpenAPIを出力し、src/contractsのスナップショットからHey APIでTypeScriptクライアントを生成する。定義と生成物の手書きによる二重更新を避け、CIでは一時領域へ生成して差分を検査する。OpenAPIの出力だけで認証、DB初期化、GPU確保を発生させない。

文言はPython製品、React画面、開発ツールごとに担当を分ける。APIは安全なエラーコードと詳細を返し、画面へ例外本文や秘密情報を渡さない。設定、監視間隔、ポートを複数の実装へ重複定義しない。既存の単一文言カタログと.js規則は、実装時に担当と適用範囲を明確にする。.js規則はComfyUI拡張へ適用し、Reactのソースには.tsと.tsx、配信物にはViteの標準出力とキャッシュ方式を使う。

## 配布と起動

Pythonの配布名とimport名はkomaquillを維持する。Web用の追加依存へFastAPIとUvicornをまとめ、HTTP入口の明示的な起動時にだけ読み込む。配布するwheelとsdistへビルド済みReact画面を含め、通常のライブラリ利用ではWeb依存や画面の起動を要求しない。

利用者はWeb用と必要なLLM・Colab用の追加依存を含めてPythonから導入し、komaquill webコマンドへ作業場所を渡して起動する。Node.jsは開発と画面ビルドでのみ使用する。配布工程はReactの静的出力とbackendのソースを.artifacts内で組み立て、画面をPythonパッケージの資源へ取り込む。追跡対象へビルド結果を書き戻さず、sdistからの再構築にも画面を同梱して利用者側でのJavaScriptビルドを要求しない。

ReactとPythonのテストは独立して実行できるようにし、全体の配布工程でだけ両方の成果物を結合する。Reactの配信物、HTTPの依存、会話処理をGPUへ転送しない。フロントだけの変更でGPU転送物のハッシュが変わらないことを検査する。

同梱画面とAPIは同じローカルサーバーから配信する。待受はループバックへ限定し、許可したOriginを検証する。APIの404を画面のHTMLへ変換せず、ブラウザーは明示オプションで開く。開発時のViteは同じAPIへプロキシする。

作業場所と設定は起動時に確定し、ブラウザーを閉じてもGPUの停止とは扱わない。Colabの対話認証はCLIで完了させ、HTTPや監視へ端末の入力待ちを持ち込まない。認証が必要な場合は問題と対応するCLI操作を表示する。

## 設定と現在状態

ScenarioDefinition、CharacterDefinition、UserDefinition、ConversationPolicy、SceneStateを区別する。ファイル入力はCLIなどのインターフェースで読み、ライブラリへ同じ型の入力として渡せるようにする。

| 対象 | 主な情報と更新規則 |
|---|---|
| シナリオ | 世界観、時代、前提、開始場面、用語、世界のルール |
| キャラクター | 種別、固定した外見、性格、口調、背景、知識と公開範囲 |
| ユーザー | 作中の設定、呼称、AIが代行してよい発言・行動の範囲 |
| 応答方針 | 会話と描写の配分、視点、長さ、擬音の扱い、画像の有無 |
| 現在状態 | 場所、時間、登場対象、衣装、所持品、関係、進行中の出来事 |
| シナリオ固有の内部パラメータ | 宣言した型、範囲、更新権限、表示範囲を持つ。必要な項目だけ定義する |

現代の地名、職業、人間の身体、貨幣、暦を必須にしない。SFの宇宙船や人工知能、中世・空想世界の制度や存在を設定として表現する。何でも受け入れる未検証の辞書にせず、拡張項目も入力で宣言したスキーマで検証する。

固定した定義と会話開始時の実効設定はスナップショットとして保存する。外部設定ファイルの編集を進行中の会話へ暗黙反映しない。明示コマンドで変更可能な項目は新しい版として記録し、既存ターンの入力と状態を書き換えない。

作業場所、起動設定、会話設定、生成条件の確定時点を分ける。作業場所と起動設定は起動時、会話の定義は作成時、画像入力とseedは要求作成時に固定する。設定ファイルの再読込みで確定済みの値を置き換えない。ポート、待機時間、入力上限などの運用値は既定設定と作業設定で扱い、画面へ必要な値だけを公開する。内部の固定条件は名前付き定数とし、利用者向け設定を増やさない。

コンテキストは、固定定義、有効な指示、確定状態、重要な出来事、直近の履歴から構成する。入力予算を検査し、古い会話を省略しても固定設定と現在状態を落とさない。過去の全発言を覚える保証と現在状態の保持を混同しない。初版からベクトルDBや自律的な記憶agentを必須にしない。

## 会話の進行とターン処理

初版は、通常のプログラムによる進行制御と、一回の構造化LLM応答で処理する。本文、状態変更案、重要な出来事、描く場面をまとめて受け取る。進行案と本文を別々に生成するDirector・Responder構成は採用しない。

| 要素 | 入力と出力 | 権限 |
|---|---|---|
| 会話サービス | 操作ID、設定と状態の版、保存済みチェックポイント | 受付、順序、上限、検証、保存確定を管理する。LLMではない |
| LLMアダプター | 確定設定、現在状態、履歴、入力から本文と変更案を返す | 状態変更を提案する。DBやGPUを直接操作しない |
| Validatorと画像入力変換 | 型、参照、変更権限、状態の版、描画条件を検証する | 決定的な処理とし、独立した批評LLMを毎ターン呼ばない |

既存のLangChain接続と型付き入出力を使い、別のagent実行基盤や批評LLMを初版へ追加しない。構造化出力と検証によって、意味の正しさまで保証されるとは扱わない。

1. 操作IDを一意に受付し、設定・状態・履歴の版と、送信予定のLLMメッセージを非公開記録へ保存する。
2. LLMを呼び出して構造化応答を保存する。同じ作業場所のLLM呼び出しは修正を含めて直列化する。
3. 型、既存ID、確定設定、ユーザーの操作範囲、状態変更権限を検査する。修正呼び出しはターン全体で上限を持ち、修正で履歴を消さない。
4. 応答、採用した状態変更、重要な出来事、固定した画像要求を、一つの短いDBトランザクションで確定する。LLM提案だけの状態を公開しない。
5. 保存済みの文章を返して会話の処理権を解放し、固定した画像要求を実行する。画像の完了待ちで次の会話入力を妨げない。CLIとAPIは画像の進捗も別に取得できる。
6. 画像の生成・回収結果を別に確定する。画像失敗で文章や現在状態を後退させず、同じ画像入力から回収・明示再試行できるようにする。

LLM通信中にDBトランザクションを保持しない。会話ごとの処理権と状態の版を確認し、古い版の応答を確定しない。会話の直列化で画像回収、状態確認、GPU停止を妨げない。中断後は保存済み応答とチェックポイントを再利用し、受付不明の実LLM呼び出しや画像要求を自動再送しない。

実LLMの許可は一回のsendと、その操作に明示した修正上限へ結び付ける。許可を次のsendへ暗黙継承しない。CLIと画面の明示送信を一操作として扱い、状態確認や通常コマンドで実LLMを呼ばない。SDKの自動再試行、外部トレース、自動モデル変更は禁止を維持する。

## 応答、状態確認、コマンド

応答は順序付きの文章ブロックと画像参照を持つ。会話、短い描写、効果音文字を必要に応じて含め、全応答へ同じ構成や擬音を強制しない。単純な文章チャットではロールプレイの専用項目を必須にしない。会話の言語と利用者の入力データは維持し、製品の操作案内はmessages.jsonの英語で扱う。

`/status`と対応するPython APIは、保存された現在状態から、場所、時間、登場対象、外見と衣装、所持品、進行中の出来事、有効な方針、最後に確定したターンを返す。初版から利用できる必須機能にする。LLM、画像生成、GPU確保を行わず、未確定値は不明と表示する。

会話の現在状態、処理中・失敗したターン、画像の処理状況、GPUの実稼働確認を区別する。通常の会話状態確認でGPUの生存を推測しない。登場対象だけが知る設定などの非公開情報は、表示対象の権限に応じて除外する。保存記録を読めない場合に、新しい会話や空の状態として扱わない。

コマンドの初期案は`/status`、`/direction`、`/state set`、`/image`、`/image retry`、`/help`、`/exit`。状態の確定変更と、LLMへの表現・展開の指示を区別する。次のターン限定か会話中継続かを明示し、操作ID、適用前後の版、結果を記録する。変更できない設定や不明なフィールドは送信前に拒否する。`/exit`による対話終了と所有GPUの停止は別の操作とし、GPUの状態を案内する。

## SQLiteと差し替え可能な保存境界

SQLiteを初版の保存先とし、SQLAlchemyとAlembicを使用する。現在のworker依存に含まれるだけのSQLAlchemyをローカルで使用できるとはみなさず、実装時にローカル側の依存と固定ロック、移行資源のwheel同梱を追加する。業務型はPydanticの型付き契約、DBテーブルは具体的アダプター内に置く。

ConversationRepository、GenerationRepository、トランザクションの作業単位、ArtifactStoreを、実際に交換する必要のある境界として定義する。SQLAlchemyのSessionやクエリ、SQLiteのパス、DB接続型を公開APIや会話処理へ渡さない。汎用CRUD層や任意DBの自動検出は追加しない。

初期の記録対象は、会話と定義スナップショット、ターン、メッセージ、コマンド、状態の版、LLM呼び出し、画像要求、保存物参照、新規評価とする。検索・関連付け・一意性に必要なキーは列にし、版付きの状態や構造化応答は検証済みJSONとして扱う。すべてのデータを巨大なJSON一個へ集約しない。

| 記録 | 正本 | 更新の担当 |
|---|---|---|
| 新規会話、ターン、操作、新規画像要求、新規評価 | SQLite | 同じリポジトリを使う各機能のサービス |
| 画像、入力素材、実行グラフ、非公開の呼び出し記録 | ArtifactStoreの実体とDBの論理参照 | 保存アダプター |
| GPUの所有、監視プロセス、停止要求、確定した起動条件 | 既存の所有・監視用ファイル | 実行環境の制御と監視 |
| 旧Story・Run・評価 | 既存ファイル | archiveによる読取り専用の取得 |

DB導入を理由にGPUの所有記録まで移行しない。新規要求の状態はDB、実行環境の所有は既存の所有記録へ一意に定め、同じ状態を双方へ書き込まない。PIDだけでなくプロセス開始時刻と操作IDを照合する契約を維持し、移動する監視の起動モジュール名と照合処理も同時に更新する。

評価は対象の画像記録を論理参照で識別する。旧作品への新しい評価も新規記録として保存し、archiveが保持する元の作品・評価を変更しない。分析用出力では、旧記録と新規記録の出自と未知の項目を区別する。

- DBと画像ファイルは作業フォルダーの.artifacts/data配下、実行診断はrecords、所有と復旧情報はstateへ保存する。DB接続先や資格情報を診断へ出力しない。
- 新しい会話と画像要求の正本をSQLiteへ集め、同じ状態をJSONとDBの二か所で更新しない。旧Story・Runは保全対象として分離する。
- 新規要求の送信、回収、監視、停止、CLI、HTTPは同じDB保存境界を使う。旧ファイル保存へ新規要求を書き続けたり、旧記録の欠損を新規DBの未送信状態と推測したりしない。
- DBへ画像バイナリを詰め込まず、ArtifactStoreの論理キーとハッシュを保存する。絶対パスを業務上の識別子にしない。
- ファイルは一時保存、検証、原子的な確定の後にDB参照を確定する。中断して残ったファイルや未確定参照を照合できるようにし、DBとファイルの一括原子性を仮定しない。
- 操作IDの一意制約と状態の版による競合検出を使う。SQLiteのロック方式をそのまま業務契約にせず、将来のPostgreSQLでも同じ意味の確定条件を維持する。
- 外部キー、トランザクション、UTC時刻、ID、一意制約、削除規則を明示する。SQLiteでの成功をPostgreSQL互換の確認済み結果にしない。
- Alembicの移行は版管理し、初期作成、旧DBからの更新、途中失敗、バックアップ復旧を検証する。SQLiteではテーブル再構築を伴う変更があるため、接続URLの変更だけで移行が済むとは扱わない。

SQLAlchemyの[トランザクション管理](https://docs.sqlalchemy.org/en/20/orm/session_transaction.html)とAlembicの[SQLite移行](https://alembic.sqlalchemy.org/en/latest/batch.html)を根拠に、この保存境界を推奨する。具体的なライブラリ版は実装時にpyproject.tomlとuv.lockで固定する。

PostgreSQLとSupabaseへの接続は初版の対象外とする。保存の具体的な接続を業務処理へ持ち込まず、将来の変更時に必要な移行と検証を行う。初版にない接続先のためだけの自動検出や汎用DB層は追加しない。

## 画像生成、二つのプロンプト、ブラウザ

画像生成は独立した機能として維持する。会話からは、そのターンに固定した描く瞬間と可視対象を受け取る。単発生成は利用者の直接入力を受け取る。両方を同じ入力合成、固定ワークフロー、要求記録、回収処理へ渡す。

利用者指定のpositiveとnegativeをCLI・Python API・App Modeで受け付ける。品質用のpositiveとnegativeは生成セットで管理し、既定で暗黙適用する。LLMは内容と避けたい描写を扱い、masterpieceなどの品質語、LoRA名、モデル固有の採点タグを生成しなくてよい構成にする。

初版は現在の[資源定義](https://github.com/satter0827/komaquill/blob/91b503b1ee40a71506cc6c26fbf42e64a227651c/src/komaquill/resources/models/wai-illustrious.toml)と[生成セット](https://github.com/satter0827/komaquill/blob/91b503b1ee40a71506cc6c26fbf42e64a227651c/src/komaquill/resources/presets/wai-illustrious/preset.toml)を基準にする。品質条件へ原文にない画風、人物数、身体、年齢、場所、時代を固定する指定を混ぜない。不要な重複、正負の衝突、別モデル系列の語を避け、品質語の最適化は基本操作の完成後に実画像で確認する。

利用者の元入力、LLMの場面指定、品質設定の版、適用後のpositive・negative、生成セット、seed、送信グラフ、観測した実行グラフを対応付ける。品質条件の無効化・置換を明示設定で可能にし、利用者のnegativeが空でも品質条件の暗黙解除とは解釈しない。再開で合成をやり直さず、既定値の更新で保存済み条件を変えない。

モデル資源、LoRAの順序・強度、入出力、標準グラフ、品質条件を一式で差し替える。モデル固有の能力は生成セットで宣言し、対応しないnegativeや編集入力は送信前に説明付きで拒否する。任意のモデルが同じグラフで動く保証はしない。WAI以外の構成はFakeとグラフ契約で差し替え経路を検査できるようにし、実機検証済みモデルの範囲を別に記録する。

App ModeとNode Graphは標準JSONを使う。API用グラフと画面用グラフで二つのプロンプトと品質条件を一致させる。標準画面で実際に編集・実行したグラフを保存し、観測時に既定値を再合成して二重適用しない。ブラウザの単発要求は会話IDなしで保存し、無関係な会話へ自動関連付けしない。外部のComfyUIやその要求の所有範囲は維持する。

## Fake、ローカルLLM、実機の検証

| 区分 | 確認すること | 実行条件 |
|---|---|---|
| 単体 | コマンド、優先順位、型、権限、状態遷移、描く瞬間、正負の入力合成 | Fakeと固定データ |
| 結合 | SQLite実DB、トランザクション、再開、操作ID、同時実行、通信・保存の失敗 | ローカルファイルDBとlocalhostの擬似API |
| 構造 | 機能間依存、公開型、文言、グラフ対応、wheelとGPU配布範囲 | GPU・実LLMなし |
| 画面 | 入力、状態、エラー、再接続、画像の成否、更新要求の重複防止 | Vitest、React Testing Library、MSW |
| E2E | Reactと実HTTP API、CLIと別アプリからのPython API、wheel導入、反復入力、status、単発画像 | Playwright、Fake、SQLite、localhost |
| ローカルLLM | 実際の構造化出力、会話の継続、設定の反映、保存と再開 | 明示実行。現行の接続プロファイルとモデル照合を維持 |
| GPU・画面 | WAI、LoRA、正負プロンプト、品質条件、App Mode、Node Graph、単発と会話の画像、回収と終了 | T4と標準画面で別途確認 |

FakeListLLMの応答は、日常、SF、中世・空想世界などの入力列と構造化応答列を対で管理する。会話開始、場所・衣装変更、方針変更、ユーザーの操作範囲、状態確認、中断、画像失敗を含める。Fakeが任意の入力を理解したという評価はしない。

失敗注入には、不正JSON、拒否、出力途中終了、タイムアウト、LLM応答保存後・文章確定後の中断、HTTPプロセス再起動、ブラウザー再読み込み、二重送信、DB競合・破損、画像部分保存、ブラウザ生成、設定変更、SSH切断、ログ回収失敗、GPU終了失敗、監視再開を含める。statusがLLM・GPUを呼ばず、破損や不明値を表示できることも確認する。

ローカル実LLMの確認は接続、設定の反映、構造化応答、保存・再開に限定し、Fakeで確認できる失敗を実モデルで繰り返さない。実モデル名・版、実行設定、指示のハッシュ、入力列、出力、使用量と不明値を非公開記録へ保存する。実LLMとGPUは日常ゲートに含めず、実行許可環境変数を引き継がない。有料・外部APIへ自動切替しない。

文章の一貫性や画像品質は保存成功と分けて記録し、精度の改善を初版の完成条件へ混在させない。Fakeによる画面確認、実LLMとの接続確認、実画像生成の確認は別の実績として扱う。

## 変更範囲に応じた検証

Nxをタスクと依存関係の正本とし、formatter、lint、型検査、単体、結合、構造、E2E、配布を独立して定義する。Python用の専用プラグインや独自のimport解析器は追加せず、uvとpytestなどの標準コマンドを呼ぶ。旧累積ゲート全体をNxから再度呼ぶ二重の実行管理は残さない。

| 場面 | 入口 | 対象と結果の扱い |
|---|---|---|
| 修正中 | pnpm check | 変更した機能と依存する機能の関連検証を実行し、その範囲の結果を保存する |
| PR | pnpm check:ci | 影響するプロジェクトの全検証と関連E2Eを実行し、対象選択と必要な検査の成功をqualityで判定する |
| 公開前 | pnpm check:all | 全プロジェクト、配布物、隔離導入を実行し、全体検証の結果を保存する |

上記の入口を実装した。Pythonテストの配置と対象選択の判断は[ADR](../decisions/0013-react-python-monorepo.md)を参照する。frontend、backend、contracts、共通ツール、横断E2Eを独立したNxプロジェクトとして扱い、同じsrcに入っていることを理由に一つの検証単位へまとめない。

Reactだけの変更でライブラリ全体のテストを実行せず、HTTP契約や共有処理の変更では利用側へ検証を広げる。機能ごとの検証対象、ロックファイル、共通設定、OSと実行環境をタスクの入力へ含める。判定できない変更では対象を広げる。キャッシュはローカルとCI内で使用し、Nx Cloudは初版へ導入しない。

修正中の差分は基準ブランチとの共通祖先から取得し、コミット済み、ステージ済み、未ステージ、新規、削除の各変更を含める。PRは差分の基準と対象のSHAを固定する。プロジェクトの選択はNxの入力と依存関係から行う。Python内はASTの逆import依存で選び、共通設定・資源の変更とPRでは対象を広げる。AIによる省略判断は行わない。

配布タスクはReactのビルド成果物にも依存するが、Python単体テストの入力へReactの配信物を含めない。依存タスクの実行順だけで影響範囲を判定せず、生成元と生成物、入力、出力を明示する。frontendのみ、Pythonの機能のみ、HTTP契約、共通設定、ロックファイル、削除・新規ファイルの変更を用意し、選択された検証対象を確認する。

共通の実行管理は製品コードをimportせず、対象、選択理由、入力ハッシュ、実行結果、キャッシュ再利用、未実行理由を記録する。部分検証、古い成功、キャッシュ再利用を、新たに実行した全体成功として表示しない。qualityとsecurityを維持し、必須ワークフロー自体をパス条件で省略しない。

全Pythonソースの計測対象と行・分岐の閾値は、共通設定へ移す既存の規定を維持する。局所テストに全体カバレッジの判定を適用しない。検証方法を変更するPRでAGENTS、CI、VS Code、要件、操作手順も更新し、未実装の検証コマンドへ先に切り替えない。

配置変更は品質検査だけでなく、配布物、GPU転送物、起動モジュール、文言の読込み、要件参照、テスト検出、環境導入の参照先も同時に更新する。既存のルート固定の探索と計測対象を残さない。

## 実装の順序と受入条件

| 段階 | 成果物 | 完了の確認 |
|---|---|---|
| 1. 配置と画面起動 | 全製品の責務対応表、src/frontend・src/backend・src/contractsへの集約、API契約と検証タスク | pnpm devでReactと実サーバーを起動し、公開Python API経由で既存の状態を取得できる。移動部分の回帰を確認する |
| 2. 会話の基本操作 | SQLite、構造化応答、会話の作成・取得・送信・状態確認・再開、ReactとCLI | Reactから反復入力し、確定本文を表示し、画面とサーバーの再起動後にも保存済み会話を取得できる |
| 3. 画像と実行環境 | 会話画像、単発画像、WAI生成セット、進捗、失敗表示、回収、所有確認、既存ブラウザ | Reactから生成と保存画像の表示を確認する。画像失敗でも本文を保持し、回収と停止を実行できる |
| 4. 横断検証 | 各段階で整理した全モジュールの責務・名称・粒度と参照先の確認、文書更新 | 依存方向、公開API、GPU転送物を確認し、旧パス、互換層、重複実装、未接続の対象機能が残っていない |
| 5. 配布と受入 | 画面同梱パッケージとWeb用追加依存、導入・起動手順、明示した実接続確認 | Node.jsなしの隔離導入でReactを起動して基本操作を確認し、全体検証とCIを通す |

早い段階からReactと実サーバーを接続し、API・画面・保存を通る単位で完成させる。全モジュールを確認するが、責務と依存が適切な箇所まで形式だけの変更を加えない。名称と配置を直しただけの状態や、リファクタリング途中の構造を最終成果にしない。

pnpm devは開発用のReactとHTTPサーバーを起動する入口として追加する。作業場所の設定を使用し、ブラウザー、LLM、GPUを自動起動しない。Fakeやlocalhostの擬似APIは検証用の設定で明示的に選び、接続失敗時の自動フォールバックには使わない。

初版の基本操作は、会話の作成、複数回の送信、確定本文の表示、状態確認、画像要求の進捗と保存画像の表示、ブラウザー再読み込み、サーバー再起動、保存済み会話の再開までを一つの受入シナリオにする。同じシナリオで二重送信と画像失敗を確認し、本文が失われず、追加の外部送信が発生しないことを確認する。

最終の受入は、利用者がPythonから導入してReactを起動し、会話を作成、複数回入力、状態確認、方針変更、保存・再開、単発生成、保存画像の表示を行えること。操作と結果が実サーバーと保存処理につながり、既存ブラウザとPython APIも利用できることを確認する。外部接続なしの検証には入力と対のFakeとlocalhostの擬似APIを使い、実LLMと画像生成の接続は明示許可の範囲で別に確認する。Fakeの成功を実接続済みとは扱わない。

## 保全、廃止、後続改善

既存の作品、モデル台帳、履歴、評価、取得済みログは変更・削除しない。旧Storyを推測でConversationへ変換しない。既存データを再配置する必要がある場合は停止確認、一覧とSHA256、移動後の照合を行い、個別の移行手順を用意する。読取りやエクスポートに必要な旧契約だけを隔離し、新しい会話処理から依存しない。現時点で削除や実データ移行は行わない。

保存方式の切替前には、既存監視と所有する実行環境の終了を確認する。終了や所有が不明な場合は所有記録を保持し、新しい保存方式への切替とGPU確保を進めない。

Storyの新規生成モード、全場面の事前計画、短編の組版、Klein固有の新規拡張は廃止・対象外として整理する。GPUの所有照合、回収、停止、ブラウザ、単発生成、保存条件の固定、評価の保全は維持する。旧モードの廃止時期と既存データの閲覧・書き出し方法は配布前に明示する。

専用キャラクター管理、個人設定、再利用するストーリー、二言語対応、画像用英訳、生成物配置の次の要件は[作成と会話体験](creators-and-play.md)で扱う。会話の分岐・巻き戻し、長期記憶の高度化、多人数の自律進行、LAN公開、複数利用者、トークン単位の逐次表示、PostgreSQL/Supabaseの実装は後続とする。未実装機能のためだけに抽象層や必須接続を増やさない。
