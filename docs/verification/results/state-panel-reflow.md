# 状況パネルの再配置

対象: REQ-WEB-VISUAL-IDENTITY、REQ-WEB-ACCESSIBILITY。

2026年11月5日、mainの58524c070058d71ef7718cb4bf60b2b75b83a07dに対するUbuntu CIで、画面幅を狭くした直後のキーボード操作から状況Dialogが開かないケースを確認した。先行PRのWindows・Ubuntu・quality・securityは成功していたが、その結果を今回の成功へ読み替えない。

## 原因と修正

PC用とモバイル用で開閉状態が分かれており、幅の変更前の操作ハンドラーは、変更後に表示しない側の状態を更新していた。開いたPCペインを狭い画面へ変えてもDialogが閉じることも、日英のE2Eで再現した。

画面幅の通知前に開く操作が入る単体テスト1件と、開いた状態・閉じた状態を幅の切替で保つE2E2件を追加した。修正前はすべて失敗した。開閉状態を一つにまとめ、画面幅は表示先の選択だけに使う構成へ修正した。状態の同期用Effectや、ライブラリーのフォーカス処理を置き換える実装は追加していない。会話の保存形式、接続判定、モデル、描画処理は変更しない。

証跡は`.artifacts/records/reports/cherry-zero-base-20261105`の`main-ubuntu-58524.log`、`panel-race-before-native.log`、`panel-width-before.log`と、対応する画面・トレースへ保持した。サンドボックス内の一時ファイル置換で中断した単体テストは実行環境の失敗として分け、通常の環境で再現を確認した。

周辺機能の確認では、状況を開いたまま非表示にして幅を変えると、後から開いた状況Dialogが復帰ボタンを操作対象から外すことも再現した。上位の非表示状態をそのまま渡し、非表示中は状況Dialogを開かず意図を保持する。復帰後の状況を閉じた際のフォーカスも、Base UIの公開指定でヘッダーへ戻す。非表示・Escape・Tab・復帰を日英の回帰テストへ含めた。

同じ条件をモバイルメニューにも適用した。メニューから非表示にし、幅を広げて狭くするとメニューが再表示され、復帰操作が利用できなくなることを日英で再現した。メニューも非表示中は開かず、復帰時に保存した意図を使う。状態を同期する処理や独自のモーダル管理は追加しない。
