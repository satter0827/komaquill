# 4場面の完走と限定的な改善を検証する

## 目的

保存済みの4場面計画を使い、本文と各場面の画像を保存する。画像の保存完了と画質の合格を分け、画質が未達でも後続場面を生成する。新しい製品機能やLLMによる計画は追加しない。

## 準備

開発環境を有効化し、`python -m pytest tests/integration/stories/test_completion.py`で完走・再開・制限・評価参照を確認する。通常の品質ゲートはGPUと実LLMを使わない。

実機用の入口は`python -m tests.live.story_completion ACTION --report REPORT`とする。REPORTは`.artifacts/records/reports/story-completion/`内の新しいフォルダーを指定する。既存セッションを使用せず、検証専用の作業場所とポートを作る。

| ACTION | 必要な指定と確認 |
|---|---|
| `prepare` | `--source-workspace WORKSPACE --story-id STORY_ID`。保存済み計画を原本のまま複製し、Ponyの取得済みファイルを再利用する。`case.json`と固定ファイルのハッシュを確認する |
| `start` | `--allow-gpu`。初回の試行時刻を保存してから専用セッションを開始する。一度試行した作業場所から追加GPUを確保しない |
| `baseline` | `--allow-gpu`。4場面、各2候補を保存する。中断後は同じ操作で既存要求を照合する。確定した失敗だけ`--retry-failed`で一度再試行できる |
| `report` | 画像を目視して`reviews.json`へ採否・問題・仮選択を記入し、本文付きの閲覧例と分析記録を作る |
| `improve` | `--allow-gpu --request FILE`。重大な問題のある最大2場面に限り、各2候補を追加する。同じ要求ファイルの再実行は照合のみとする |
| `stop` | `--allow-gpu`。この作業場所が所有するセッションを停止する。固定入力やcase.jsonが破損しても停止を試みる |

`case.json`に出力予約と起動時刻を保持する。開始から40分以降は新規送信せず、準備・回収・停止を含め60分以内に終了する。主出力は技術的な再試行を含め最大12枚とする。受付不明の要求は再送しない。停止確認ができなければ所有記録を残す。

## 改善方法

対象数や構図の誤りは`regenerate`、一部分の誤りは`inpaint`を選ぶ。局所補正の要求には場面番号、親画像の論理キー、正負プロンプト、マスクのファイル名を記載する。マスクは白が編集対象で、元画像と同じ寸法にする。

検証用の局所補正グラフは元画像とマスクだけを入力し、標準ノードのVAEEncode、SetLatentNoiseMask、KSamplerでdenoise 0.55の補正を行う。最後に編集範囲外を元画像から復元する。切り出し・拡大縮小・追加モデルは使わない。擬似環境では入力と配線を、実機では保護領域の画素一致と境界の自然さを別に確認する。

## 出力と判断

`selected.md`は仮選択4枚と本文、`all-candidates.md`は全候補、`before-after.md`は改善前後、`manifest.json`は場面・Run・画像・親画像・評価の対応を持つ。画像は既存の保存先を参照し、複製しない。最初の仮選択は`baseline-selection.md`へ保全する。

評価は既存の評価APIへ追記する。仮選択は不合格画像からも選べるが、品質の合格を意味しない。改善後が悪ければ元の候補を残す。原文、確定計画、生成履歴、既存画像は書き換えない。計画の来歴を複製しても今回のLLM呼び出しには数えない。

実機結果には対象版、条件、時間、保存枚数、全候補の問題、改善前後、停止確認を残す。4場面が揃わなければ完成と扱わない。固定素材の自動生成や任意の物語での品質は、この検証の達成範囲に含めない。
