# 評価と分析用出力の契約

## 保存

評価は版付きJSONで追記します。型の正本は[評価契約](../../src/komaquill/domain/evaluations.py)です。採否と二つの生成の選好を分け、対象、基準と版、評価者、理由、訂正元、評価時点のワークフローハッシュを保持します。

AIの評価にはモデルと指示のハッシュを必要とします。指示内容が入力された場合は内容とハッシュを一致させます。確認できないモデル版は不明とし、認証情報は契約に含めません。

## 依存境界

アプリケーションは生成履歴と評価のリポジトリ契約を使います。ファイル用アダプターが排他と原子的保存を担当します。既存の生成・画像・モデル・素材は更新しません。DBや外部の実験管理ツールは導入していません。

## 分析用出力

評価のない生成も出力できます。評価、評価用JSONスキーマ、実行グラフ、来歴、画像と入力素材の保存キーを含めます。バイナリの埋め込みや外部送信は行いません。

過去の記録にない情報は補完しません。画像の現在の観測値と保存済み情報、グラフと保存ハッシュの一致を区別します。分析するAIは画像を別途読み込み、不一致・不明・異なる基準の版を考慮します。

## 未実装

AI評価の実行、複数作品の比較集計、比較生成、改善案の自動適用、DB移行、MLflow連携は[今後の候補](../plans/future.md)です。

## 記録の整合性と部分的な出力

保存済み評価のIDはファイルの識別子と照合します。登録と一覧では破損記録を安全な保存エラーとして返し、分析用出力では正常な評価を続けてunreadable_evaluation_idsへ読めない記録を列挙します。この一覧が空でない出力を評価の全件成功として扱いません。

モデルの台帳は生成履歴が参照したSHA256だけを読みます。必要な台帳の形式が不正な場合は保存エラーとし、無関係なモデルの破損で選択した作品の分析を止めません。画像と生成履歴、後からの評価を変更する処理は行いません。
