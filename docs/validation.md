## T4での生成と回収

| 確認内容 | 結果 |
|---|---|
| CLIからプロンプトを指定して生成 | PNG、生成条件、ワークフローをローカルへ保存 |
| CLIから入力画面を開いて生成 | 画面上の画像とローカルへの自動回収を確認 |
| CLIからノード画面を開いて生成 | 画面上の画像とローカルへの自動回収を確認 |
| 同じ履歴を再回収 | 保存済み画像の重複なし |
| 所有するSSH接続を切断 | 同じT4へ再接続し、新規GPUを確保しないことを確認 |
| 生成中に通常終了 | 生成完了と画像の保存を待ち、T4の終了を確認。約23.95秒 |
| 監視プロセスを強制終了 | statusで監視停止と接続可能なT4を確認 |
| 監視停止後に強制終了 | 完了済み画像を回収し、実行中のIDを報告してT4を終了。約6.12秒 |
| 終了後にstopを再実行 | GPUの再確保なし |

時間は検証時の実測値であり、生成条件や回線によって変わります。
監視停止後の強制終了では、未回収の完了画像と300ステップの実行中要求を用意し、実行中要求の完了を待たないことを確認しました。

監視の強制終了後、GPU終了だけではローカルの公式CLI待機プロセスが残ることも確認しました。
プロジェクトの公式設定パスとセッション名を照合して親子プロセスを終了する処理を追加し、残存していた実プロセスの終了を確認しました。
別プロジェクト・別セッションを終了しないこと、終了確認に失敗した場合に管理記録を残すことをテストしています。
強制終了要求の並行更新と、終了待機中の接続入れ替わりにも回帰テストを追加しました。
