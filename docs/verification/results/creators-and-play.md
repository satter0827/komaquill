## 修正した問題

- 複数systemメッセージ、登録モデルIDの不一致、入力言語を維持する指示の競合を共通のLLM要求処理で修正した。
- 日本語会話で画像説明まで日本語になる問題を、本文と画像説明の契約、言語検査、上限付きの修正要求で修正した。
- 画像を明示指定した会話が `scene=null` で終了する問題を、明示指定時だけ画像説明を必須にする契約で修正した。
- 任意の設定に固定サンプルが人物名付きで返答する問題を、設定・入力・状態の照合と、設定未指定時の専用応答で修正した。
- 古い観測による生成操作の状態・英訳の後退、同じ操作の二重実行、古い版への画像適用を防いだ。
- 削除した既定プロフィール・相手の参照が残り、別の設定を保存できなくなる問題を、同じ削除トランザクションで解除するよう修正した。
- 画像・下書きの受付直後や応答不明時に作成ボタンが再び押せる問題を修正した。受付済みの状態を保持し、未確認の要求には同じIDと入力で再確認する。
- Windows CIで、接続確認が終わる前の保存から自動画像が作られない問題を確認した。接続結果を待ち、受付時の言語・モデル・許可を固定して画像要求を作成するよう修正した。画像の失敗で本文の保存を失敗扱いにしない。
- 保存済みの好みを読み込む前に既定の言語・モデルで操作できる問題を、共通の設定読込画面で防いだ。読込失敗時は再確認できる。
- 単発画像の実LLM許可を操作ごとに消費するよう統一した。送信前の許可不足は入力を修正でき、受付不明の通信失敗では同じIDと入力を保持する。
- Windows CIでは、回収直後の一時表示が保存済みの人物プレビューへ切り替わり、画像の検出を取りこぼすテストも確認した。保存先のプレビューと再読込後の画像の読込完了を検査するよう修正した。
- 依存検査の終了コードとキャッシュ先が無視されていた呼び出しを修正した。移行の停止確認は、venvを使うエディター支援と実際のDB使用を区別した。

## 残る品質上の課題

- 4Bは人物の名前・職業を採用した一方、舞台にない出来事や魔法を加える例があった。設定を送信する機能の確認と、設定に常に忠実な返答であることの保証は分ける。
- 会話画像には小物の重複、動作や位置のずれがある。人物画像と会話画像で同一性を保証する機構は設けていない。
- バナーの題名はReactで表示する。画像モデルが背景の看板などに不自然な文字を生成する場合があり、画像内の文字抑制は改善が必要。
- Windowsで画面と実機を確認した。ほかのOS・ブラウザーの見た目や、長期間の作品品質を一律に合格とはしていない。

精度の改善は、保持した入出力・英訳・画像を同じ条件で比較して進める。保存成功、スキーマ成功、文章の忠実度、画質を別の判定として扱う。
