## 発見した問題と修正

| 原因                                                                 | 修正と再確認                                                                                   |
| -------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------- |
| HTTPの失敗から段階が欠落し、接続確認時の拒否を受付不明と扱う         | 安全なErrorViewをOpenAPIにも定義し、下書きと行動を編集可能なまま保持する                       |
| 再開可否の確認が操作の確定処理を呼ぶ                                 | 読取り専用スナップショットを分離し、確認だけでは保存済み返答を確定しない                       |
| 初回の入力準備が既定プリセットと好みの保存を伴う                     | サービス構築と初期保存を分け、下書き・会話描画の接続確認だけでは記録を追加しない               |
| 描画の接続確認中に会話の版が進む                                     | 受付トランザクション内で対象の版を再確認し、古い場面の受付を拒否する                           |
| 遅い確認結果が別の入力や新しい接続失敗を上書きする                   | 画面では確認した要求へ結果を対応付け、サーバーでは確認の開始順を比較する                       |
| 受付不明でも描画と行動編集が操作可能になる                           | 受付を照合するまで依存する操作を止め、文章の下書きは保持する                                   |
| 返答失敗後に保存済みの発言が履歴から消える                           | 保存済み要求から発言・行動を表示し、成功ターンとの重複を除く。旧行動IDも原本を変更せず参照する |
| 受付後の接続失敗で利用可否が更新されない                             | 会話・下書き・画像の状態取得からも接続を再確認する                                             |
| 明示再開後も古い中断状態が残り、遅い失敗通知が成功を上書きする       | 再開受付時は古い観測を破棄し、完了・保存済み状態は後退させない                                 |
| 保存済み画像の取得失敗で再試行できず、ファイル表示失敗も通知されない | ローカルの再確認と同じファイルURLの再取得を分け、新しい生成を行わない                          |
| 一覧の説明とリンク、右ペインの区画が接している                       | 親のgapと子の余白を整理し、狭い画面の操作幅も確認する                                          |
| 現在設計・要件・API例に削除済みの保存時生成や独立行動APIが残る       | 現行の保存・送信契約へ更新し、関連する説明の用語と文体を揃える                                 |

問題ごとに最小再現の失敗を保存し、修正後に関連テストを再実行した。再レビューでは成功・受付前の拒否・受付不明・受付後の失敗・保存済み結果からの復旧を分けて確認した。最後の確認範囲に、未解決の再現不具合は残っていない。
