# 保存とDBの設計

## 正本の境界

| 情報 | 正本 | 更新方法 |
|---|---|---|
| 会話、確定ターン、状態、プリセット、生成要求、関連付け | SQLiteの機能別テーブル | 短いトランザクションで確定 |
| 画像、入力素材、ワークフロー、確定した画像用記述 | 内容のSHA256で識別するオブジェクト | 同一内容を再利用し、保存キーの別内容への付け替えを拒否 |
| LLMへ実際に送った要求と受信した応答 | 不変オブジェクトと追記する呼び出しの版 | 要求開始、受信、検証を別の版として保存 |
| LangGraphの実行途中と検証済み結果 | 公式SQLite saverのテーブル | ワークフローの版と実効設定を照合して再開 |
| 閲覧用ZIP、分析結果、検査証跡 | `.artifacts/outputs`と`records` | 正本から作成し、失敗を別に報告 |
| 接続、所有ID、監視、排他 | `.artifacts/state` | 作業場所とプロセスの識別情報を照合 |

構造化された会話記録はDB内で一度だけ確定します。自由形式のLLM通信記録とバイナリはオブジェクトに分離します。全JSONをファイルへ移してDBに可変の索引を重複管理する方式は採りません。

## DBの整合性

[テーブル定義](../../src/backend/src/komaquill/adapters/persistence/schema.py)を参照してください。会話に属する操作・ターン・イベント・場面には外部キーを設定し、ターンの位置と識別子、操作の占有枠、既定のプレイヤーを一意にします。JSONの識別子と行の識別子を照合し、状態と版を生成列から検査・索引化します。生成列は書き込み用の重複状態ではありません。

SQLiteの外部キーを接続ごとに有効にします。SQLAlchemyの接続を使い終えたら閉じ、Windowsで未使用の接続がDB切り替えを妨げないようにします。ネットワーク通信をDBトランザクションや回収の共通ロック内へ持ち込みません。

DBの新規作成は作業フォルダーの初期化に限定します。通常の接続は既存ファイルだけを開き、ファイルの喪失や版情報の欠損を空の作品一覧へ置き換えません。保存フォルダーが残っているのにDBがない場合も再作成を拒否します。初期化前に用意した設定ファイルは保持します。SQLAlchemyと公式SQLite saverの全接続で同じ共有リースを保持し、接続が閉じるまで移行の排他リースを取得できないようにします。

## オブジェクトの確定

保存キーは論理的な識別子です。物理パスへの解決は保存アダプターへ限定します。内容を一時ファイルへ書き、ハッシュとサイズを確認してから公開し、その後にDBの参照を確定します。途中停止で未参照のファイルが残っても、存在しないファイルを保存済みとして参照しません。画像一件ごとに確定し、必要な画像が揃ってからsavedへ進めます。

既存オブジェクトの破損は検出します。回収で同一ハッシュの原本を再取得できた場合は、破損ファイルを`data/quarantine`へ保全して復元します。異なる内容を元の保存キーへ書きません。未参照オブジェクトや隔離ファイルは自動削除しません。

## LLMの記録と予算

モデル、設定・指示の識別情報、実際のメッセージ、構造化スキーマ、使用量、不明値、検証結果を保存します。資格情報とHTTPヘッダーは保存しません。応答の内容と使用量は受信後に変更せず、検証の訂正を追記します。使用量集計は呼び出しの最新の版から導出します。

明示した呼び出し予算は送信前に予約し、中断しても消費を戻しません。再起動で期限と回数をリセットしません。開始だけが残る要求は受付不明として扱い、自動再送や別モデルへの切り替えを行いません。

予算の新規作成と保存済み予算の再接続を分けます。接続済み台帳のファイルや行が失われた場合は保存失敗とし、同じ上限を再指定しても回数や期限を復活させません。接続情報は型と範囲を検証してから使用します。応答へ検証結果を追記するときも、前の応答のハッシュとサイズを照合します。

## 一度だけの変換

公開APIの`Client.migrate()`で明示的に変換します。監視・DB利用・実行中の要求が残っている場合は開始しません。変換前にSQLite backupとファイル一覧・SHA256を保存し、別のDBで変換・参照検査・原本照合を完了してから切り替えます。既存の作品、固定条件、過去の不明値を推測で書き換えません。通常の読み込みには旧パスへのフォールバックを置きません。

過去のアーカイブ形式は閲覧専用の境界で扱います。履歴の喪失や破損を未送信と推測しません。変換結果と元DBは非公開の`records/migrations`へ残します。

アーカイブ済み会話に属する過去の操作は`archived_operations`へ保全します。親のない現行操作を作ったり、元の要求・応答を補完したりしません。移行のDDLは版ごとに固定し、現在のテーブル定義や業務モデルの変更で過去の変換結果を変えません。DBの利用には共有ロック、切り替えには排他ロックを使用し、変換中の新規接続も防ぎます。
