対象: REQ-CONVERSATION-ALBUM-UX、REQ-PLAYER-ACTIONS、REQ-WEB-ACCESSIBILITY。

## 対象と方法

2026年11月5日、Windows、Node v24.15.0で確認した。対象はPR #44の14c704747be5b3d19340b0a8b6a177fc89899c1aと、その後の修正である。承認済み計画、要件台帳、現在設計、コード、今回取得した画面と通信を照合した。過去の成功件数を今回の検査成功として数えない。

ブラウザーは隔離した作業フォルダーとlocalhostの固定応答LLM・ComfyUI擬似境界を使った。私的な本文・画像は使わず、API・モデル・保存形式は変更していない。

## 発見と修正

| 問題                               | 原因と修正                                                                                                                 | 再確認                                                                                                                                                      |
| ---------------------------------- | -------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 受付確認で生成を再送する           | 会話と作成処理の「送信結果を確認」が送信関数を呼んでいた。同じIDのGETだけへ変更した                                        | 修正前は3件のReact検査がPOST 2回を検出。修正後は1回のPOSTと同じIDの照会、入力・行動の保持を確認                                                             |
| 画像失敗の復旧操作が隠れる         | 画像用の固定比率と高さをエラー説明にも適用していた。失敗時は説明と操作に応じた高さへ変更し、会話バナーも共通部品へ統一した | 修正前は再試行ボタンが枠より約110px下へはみ出した。修正後は人物・ストーリーのカードと編集画面、会話バナーで操作が枠内に収まり、クリックでファイル表示を復旧 |
| 保存の再実行と受付確認の文言が同じ | ローカル保存の再実行にも受付確認の文言を流用していた。「保存を再試行」と分け、既存の同じ操作IDによる保存を維持した         | メモ、人物・ストーリー、外見確認を横断して確認                                                                                                              |
| 状況の見出しが重複する             | 装飾用の見出しと主見出しに同じ内容を表示していた。主見出しへ統一した                                                       | 会話の画面とReact検査で1件の表示を確認                                                                                                                      |

修正後に再度、要件から画像の更新・監視・復旧を照合した。失敗した画像IDが別のIDへ変わる場合も新しい画像を表示でき、過去の失敗で更新を止めない回帰テストを追加した。監視範囲、終端状態と部分画像の保持、受付IDの照合、原画像リンク、下書きの版と人物・持ち物の識別子は維持する。
