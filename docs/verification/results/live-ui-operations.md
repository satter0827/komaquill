## 発見した原因と修正

人物の固定情報と現在状態が別の役割名へ分散し、行動にも未指定のnull項目が含まれていた。人物ごとに名前・固定情報・服装・持ち物・場所をまとめ、確定済みの行動には行為者と指定した項目だけを付ける。相手の服装や持ち物を変えるものではないことを送信Schemaと指示にも示した。保存済みの原文や過去の要求は変更しない。

応答Schemaを入れ子へ変更した後も、言語指定の処理は最上位の項目だけを対象にしていた。台詞・動作・場面変更の定義にも同じ言語指定を適用し、人物名や服装の原文へ翻訳指示を加えない。所有物の制約違反には安全な項目パスを付け、有限修正が尽きた失敗段階はresponse_validationとする。

HTTPのバックグラウンド実行から既知の保存失敗が伝播すると、送信済みの受付応答に対してエラー処理が再実行され、接続が壊れていた。会話・再開・下書き・描画で同じ境界を使い、保持した操作とチェックポイントを状態照会で復旧する。未知の例外の抑制、推論の自動再送、行動の再適用は追加していない。以前記録した単発のGET切断との因果関係は確認できていないため、同じ原因だったとは断定しない。

標準トリマーは空履歴やsystemだけの候補を計数するが、LM Studioのテンプレートはその入力を拒否した。空履歴はゼロとし、systemだけの候補は計数専用の空のuserターンを添えて保守的に数える。送信する完全な履歴と、最終確認の実測値は変更しない。下書き、画像用前処理、長い履歴の選択へ同じ修正を適用した。

基点の二人画像では、第三の人物が現れる、二人に同じ服装が混ざる、主観なのに自分の顔が見える、封筒が白くなる問題を確認した。服装解除では指定していないエプロンとシャツが現れた。風景2枚は人物ゼロだが、棚の内容や店舗の描写まで正確という判定には進めない。
