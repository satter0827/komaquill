# Klein・WAIの固定条件比較

## 対象

同じ原文・確定計画・seedでKlein 4BとWAI Illustriousを比較します。8題材の構造検証を維持し、実機の対象と予算は[検証用設定](../../tests/fixtures/klein-comparison/config.toml)を正本とします。9Bの取得・実生成、新しい計画LLM呼び出し、二段階生成は実施しません。

## 準備と再開

[仕様データ](../../tests/fixtures/klein-comparison/specifications.json)を原文と照合してから、`python -m tests.live.klein_comparison prepare REPORT --source PARENTS_WORKSPACE --parents PARENTS_JSON`で計画・要求・親画像を固定します。親のJSONには場面、保存キー、SHA256、編集指示を記録します。Fakeの理解結果や実LLMの成功として扱いません。

`start REPORT --gpu T4`で選択資源をColabへ直接取得します。PCでは認証・取得権限・固定版を確認し、重みを保存しません。資格情報は所有IDとGPUコードを照合したSSHの標準入力だけで渡します。[モデル準備](../guides/preparation.md)に手順と制約を記載します。

生成は`generate REPORT --group baseline --model wai-illustrious`などで実行します。`edit`と`ablation`も同じ補助を使います。画像を追加送信する前に保存済みIDを照合し、受付不明は再送しません。再開は元の入力・条件・使用済み時間・CU・枚数を引き継ぎます。

実行版を修正して再開するときは、理由、内容ハッシュ、承認済みセッション数を追記の実行版記録へ保存します。元のcomparison.json、計画、生成入力、予算は変更しません。既存の作業別プリセット一式を保持すると、パッケージ更新後も同じグラフを再現できます。

終了は`stop REPORT`を使います。停止は検証補助の対象版が変わっていても利用でき、プロバイダーの停止確認と所有解放を記録します。

## 標準画面

`export-ui REPORT --job JOB --view app`または`--view graph`で既定の画像枠を予約し、標準JSONを読み込みます。実行後の`adopt-ui REPORT --job JOB`は実行グラフと素材ハッシュが一致する一件だけを関連付けます。UI確認のために別の画像予算を追加しません。

キューが空であることを確認してから、標準のモデル・実行キャッシュ解放を使ってモデルを切り替えます。画面の編集値と、実行して保存された値を区別します。

## 評価

Codexが実画像を確認し、原文一致、人数、所有者、小物、身体、外見、連続性、編集対象以外の条件を評価します。条件ID、由来、根拠、画像ハッシュ、評価者、モデル、指示ハッシュを保存します。評価APIや追加LLM呼び出しを記録操作へ混在させません。

期待条件は題材ごとの確定場面と照合します。条件の転記ミスは、元の条件ハッシュと比較IDを示す訂正記録へ分け、元の計画・画像・条件ファイルを変更しません。訂正後の場面・原文・演出条件が一致しない記録は評価へ使いません。

`reviews REPORT --review-file FILE`で追記し、`summarize REPORT`で保存・選択・採否・比較・未実施を集計します。局所評価を場面や作品の合格へ広げず、判断不能は合格に含めません。選択不能では前の有効選択、初回は有効画像の生成順を使います。必要な全画像が揃った作品だけをPNG・PDFへ組版し、欠損を仮画像で埋めません。

初回ロード、生成、回収、CUを分けて記録します。ブラウザーで初めて観測したRunの時刻から、送信時刻やキュー待ちを推測しません。少数例と単一seedからモデル全体の優劣や安定性を断定しません。
