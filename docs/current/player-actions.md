# 自分の行動と現在の場面

対象: REQ-PLAYER-ACTIONS、REQ-CHAT-STATE、REQ-CHAT-COMMAND、REQ-IMAGE-TRANSLATION、REQ-CREATOR-ACCEPTANCE。

## 確定するもの

人物の名前、年齢、性別、身体的な特徴と、開始時の服装・持ち物を分ける。会話開始後の服装、姿勢、表情、持ち物は現在状態として保存する。現在地は二人で共有し、物語の目的と自分の今の目標も区別する。

送信欄の「場所を変える」で行き先を入力し、「送信」で発言と一緒に確定する。行動だけの送信もできる。「その他の行動」は待機、服装、姿勢、表情、持ち物、今の目標を扱う。主人公とキャラクターは常に同じ場所にいて、移動に同行する。人物別の服装・持ち物と固定した人物設定は混同しない。

待機は経過した分数を加算する。時刻の基準がない設定で、時計や昼夜を推測して変更しない。移動時は直前の場所の描写を解除し、新しい場所の情報を使う。

## 保存と再確認

公開APIのconversations.accept/sendとHTTPのturnsへ、発言、任意の型付き行動・提案ID、期待する版、操作IDを渡す。接続確認はトランザクションの外で行い、行動の保存と発言・返答処理の受付を同じ短いトランザクションで確定する。返答操作は送信と同じIDの一件とし、通信はその外で行う。独立した行動実行APIは提供しない。失敗した返答のために行動を再実行しない。

同じID・内容の再確認は保存済みの結果を返す。別の会話や用途へのIDの再利用、内容違い、古い版の行動は拒否する。状態が進んだ行動案は失効する。受付応答が失われた場合は保存済みの行動を取得し、自動再送しない。

送信の生成言語を省略したPython API要求は、会話の開始言語を使い、受付時に返答の要求へ固定する。画面では選択中の表示言語を明示して渡す。現在地が未指定のときは場面の場所を使う。人物別の現在地は公開入力に持たない。

実行中かどうかはPIDと開始時刻に加え、操作単位のFileLockで判定する。通信中はこの実行ロックを保持し、共通のDBトランザクションは保持しない。実行ロックが解放された処理は、サーバープロセスが生存していても復旧対象になる。保存済みの返答があればそれを確定し、なければ受付不明の中断として記録する。どちらもLLMを再送しない。下書き作成と画像受付も同じ実行ロックを使い、画像Runの回収は独立して継続する。

返答が更新できるのは相手と周囲の許可された項目だけである。自分の状態、現在地、物語の目的、固定した外見を変更する応答は採用しない。応答のチェックポイントは未指定の差分を省略して保存し、再開時に解除へ変わることを防ぐ。

生成応答は即時移動の判定と返答を別の必須項目として返す。質問を含む入力でも移動の判定を省略しない。返答には自分の他の行動案、現在状態、相手の動作、台詞を含める。現在状態に人物の変化がない動作文は表示しない。背景説明を別の自由文として二重生成せず、現在状態のsceneryを会話本文へ表示する。説明が空の場合は保存済みの場所を表示する。行動案がある応答は、確認前の台詞・背景・状態変更を公開しない。自然文の即時移動は解釈を保存してから一度だけ適用し、移動後の返答まで同じ操作・会話ターンで保存する。解釈だけの空のターンを公開しない。質問、条件付きの相談、将来の予定は移動として確定しない。

右ペインを閉じたり画面幅を変えたりしても、編集中の内容、基準となる版、受付確認中の操作IDは保持する。確定・見送り・外見確認の応答が失われた場合は保存された履歴から確認する。受付が不明な間は新しい発言と描画を止める。

自分とキャラクターの持ち物欄は、編集時には改行を含む文字列を保持し、保存時に識別子と表示名を持つ物理的な物の一覧へ変換する。同じ名前の別の物を区別し、同一の識別子を二人で保持しない。約束や知識は固定メモと原文を引用する記憶で扱う。既存の持ち物と下書きの持ち物も同じ欄へ復元する。開始時の服装は、未指定のnullと明示的な解除の空文字を、入力・変更検知・画像説明まで区別して保持する。

持ち物の生成応答は、相手が実際に拾う・手放す・受け渡す物理動作を行い、その動作を説明している場合に限定する。変更後の一覧は他の持ち物を維持し、情報や過去の質問に答えるだけの入力で以前の一覧を復元しない。合言葉や題名を物体として扱わず、所持していない人物からの受け渡しを作らない。この意味上の条件は型だけでは保証できないため、固定入力の実モデル検証でも確認する。

## 画像と視点

会話のLLM入力では、自分と相手の名前・固定情報・現在の服装・持ち物・場所を、それぞれ一つの人物レコードへまとめる。確定した行動は行為者と指定された項目だけを付けて渡す。未指定の項目を解除として送らず、古い服装を重複する人物定義から復元しない。応答の台詞・動作・場面変更には、入れ子の送信Schemaでも生成言語を指定する。名前と保存済み原文の翻訳は要求しない。

所有物の重複を検出した修正要求には、問題の項目のパスと制約を渡す。例外本文や値の転載は行わない。構造化された持ち物の整合を検査しても、自由な動作文の所有関係まで保証できるわけではない。実出力の意味は[固定評価ケース](../verification/conversation-quality.md)で確認する。

画像へ渡すのは解決済みの身体的特徴、現在の服装・姿勢・持ち物、場所・時間・周囲の様子である。服装が解除された場合に、古い服装を人物の紹介文から復元しない。風景を選択した場合だけ人物を除く。画像の操作へ受付時の状態・版・英語入力を固定する。

単発画像の忠実な英訳と、場面の画像説明の作成を分ける。翻訳の確認が必要な場合や処理不能の場合は、別の画像説明へ置換して送信しない。型と言語の検査は意味や画質の保証ではなく、実出力の対応は別に確認する。代表画像は人物紹介用であり、現在の場面や顔の固定を保証しない。

人物紹介と会話画像は、解決済みの項目を自由な場面文章へ書き直さない。英語の値と数値の年齢はそのまま保持し、日本語の値だけを必須キー付きの一回の要求で英訳する。姿勢がある場合は全身を示す構図を使う。風景のみの送信には、人物を除く正負の条件とバナー用の寸法設定を適用する。単発画像とストーリーバナーの自由文は、それぞれ忠実な英訳と環境の抽出を使う。

## 旧データの確認

停止とバックアップを伴う明示移行で、元の会話・プリセットのJSONを別表に保持する。画像、本文、過去の状態は推測で書き換えない。外見の分離が必要な人物には確認待ちの印を付け、履歴の閲覧は維持する。

画面から身体的特徴、開始時の服装、現在の服装を確認する。確認結果は操作IDと新しい版で保存し、確認後に新しい生成を再開する。後のプリセット編集を既存会話へ反映しない。

確認対象は印のある人物だけとし、確認済みの人物の固定情報と現在状態は更新しない。服装は未指定のnullと、明示的な解除の空文字を区別する。自分か相手のどちらかが未確認なら、画面と公開APIの両方で新しい会話・行動・描画を止める。確認によって版が進んだ行動案は失効する。

旧要約は原本として退避し、新しい記憶は発言・台詞・環境・動作・確定した行動から原文を選ぶ。現在状態は別に渡す。引用の出典と保存済み範囲のハッシュを照合し、新しい型で過去のハッシュを書き換えない。現在の契約は[原文を根拠にした会話](../decisions/0018-source-backed-conversation.md)を参照する。

公式チェックポイント、NSFW、二人の描画、場面の分岐は[実行とコンテンツ設定](execution-and-content.md)を参照する。

## 移動の復旧と記録

自然文の解釈と移動後の返答には別のチェックポイントと呼び出し記録を使う。移動の確定と受付操作の基準版更新は同じ短いトランザクションで行う。受付原文と要求のフィンガープリントは変更しない。返答が失敗しても移動を戻さず、同じ操作IDで再確認しても重複適用しない。保存済みの呼び出しは再利用し、未送信の後段だけを明示的な再開で実行する。受付不明の呼び出しは再送しない。

旧形式の人物別の現在地は保存アダプターで読み取り、新しい公開状態へ持ち込まない。過去の本文、確定行動、ターンの状態、履歴ハッシュは原本のまま保持する。実行中の旧チェックポイントは版不一致として停止し、旧処理へ戻さない。設計理由は[共有する現在地](../decisions/0023-shared-location-and-verification-retention.md)を参照する。

操作のresume_countは、受理した再開の回数を表す。最初は0とし、再開の受理と同じトランザクションで増やす。重複拒否と完了済みの再確認では増やさない。画面は同じ操作IDでも新しい回数の観測を優先し、その回数内で終端状態を維持する。再開前の中断や完了応答が遅れて届いても、新しい状態へ戻さない。

再開の送信前から同じ操作IDを照会する。受付応答が途切れた場合は「送信結果を確認」でGETだけを行い、受理済みと分かれば監視を継続する。新しい受理回数か、現在も再開可能な中断であることを取得するまで新規送信を止め、下書きを維持する。中断を確認できた場合は利用者が同じ操作を明示的に再開できる。GETが失敗しても確認操作を残し、POSTを自動再送しない。再開の遅い受付応答で、後から送った別の操作の監視へ戻らない。
