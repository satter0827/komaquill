# ワークフローのモデルを準備する

## 利用条件

Komaquillで起動したComfyUIには、モデル準備用の画面拡張を同梱しています。計算には標準ノードを使用します。Node Graphの編集機能はそのまま利用できます。

自動準備の対象は、導入済みの標準ノードで動作する画像生成ワークフローです。テンプレートのモデル情報にある名前、用途、取得元を使い、公開Hugging FaceまたはCivitaiのモデルを照合します。追加取得できる形式は.safetensorsと.sftです。取得元とSHA256を固定できないモデル、認証が必要なモデル、追加ノード、動画・音声は手動準備が必要です。同梱する生成・編集セットの資源はモデル定義へ固定しています。

## 画面で準備する

1. startで起動し、標準のテンプレートまたはワークフローを読み込みます。
2. 不足モデルの案内、またはNode Graph上部のPrepare Workflowを選びます。
3. モデル名、容量、取得元、ローカルで再利用できるファイルを確認します。容量を取得できない場合はUnknown sizeと表示します。
4. 確認すると、ローカルへの保存とGPU側の準備が進みます。両方のSHA256が一致するまで準備完了とは扱いません。

途中で中止する場合は、Prepare Workflowの隣にある停止ボタン（Cancel Preparation）を選びます。再試行はPrepare Workflowから行います。ワークフローに取得先がない場合は、配布元でモデルと利用条件を確認してください。自動導入のために追加ノードをインストールすることはありません。

## CLIで準備する

```powershell
komaquill prepare ./workflow.json
```

起動済みのセッションを使用し、GPUを新しく確保しません。確認後に取得を始めます。Ctrl+Cで取消を要求し、部分ファイルを次の取得で利用します。

## 保存と再利用

モデルは.artifacts/data/models/用途/SHA256/ファイル名へ保存します。asset.jsonに固定した取得元、用途、容量、検証済みファイルの情報を記録します。同名でも内容が異なるモデルを区別し、ComfyUIからはSHA256/ファイル名で参照します。テンプレートの取得元をノードごとに照合するため、同名の別モデルを一つへまとめません。同じノード内で名前だけでは区別できない指定は、不足内容として案内します。

GPU側は同じ固定配布元から直接取得します。ローカルにしかない登録済みモデルはストリーミング転送します。既存ファイルは検証情報と一致すれば再利用します。明示的なハッシュ検証が必要な場合はファイル全体を読み直します。取得途中の切断では部分ファイルを残し、配布元がRangeに対応する場合に再開します。ハッシュ不一致のファイルは公開しません。

取得は画像回収と別の処理で行います。stopは新しい準備を受け付けず、進行中のモデル取得へ取消を要求します。停止後に必要なモデルを再度準備してください。

拡張のない外部ComfyUIでは、標準APIによる生成と回収を利用できます。prepareは拡張が必要であることを案内します。外部サーバーの停止は行いません。

## 別のComfyUIへ拡張を導入する

ComfyUIと同じPython環境へKomaquillとaiohttpを導入し、custom_nodes/komaquill/__init__.pyでNODE_CLASS_MAPPINGSを空の辞書、WEB_DIRECTORYをパッケージのinterfaces/comfyui/webへ設定します。起動前に`komaquill.interfaces.comfyui.api.register(PromptServer.instance, 保存用一時フォルダー, 通信待機秒数)`を呼び出します。registerは標準のモデル検索パスとAPIを登録します。Colabの操作やアカウント情報は不要です。保存用一時フォルダーには、そのComfyUIが書き込める専用パスを指定してください。

その後、PCで`start --backend external --endpoint URL`を実行します。1つのComfyUIへ同時に接続できる作業フォルダーは1つです。接続の制御情報はOSの資格情報ストアへ保存し、画面側から保存確認を偽装できないようにします。

## 標準Klein構成を準備する

モデルの固定版と利用条件は[モデル定義](../../src/komaquill/resources/models/)を確認します。指定のエンコーダーは配布ページでのアクセス許可が必要です。通常の端末でHugging Faceへログインし、必要な利用条件へ同意してからstartしてください。資格情報を設定ファイルやチャットへ貼らないでください。

認証を要するLoRAを手動取得する場合は、モデル定義のSHA256と一致するファイルを`.artifacts/data/models/用途/SHA256/ファイル名`へ配置します。ファイルの内容で識別するため、別版を同じ場所へ上書きしないでください。起動時に全資源を照合し、失敗した場合はGPUを確保しません。

`transfer`で指定した資源は既存の公式SSHアダプターを使うOpenSSH scpで転送します。`scp -X`に対応するOpenSSHを使用してください。GPU側でも照合してから生成へ使用します。認証情報は転送しません。転送の途中失敗では不完全なファイルをモデルとして登録しません。
