## 原因修正と再現方法

| 問題 | 切り分けと対応 | 確認・限界 |
|---|---|---|
| 起動SSHの失敗 | 長時間の起動処理と次の接続を分離。認証情報の受け渡しを短いSSHで完了してから転送接続を開始 | 契約・失敗注入と3回目の実機起動を確認。プロバイダー内部の拒否理由は未確定 |
| 大きな取得の中断 | 同じ固定ファイルの部分取得を、回数・取消・期限で制限して回復。認証エラーと不正ハッシュは自動代替しない | localhostで途中切断・Range再開・SHA256一致を再現。実機は全資源取得成功。先行失敗のHTTP詳細は不明 |
| 初発理由の消失 | GPU進捗の最初の失敗を保持し、外側の汎用エラーで置換しない。準備期限は専用コードを使う | HTTP失敗後の外側失敗・成功通知と、期限超過を回帰検証 |
| 未作成ログの誤報 | 起動の到達段階と過去の取得成功から必要なログを判定 | 起動段階・欠損・取得失敗を分けて検証。終了時のログ回収は成功 |
| App Modeの画像不足 | 拡張子のない保存キー名が転送名へ混ざり、標準画像一覧から外れることを再現。新規素材形式3で実画像形式の拡張子をGPU参照名へ付与 | PNG名での実編集と、新形式の標準LoadImage一覧登録を確認。形式1・2の値と参照名は維持 |
| 題材の期待条件の取り違え | 期待条件の組み立てで最後の題材の変数を参照していた。各題材の場面から条件を作り、全題材の対応を検査 | 元の計画・生成入力は正しかった。comparison.jsonは変更せず、誤条件を追記の訂正へ分離して全17枚を評価 |
| 未対応モデル入力の分類 | 参照素材と画面操作でモデル解決のValueErrorが汎用エラーになることを再現。両経路を公開APIと同じ型付き設定エラーへ統一 | 未対応・未有効モデルをファイル取り込み・送信前に拒否する回帰検証 |
| 条件IDと表題の不統一 | 分析用IDの二重接頭辞を除去し、漫画表題を原文の題名へ統一 | 条件IDの対応を回帰検証し、四作品を再組版 |
