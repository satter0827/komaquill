# LangGraph移行と会話・画像の整合性

対象: REQ-CHAT-WORKFLOW、REQ-CHAT-STATE、REQ-CHAT-PROCESSING、REQ-IMAGE-TRANSLATION、REQ-CHARACTER-PRESETS、REQ-PLAY-EXPERIENCE。

## 旧実装の扱い

旧作業ブランチの会話ワークフローはローカルコミット `ae1c726572786de7aac7e2c6b73a90bfd480a5f7` に保全した。旧ディレクトリ構成、公開API、DB形式、会話ごとの自動画像生成を前提とするため、現在のmainへ一括マージしない。React、個人設定、プリセット、日本語・英語、専用ボタンによる描画を維持し、必要な考え方と回帰条件を現在の契約へ移す。

旧実装から再利用するのは、SDKをアダプターへ限定する配置、型付き状態、有限の修正、実行段階の分離、モデル呼び出しと保存の照合、復旧検査の観点である。DirectorとResponderの常時二段呼び出し、会話ごとの投機的画像生成、画像の自動比較・抽選、旧DBの再初期化は取り込まない。

## 実装済みの移行範囲

構造化LLM要求を、LangGraphの `request → validate → complete / repair → request` で実行する。会話、下書き、画像用英語の作成は同じ要求処理を使う。既存のモデル接続には `langchain-openai`、標準メッセージには `langchain-core` を使い、実行順序と分岐をLangGraphが担当する。LangChain全体を新たに導入しない。

履歴は `trim_messages` で整理し、system、最新の発言、完全な直近の会話の組を保持する。現在の上限は文字数であり、トークン数と読み替えない。確定設定や最新の発言だけで上限を超える場合は、削除して送信せず失敗を返す。

通信失敗、モデルID不一致、拒否応答は修正ループへ入れない。型・言語の不正だけを既存の修正上限内で処理する。SDKとグラフの自動再試行、モデル切替、外部トレース、ノード結果のキャッシュを使わない。グラフ全体のトレースを無効にし、呼び出し記録へ実行基盤の識別を残す。

保存・操作ID・排他・応答チェックポイントは既存のSQLite処理を正本とする。グラフ内の状態は一回の要求だけを扱い、別のDBへ会話本文を二重保存しない。新しいグラフ単体でプロセス中断後のノード再開を提供するものではない。受付不明を再送しない既存の会話・画像の復旧契約を維持する。

## 次の実装順序と受入条件

| 順序 | 対象 | 変更と受入条件 |
|---|---|---|
| 1 | 最新発言と現在状態 | 開始設定、直前場面、今回の発言の役割を分ける。利用者による現在地の訂正が台詞・場面説明・状態へ一致して反映され、以前の用事を繰り返さないことを実モデルで確認する |
| 2 | 人物と持ち物 | Pydanticで人物ごとの服装・姿勢・所持品を扱う。省略と明示解除を区別し、状態の全置換による脱落を防ぐ。描画対象と画面外の自分を分け、英訳でも持ち主を維持する |
| 3 | 編集と画像生成 | 入力の保存成功後に返された版で画像を生成する。保存前の画面入力と別の設定で生成しない。年齢・性別を含め、入力、原文、英訳、実画像を照合する |
| 4 | 画像操作の競合と回収 | 同じ対象・版・用途の進行中操作をDBの制約と短いトランザクションで再利用する。新しい失敗操作で正常な画像の適用を妨げない。画面を閉じても保存済み画像の照合・適用を復旧できるようにする |
| 5 | 表示と操作 | 代表画像と進捗の表示元を一つずつにする。カードへ保存済みの立場と紹介・性格を表示する。描画を送信の隣の独立したアイコン操作にし、読み上げ名・ツールチップ・生成中表示を付ける |
| 6 | 長期会話 | 直近履歴と現在状態だけでは足りない実例を測定する。必要な場合に古い確定履歴を要約し、対象範囲・版・原文参照を保存する。最新の発言、人物の識別、所有関係、未確定の操作は要約で置き換えない |

状態の型や保存形式を変える段階では、公開API・HTTP契約・React・要件・移行手順を同じ変更で更新する。既存DBへの適用は停止確認とバックアップを行い、既存の本文・画像・評価を推測変換しない。

## 標準機能の採用方針

| 機能 | 方針 | 採用条件 |
|---|---|---|
| LangGraph StateGraph | 採用済み | 小さな固定グラフで呼び出し・検証・修正を明示する |
| LangChain trim_messages | 採用済み | 既存の文字数上限を維持し、メッセージの途中や会話の片側で切らない |
| Pydantic | 継続採用 | 人物別状態と更新の契約に使い、語句の禁止や全文一致で品質を判定しない |
| SQLAlchemy・Alembic | 継続採用 | 操作の一意性と版の競合をDBで保証し、通信中はトランザクションを保持しない |
| LangGraph SqliteSaver | 必要時に検討 | 複数ノードの中断再開が必要になった場合に限る。チェックポイントは実行位置と正本への参照を持ち、業務状態を二重保存しない。再実行されるノードの副作用を操作IDで照合する |
| 標準の要約機能 | 長期会話で比較後に選定 | モデル呼び出しの増加、要約誤り、訂正・再開時の扱いを記録する。LangChainのSummarizationMiddlewareはagent向けのため、現在の固定グラフへそのまま差し込める前提にしない |

ベクトルDB、検索基盤、汎用agent、自動モデル切替、自動リトライは今回の問題を解くためには追加しない。モデルを替えるだけで状態や所有関係の不整合が直るとは扱わない。

## 検証と完了条件

自動検査は、グラフの有限実行、言語修正、通信失敗、中断・再開、二重要求、対象版の競合、画像の回収・適用を機能別に行う。確定した期待結果はtests、主観的な収集・比較はscriptsへ置き、収集処理も検査する。

実機では、許可したローカルLLMとWAIを基準にする。旧Klein画像の成功をWAIの証拠へ読み替えない。場所の移動、話題変更、服の所有者、年齢・性別、短髪と姿勢について、保存入力・送信メッセージ・応答・英訳・画像を同じ操作で照合する。少数の比較から全体の改善率を算出しない。

今回実装したグラフへの移行と、これから行う意味・画質の改善は別の完了判定にする。保存成功、JSON適合、言語適合、会話の関連性、画像の指定遵守を区別して報告する。
