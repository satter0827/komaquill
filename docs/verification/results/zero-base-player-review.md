# 行動・外見確認・保存復旧の再レビュー

実施日: 2026-11-02。基準はmainのa5db5af147c7e5312fbe28596cb6c175656e636e。対象はREQ-PLAYER-ACTIONS、REQ-CHAT-PROCESSING、REQ-CHAT-STATE、REQ-IMAGE-TRANSLATION、REQ-CREATOR-ACCEPTANCE、REQ-LLM-EFFICIENCY。今回の変更はcodex/review-player-actionsで扱う。

## 確認した問題と修正

外見確認の要求が自分と相手の両方を必須にしていたため、一方だけの確認でも確認済みの別の人物を変更できた。確認印のある人物だけを要求・表示・更新し、他の人物を含む要求は拒否する。未指定の服装を空文字へ変えていた入力処理も修正した。自分が画面外の場合や相手が不在の場合に、描画APIだけが未確認の外見を通せる経路は共通の確認処理へ揃えた。

行動の生成言語が日本語を既定としていたため、英語の会話へ公開Python APIから行動すると日本語の返答になった。省略時は会話の言語を継承して受付時に固定する。開始状態で明示した相手の不明な現在地を、自分の場所で補っていた処理も修正した。

会話・下書きの結果保存に失敗すると、実行が終了していても生きているサーバープロセスを根拠に処理中のまま残った。操作単位のFileLockで実行の生存を判定し、返答のチェックポイントがあれば追加送信なしで確定する。ない場合は中断として記録する。実行中の処理を再確認で奪わないことも並行テストで確認する。保存済みRunからの画像回収は既存処理を維持する。

画面で行動の種類や身支度の項目を変えて入力を破棄した後も、古い版を使う入力管理を修正した。編集中の入力を保持する場合は古い版のまま競合を検出し、新しい入力では現在の版を使う。送信が外見の確認待ちで拒否された場合は、受付不明として扱わず、入力を残して確認画面を再取得する。

仕様の入口でReact移行を未実装とし、旧Storyの新規生成を現在の提供範囲としていた文書を修正した。現在の会話・プリセット・APIと、既存作品の読取り、未達の生成品質を分けて説明する。

## 検証方法と証跡

Windowsのローカル環境でFake、SQLite、localhostの擬似APIを使う。新しい回帰テストの初回は7件が失敗し、修正後の関連Pythonテストは86件が成功した。追加した並行下書き・不在人物の描画検査と、全体の検査結果は今回の品質ゲートの記録で区別する。Reactはlint・formatter・型検査と41件のテストが成功した。

画面E2Eには日本語・英語で、確認が必要な人物だけの入力、キーボードからの確定、会話入力の保持、服装の未指定保持、再読込みを追加する。期待値のある検査はtestsに置き、既存の収集処理で画面・DOM・通信・manifestを対応付ける。検証対象の内容ハッシュ、環境、各検査の結果は非公開の`.artifacts/records/reports`に保存する。

修正した実装とAPI契約を対象とするpnpm check:ciが成功した。Pythonは1,094件成功・2件スキップ、行92.54%・分岐81.95%で既存基準を維持した。画面E2Eは32件成功し、配布物の内容検査と導入したwheelの検査も成功した。スキップはWindows環境で対象外となるLinuxの仮想環境プロセス検査であり、実施済みとしない。仕様文書の追加修正後の対象版は、全体検査の内容ハッシュで区別する。

実データのDB移行や、既存の作品・画像・履歴の書換えは行わない。新しい実LLM・WAI要求も送っていない。先行する実4Bの30回とWAIの6枚は[実機の記録](player-actions-and-scenes.md)として確認し、今回のコードで生成した結果とは扱わない。

## 達成範囲と残存課題

作成、保存、プリセット選択、会話、本人の行動確定、専用ボタンからの描画、再開は実装されている。今回の修正は、人物の設定保持、言語、保存失敗からの復旧を対象とする。新しい保存形式や互換用の別名は追加していない。

実4Bでは自然文の行動案を抽出しない、移動後に以前の場所を描写する、服の持ち主を取り違える、要約後の重要事項を取り出せない例が残る。WAIでは年齢・性別・人数の遵守が不十分な例がある。これらは今回のFake検査で解消したとは判定しない。会話全体のトークン削減率も未確認であり、REQ-CREATOR-ACCEPTANCEとREQ-LLM-EFFICIENCYは継続中とする。
