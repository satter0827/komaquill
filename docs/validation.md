# 検証手順

## 対応環境

Windows x64とARM64でPowerShell 7を使用します。ARM64ではx64 Pythonを使用します。CIはWindowsとLinuxで実行します。
ColabのGPUはT4、モデルはSD 1.5 FP16です。Python、公式Colab CLI、ComfyUI、フロントエンドはリポジトリの固定値を使用します。
外部接続にはComfyUI標準API、モデル、必要な標準ノードが必要です。

## 自動検査

環境を有効にし、次を実行します。

```powershell
python scripts/check.py
python scripts/security.py
uv build --out-dir .artifacts/dist
python scripts/check_package.py
```

すべて終了コード0で完了することを確認します。検査結果は`.artifacts/reports/quality/`、テスト用の一時ファイルは`.artifacts/tests/tmp/`へ保存します。

| 対象 | 確認内容 |
|---|---|
| 要求と回収 | 受付不明の照合、部分取得の再開、不正な応答・読めない履歴が混在する場合の回収継続、重複防止 |
| 画面の要求 | キュー上の条件保存、同じIDでの完了画像の保存 |
| 終了 | 通常・強制終了、監視停止後の復旧、再接続・表示・回収の異常時もGPU終了を試行、所有記録の保持 |
| ログ | 個別取得、既存ファイルの保全、秘密情報の除外 |
| 外部接続 | 接続前の画像の除外、未回収要求の再照合、外部サーバーの継続 |
| 構造と保存先 | 依存の4契約、.artifactsへの統一、Gitと配布物からの除外 |

## Colabと画面の実機検証

GPUを消費するため、自動テストとは分けて実施します。Google認証は本人が端末で行います。

1. 公式CLIや転送経路を変更した場合は、CPUで作成、コード実行、ファイル往復転送、同じSSH接続上のHTTP・WebSocket通信、終了を確認します。
2. 変更したソースをコミットし、startでT4を起動します。doctorで接続・GPU・モデル・ノードを確認します。
3. CLI、入力画面、ノード画面から生成し、画像と条件が保存されることを確認します。
4. collectを再実行し、保存済み画像が重複取得されないことを確認します。
5. 完了済み要求と実行中要求を用意し、通常終了と強制終了の待機・保存・履歴を確認します。
6. 所有する監視とSSH接続を停止し、stopによる既存GPUへの再接続、回収、最終ログ取得、GPU終了を確認します。
7. statusと公式CLIで残存GPUを確認し、接続待ち受けと所有する子プロセスが残っていないことを確認します。

外部接続は専用の識別情報がないComfyUIでも実施します。接続前、接続中、監視停止中、再接続後の要求を区別して確認してください。
終了後も外部ComfyUIが応答することを確認します。

## 保存先を変更する場合

モデル、画像、履歴、ログのファイル一覧とSHA256を保存し、移動後に照合します。履歴やワークフローの内容は書き換えません。
絶対パスを持つ仮想環境とVS Code用環境設定を再作成し、CLI、検査、エディター、GPU側の保存先を確認します。

## 記録する内容と制約

実機結果にはソースのコミット、実行環境、実施した手順、期待結果との差、終了確認を記録します。ローカルの画像・ログ・詳細結果は`.artifacts/`へ保存します。
PRには検証結果と残る制約を記載し、認証情報、接続トークン、私有ログを転載しません。

標準APIだけでは同じURLの外部サーバーの入れ替わりを完全には識別できません。別GPUサービスとローカルGPUは、使用する環境で確認が必要です。
PCの電源断、ランタイム消失、監視が確認する前に失われた画面の要求は、回収や終了を保証できません。
