# 目的と範囲

## 利用者の目的

ストーリーから本文付き画像を順次生成し、標準画面で細部を編集しながら、作品と再現に必要な条件・素材をPCへ残します。通常の生成ではGPU側の接続先や転送先を指定せずに利用できます。

## 現在の提供範囲

Python CLI、ComfyUI標準API・App Mode・Node Graph、公式Colab CLIを組み合わせます。Colab T4または起動済みComfyUIへ接続し、プリセット、モデル準備、生成・回収、入力・保存ワークフローの保全を扱います。

作品と資源の正本は作業フォルダーの.artifacts/dataです。外部GPUは計算と一時キャッシュを担当し、Driveへ永続保存しません。通常の品質ゲートではGPUを確保しません。

## 制約

一つの作業フォルダーで一つのセッションを管理します。GPUの新規確保は明示的なstartだけです。PCの電源断やログアウトでGPUが停止する保証はありません。未保存の画面編集、拡張ノード独自のファイル、動画・音声、認証必須モデルの自動取得は対象外です。

## 今後の目的

日本語ストーリーから1〜8場面の本文・人物・場面を計画し、起動済みセッションで画像を順次保存できます。長編の分割計画や複数プロンプト入力の候補は[今後の候補](../plans/future.md)で管理します。

## 用語

| 用語 | 意味 |
|---|---|
| 作業フォルダー | komaquill.tomlと.artifactsを置く利用単位。Gitは必須ではない |
| 生成セット | 生成条件、画面グラフ、APIグラフ、入力対応の一式 |
| 画像プロファイル | 起動時に選ぶ生成セットのID。profilesの先頭が既定 |
| LLMプロファイル | 接続先、モデル、認証の参照を持つ計画用設定 |
| 計画 | 原文、人物共通設定、順序付き本文と描く瞬間の不変の記録 |
| 生成試行 | 一つの計画を固定した画像設定で生成する単位 |
| 資源 | checkpoint、LoRA、アップスケーラーなどのモデルファイル |
| 回収 | GPU側の結果を検証し、PCへ保存して履歴を確定する処理 |
| 素材 | 入力画像・マスクと、明示的にSaveしたワークフロー |
