# 検証手順

## 対応環境

Windows x64とARM64でPowerShell 7を使用します。ARM64ではx64 Pythonを使用します。CIはWindowsとLinuxで実行します。
ColabのGPUはT4、既定モデルはPony Diffusion V6 XLです。SD 1.5 FP16は比較用に残します。Python、公式Colab CLI、ComfyUI、フロントエンドはリポジトリの固定値を使用します。
外部接続にはComfyUI標準API、モデル、必要な標準ノードが必要です。

## 自動検査

環境を有効にし、次を実行します。

```powershell
python scripts/check.py
```

すべて終了コード0で完了することを確認します。検査結果は`.artifacts/reports/quality/`、テスト用の一時ファイルは`.artifacts/tmp/pytest-プロセスID/`へ保存します。

| 対象 | 確認内容 |
|---|---|
| 要求と回収 | 受付不明の照合、部分取得の再開、不正な応答・読めない履歴が混在する場合の回収継続、重複防止 |
| 画面の要求 | キュー上の条件保存、同じIDでの完了画像の保存 |
| 終了 | 通常・強制終了、監視停止後の復旧、再接続・表示・回収の異常時もGPU終了を試行、所有記録の保持 |
| ログ | 個別取得、既存ファイルの保全、秘密情報の除外 |
| 外部接続 | 接続前の画像の除外、未回収要求の再照合、外部サーバーの継続 |
| 構造と保存先 | 依存方向と循環参照、.artifactsへの統一、Gitと配布物からの除外 |

## Colabと画面の実機検証

GPUを消費するため、自動テストとは分けて実施します。Google認証は本人が端末で行います。

1. 公式CLIや転送経路を変更した場合は、CPUで作成、コード実行、ファイル往復転送、同じSSH接続上のHTTP・WebSocket通信、終了を確認します。
2. startでT4を起動し、転送物のコードハッシュとバージョンを記録します。doctorで接続・GPU・モデル・ノードを確認します。
3. CLI、App Mode、Node Graphから生成し、画像と条件が保存されることを確認します。
4. collectを再実行し、保存済み画像が重複取得されないことを確認します。
5. 完了済み要求と実行中要求を用意し、通常終了と強制終了の待機・保存・履歴を確認します。
6. 所有する監視とSSH接続を停止し、stopによる既存GPUへの再接続、回収、最終ログ取得、GPU終了を確認します。
7. statusと公式CLIで残存GPUを確認し、接続待ち受けと所有する子プロセスが残っていないことを確認します。

外部接続は専用の識別情報がないComfyUIでも実施します。接続前、接続中、監視停止中、再接続後の要求を区別して確認してください。
終了後も外部ComfyUIが応答することを確認します。

## 保存先を変更する場合

モデル、画像、履歴、ログのファイル一覧とSHA256を保存し、移動後に照合します。履歴やワークフローの内容は書き換えません。
絶対パスを持つ仮想環境とVS Code用環境設定を再作成し、CLI、検査、エディター、GPU側の保存先を確認します。

## 記録する内容と制約

実機結果には日時、対象バージョンとコードハッシュ、確認できる場合のGitコミット、実行環境、実施した手順、期待結果との差、終了確認を記録します。ローカルの画像・ログ・詳細結果は`.artifacts/`へ保存します。
PRには検証結果と残る制約を記載し、認証情報、接続トークン、私有ログを転載しません。

標準APIだけでは同じURLの外部サーバーの入れ替わりを完全には識別できません。別GPUサービスとローカルGPUは、使用する環境で確認が必要です。
PCの電源断、ランタイム消失、監視が確認する前に失われた画面の要求は、回収や終了を保証できません。

## 確認済みの構成

パッケージ版0.1.0.dev0を、2026年10月23日16時台から17時台（日本時間）に検証しました。
2026年10月23日にWindows ARM64、x64 Python 3.12.15、uv 0.13.5、公式Colab CLI 0.7.5、T4、SD 1.5 FP16で確認しました。GPU側はComfyUI 63be2f9、フロントエンド1.55.18です。検証したGPU用コードのSHA256は6006c55e03dce0ad76ed7987d382ebec0a32d4f05cacdb8f035c7cc2fa522672です。

| 手順 | 結果 |
|---|---|
| CLI、App Mode、Node Graphからの生成 | 512×512画像と条件をローカルへ保存 |
| HTTP・WebSocket、再回収 | 接続成功。保存済み画像の重複なし |
| 設定変更と二重起動 | 起動設定の保持と二重起動の拒否を回帰テストで確認 |
| 通常終了 | 実行中の200ステップの生成を待って保存。ログ3点取得、GPU終了、所有記録削除 |
| 監視・SSHの中断後の強制終了 | 同じGPUへの接続を復旧。意図的に中断した未完了要求1件をlostへ確定して終了 |
| 終了後 | 所有記録・関連プロセス・18188番ポートの待ち受けが残っていないことを確認。再停止でも新規GPU確保なし |
| 保存済みデータ | 元のモデル・画像・履歴110ファイルのサイズとSHA256が一致。既存25件の画像とlost 2件を保持し、検証で画像4件とlost 1件を追加 |
| wheel | Gitを参照しない隔離環境で初期化、外部接続、生成・保存、転送物作成に成功 |

ComfyUIはCUDA最適化とTorchの非推奨機能について警告を出力します。uvは`venv --system`の指定が無効であることと、pylock読み込みが実験的機能であることを通知します。この構成で画像生成・回収・終了が成功することを確認しました。依存を更新する場合は警告の変化と実機の動作を再確認してください。

requirements形式への出力ではパッケージごとのインデックス指定を保持できず、別配布物を選んでハッシュ不一致となることを確認しました。GPU用は配布URLとハッシュを保持するpylockへ統一しています。uv 0.13.5のpylock読み込みは実験的機能のため、uv更新時は固定定義の照合と実機導入を再確認してください。

実機試験は起動済み接続に対して実行できます。次の試験自体はGPUを確保しません。

```powershell
$env:KOMAQUILL_LIVE = '1'
python -m pytest tests/live/test_live.py -q
$env:KOMAQUILL_LIVE_STOP = 'normal'
python -m pytest tests/live/test_live_shutdown.py -q
```

監視停止からの復旧と強制終了を確認する場合は、別の起動済みランタイムに対してKOMAQUILL_LIVE_STOPをrecovery-forceへ設定します。この試験は対象の所有IDと起動引数を確認してローカルの監視・接続を中断し、未完了要求を残してGPUを終了します。実機試験の環境変数は、通常の品質検査の前に解除してください。

## Ponyとプリセットの検証結果

2026年10月23日19時台から20時台（日本時間）に、Windows ARM64、x64 Python 3.12.15、uv 0.13.5、公式Colab CLI 0.7.5、T4で確認しました。ComfyUIとフロントエンドは63be2f9、1.55.18です。Pony V6 XL、Hyper-SDXL 8steps CFG LoRA、Real-ESRGAN anime 6Bはpresets.tomlの配布元とSHA256を使用しました。

最終のGPUコードSHA256は`d87623f653cdf1803843bd7bfdf6f99f328b29b4ee454ffe0d501bffc8b2c5ad`です。実機で動作したコードと、検証終了時のパッケージから作成したGPU転送物のコードハッシュが一致しました。

| 対象 | 確認結果 |
|---|---|
| 既定のstart | Pony標準だけを準備してApp Modeを自動表示。Promptへ例が入力され、変更せずRunで1024×1024を生成・保存 |

| 診断 | V1の一覧形式とV3のCOMBO形式を読み、選択したチェックポイント・LoRA・アップスケーラーを確認 |

| 通常終了 | 実行中の25ステップ生成を待って保存。ログ4点取得、GPU終了、接続終了、履歴確定、所有記録削除に成功 |

準備は新しいColabで約301秒、モデル取得・SHA256確認は約128秒でした。別の同時検証ではPony標準の初回生成49.3秒、App Modeの生成21.1秒、8ステッププレビュー15.2秒、元画像と拡大画像の生成28.0秒を記録しました。生成時間はComfyUIの開始・完了時刻による値で、キューの待機時間を含みません。同一セッション内のキャッシュ状態が異なるため、性能保証や公平なモデル比較には使用しません。

新しいColabではモデルを取得し直します。Google Driveへの永続保存を使わない構成では、この取得時間は残ります。再接続時は同じランタイム内のモデルを再利用します。

旧配布物10ファイルと実行記録に対応しないカバレッジ出力37ファイル、計3,490,415バイトを整理しました。現在と変更前の代表的な配布物、実行別レポート、作品、モデル、取得済みログは保持しています。詳細な検証結果・ファイル一覧・SHA256は.artifacts/reports/pony-live、pony-baseline、pony-cleanup.jsonへ保存します。

## バックグラウンド監視の検査

2026年10月23日、Windows・Python 3.12.15でGPUを使わない品質ゲートを実行し、350件のテスト、隔離wheel E2E、整形・lint・strict mypy・依存境界・配布物検査を確認しました。行カバレッジ94.19%、分岐84.01%です。

隔離wheel E2Eは、起動コマンドが終了してから外部ComfyUIのテストサーバーへ生成要求を送り、画像・生成条件の保存と監視の停止を確認します。外部サーバーが動作を続けることも確認します。プロセス識別・二重起動・設定差分・起動待ちの中断・停止の中断・破損した監視記録はGPUなしのテストで確認します。

LinuxとT4の結果は、それぞれCIと実機試験で別途確認します。この検査だけで実際のGoogle認証やGPU生成の成功を保証するものではありません。

## モデル準備の検査

2026年10月23日、Windows・Python 3.12.15・Node.js 24で418件のPythonテストと5件のNode標準テスト、隔離wheel E2Eを実行しました。行カバレッジ94.54%、分岐84.98%です。公開取得元の固定、同名別モデル、部分取得の再開、容量不足、取消、SHA256不一致、ローカル限定モデルの転送、準備完了とローカル保存の区別をGPUなしで確認しています。

既存モデル4件・9,876,036,259バイトを用途とSHA256別の配置へ移動し、移動前後のハッシュ一致を確認しました。画像・履歴・取得済みログは移動対象に含めません。T4と標準画面での結果は実機試験で確認します。
