# モデルの実行と評価

## 実行条件

画像モデルの配布元、固定リビジョン、SHA256、利用条件は[モデル台帳](../../src/backend/src/komaquill/resources/models/)を正本とします。[生成セット](../../src/backend/src/komaquill/resources/presets/)に標準ComfyUIのグラフと条件をまとめます。LLMは接続先とモデルを明示し、モデル一致と文脈上限を送信前に検査します。モデルの自動切り替え、SDKの自動再試行、外部トレースは使用しません。

実効設定のハッシュ、指示の識別情報、送信したメッセージ、受信した応答、構造検査、使用量を対応付けます。開始・受信・検証は追記する版として保持し、開始だけの要求を未送信と推測しません。本文・原応答・画像は私有データ、診断は安全なコードと識別子に分離します。保存の構成は[保存設計](storage.md)を参照してください。

## 機能の検証

通常ゲートは対応する入力と応答を持つFakeListLLMと、自分が起動したloopbackの擬似APIを使います。実LLMとT4は[受入実行器](../../scripts/acceptance/run.py)から明示許可して実行します。[呼び出し予算](../../scripts/acceptance/budget.toml)と[作業設定](../../scripts/acceptance/workspace.toml)を分け、同じ出力親フォルダーの試行は同じ作業場所と呼び出し台帳を使用します。失敗、修正、受付不明の試行も予算を消費します。

操作・呼び出し・画像の成功率、回数、使用量、不明値を記録します。再起動と重複確認では追加推論を行わず、保存済みの結果を読みます。実行器が確保したGPUだけを停止し、終了と所有記録の解消まで確認します。

## 品質の評価

構造の成立と、日本語・英語の自然さ、記憶、指定遵守、画像の品質を別々に判定します。[評価API](../../src/backend/src/komaquill/api/evaluations.py)は基準・版・対象・根拠・評価者を保持し、訂正を追記します。採否、選好、生成時の事実、後から確認したファイルの状態を混同しません。

[比較](../../scripts/evaluation/llm/compare.py)と[画像レビュー](../../scripts/evaluation/images/roleplay.py)は非決定的な出力の収集です。拒否と失敗も分母へ含め、成功例だけで改善率を報告しません。JSONの比較を、画像を実際に見た評価として扱いません。AI評価にはモデルと指示の識別情報を必要とし、外部AIへの送信や改善案の適用を記録操作から分離します。

学習やモデル登録の専用サーバーは導入しません。現在必要な実行・来歴・評価の責務を、既存のLangGraph、型付き契約、SQLite、標準ファイル保存で扱います。自動検査できない文章・画質・規約の妥当性は、対象と証跡を明示してレビューします。
