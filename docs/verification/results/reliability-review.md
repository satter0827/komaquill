# 基本動作と保存境界の再レビュー

## 対象と判定

確認日は2026年11月6日（JST）。基準版は`506dc42e03f071793c3b5ae1ebff095693a8d44b`です。修正後の製品コードのSHA256は`046ea172b010a9cafd5f5a749c9ce43db39df5619f0c2dc6883f4a6e031de78c`です。Windows ARM64上のPython 3.12.15、Node 24.15.0で確認しています。検査全体の対象版・入力ハッシュ・環境・成否は、各実行の`checks.json`と[PRのCI](https://github.com/satter0827/komaquill/pull/47/checks)を正本とします。

業務上の生成品質とは分けて、保存済み状態を失わず、基本操作が予期しない例外や無制限待機で止まらず、失敗を特定して再検証できることを受入条件にしました。コードと設定だけで判断せず、隔離したDB、実プロセス、HTTP、配布物の画面操作で確認します。

## 発見と修正

| 対象 | 原因 | 修正と回帰検証 |
|---|---|---|
| DBの喪失 | SQLiteが既存接続でもファイルを作成する | 明示作成と既存接続を分離。ファイル喪失・版情報欠損・再初期化を検証 |
| 実行上限 | 接続済み台帳の喪失を新規予算として扱う | 新規予約枠の作成と復元を分離。ファイル・行の喪失、再指定、並行予約、期限切れを検証 |
| DBの移行排他 | 公式Saverの接続が共有リースを取得しない | キャッシュ接続と短い接続の全てで同じリースを保持し、閉じた後だけ移行を許可 |
| LANの失敗応答 | 端末判定がルート用の例外処理の外にある | 外側のHTTP境界で型付き失敗と予期しない失敗を処理。登録上限、保存失敗、情報漏洩、ヘッダーを検証 |
| 検査プロセス | 親終了後に子を列挙できない | WindowsのJob ObjectとLinuxの専用プロセスグループで回収。正常終了・期限切れ・設定失敗・別プロセスの保全を検証 |
| LLM記録の追記 | 前の応答をハッシュ照合せずに読む | 不変オブジェクトの検証済み読み取りへ統一。破損した原本を保持し、追記を拒否することを検証 |
| 予算の接続情報 | JSONの形を検証せず添字で読む | 既存のPydanticで型・必須項目・範囲を検証し、安全な設定失敗へ変換 |
| 診断ログ | 排他待機に期限がない | 待機を有限にし、保存不能を返す。ログを占有しても処理が戻ることを検証 |
| 検証基盤 | 型検査の共有キャッシュ、期限切れ接続の再利用、TypeScriptテストの配置検査漏れ、管理自体の例外で未完了のまま残る記録 | キャッシュを対象ごとに分離。テスト用API接続を応答ごとに閉じ、再試行を無効化。配置検査に`.test.ts`を含める。予期しない管理失敗も終端として原子的に記録し、例外本文を除外 |

各障害は修正前の失敗を確認し、修正後に再実行しています。初期化に伴ってDBが作成される契約も見直し、移行元を作るfixtureは対象版のDBを明示的に用意するようにしました。初期化前に利用者が用意した設定は保持し、既存の保存フォルダーでDBだけを失った場合は空のDBへ置き換えません。

## 要件の達成範囲

構成、保存の正本、依存方向、文言、配布物、通常検査と実機検証の分離は、[要件台帳](../../requirements/catalog.toml)と[検証方針](../strategy.md)で管理しています。新しい汎用層は追加せず、SQLAlchemy・公式SQLite saver・Pydantic・pywin32とOS標準機能を使いました。

保存済みの会話11件、画像132件を現在の公開APIで読み直しました。作品の再変換、追加推論、追加画像生成は行っていません。実LLMと画像生成の既存の確認結果は[再設計の検証結果](reliability-redesign.md)を参照してください。今回の自動検査の成功を、新しい実機実行の成功として扱いません。

修正後は保存、上限、排他、HTTP、実行管理を再レビューし、関連検査を再実行します。最終の受入は、同じ対象版のformatter・lint・型・行と分岐のカバレッジ・画面E2E・隔離導入・WindowsとLinuxのquality・securityで判定します。修正途中の全体検査の失敗も証跡に保持し、成功へ置き換えません。
