# 共有する現在地と検証生成物の保持

状態: 採用。

## 判断

会話の主人公とキャラクターは常に同行し、現在地を一つにする。人物別の場所と同行判断を持つと、同じ場面の発言が非表示になり、移動と合流の操作も増える。服装・持ち物の識別は維持し、現在地だけを共有する。

明示入力の移動は受付時、自然文の即時移動は保存済みの解釈から確定する。自然文は移動後の状態を返答生成へ渡すため二段階とし、操作IDと公開する会話ターンは一つにする。段階ごとの記録と公式LangGraphチェックポイントを分け、移動後の失敗で移動を再実行しない。元の受付要求は変更しない。質問、条件付きの相談、予定を移動の許可にしない。

過去の人物別の現在地は保存アダプターで読み取る。公開契約には残さず、過去の本文・行動・状態・履歴ハッシュを新しい型で書き換えない。実行途中の旧ワークフローは版不一致として止める。

## 検証と保持

通常の検査と実LLM・GPUの受入を分ける。通常は固定応答と擬似APIで復旧・保存・表示の契約を検査し、実モデルは許可された台帳の回数と期限で本文の意味を確認する。構造上の成功を会話品質や画質の達成と同一視しない。

生成物は作成時に保持条件を決める。pytest、Playwright、Node標準の保持とteardownを使い、独自の汎用削除基盤を増やさない。検証用Python環境は完成世代と使用リースで保持を決める。原本、失敗、受付不明、予算台帳、所有不明の環境は自動削除しない。終了していない過去の記録は書き換えず、元の内容ハッシュと所有プロセスの観測を追記する。

## 移動と質問の同時入力

実モデルで、移動と質問を含む入力が通常の台詞として分類され、現在地が更新されない失敗を確認した。移動は返答の話者による分類から分離し、即時移動先または移動なしを必須項目として返す。移動確定後の応答は新たな移動を提案できない。実行形式の版を更新し、旧形式の実行中チェックポイントを再送しない。

## 持ち物の更新と情報への返答

実モデルで、合言葉を持ち物へ追加し、質問への返答で過去の一覧を復元する問題を観測した。生成応答の「変更後の全一覧」は、最新の入力に相手の物理動作が明示されている場合だけ返す。通常の質問は状態を維持する。語句を検索して物体を削除する後処理や、保存済みの原文・状態の書き換えは追加しない。型の成功と意味上の成功を分け、同じ固定入力で実モデルを確認する。

## 形式制約と項目の指示

送信経路を確認すると、Field.descriptionの説明は応答スキーマへ入り、会話指示には同じ定義が展開されていなかった。[LM Studioの構造化出力](https://lmstudio.ai/docs/developer/openai-compat/structured-output)はGGUFの文法制約を使う。文法に合うJSONであることと、項目の意味を理解したことを区別する。移動、持ち物、動作、台詞の説明を同じField.descriptionから会話指示のresponse_rulesにも渡し、二つの定義を別々に保守しない。旧実行中チェックポイントを再利用せず、原本は保持する。
