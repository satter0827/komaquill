# 会話表示と描画監視の分離

状態: 採用。対象: REQ-CONVERSATION-ALBUM-UX。

## 背景

画像部品が回収を行う構成では、一覧の表示数と通信量が結び付き、折りたたむと処理を失う。一方、未完了履歴の全件監視は過去の接続先への不要な回収を起こす。単発描画の受付結果を一覧更新だけに使うと、今回の結果も追いにくい。

## 判断

画像部品は保存済みRunまたは読み取り用Queryから表示する。アプリ直下のReact部品が、今回受付済みのRunと作成処理を監視し、Queryキャッシュへ結果を共有する。作成処理は画像IDがまだない段階から保持する。

実行状態の未完了一覧は現在の接続先に限定された一覧ではないため、そのまま回収しない。既存の操作別availabilityで対象セッションの回収が利用可能と確認できたIDだけを渡す。画像一覧の閲覧から監視へ登録しない。回収の失敗後は自動再試行を止め、明示的な取得再試行を使う。

日付ごとの表示は保存日時から導出し、折りたたみ内の画像を開いたときだけ描画する。完了画像を別の進行欄へ複製せず、該当日の結果へリンクする。受付不明では同じ要求IDを照会し、送信を自動で繰り返さない。

手動の「送信結果を確認」も既存の読み取りAPIだけを呼ぶ。生成を伴う送信の再実行と、冪等なローカル保存の再実行を同じ文言で扱わない。保存は「保存を再試行」と明示する。画像枠の縦横比は正常な画像の表示に使い、失敗の説明と復旧操作には内容に応じた高さを使う。

受付応答の喪失は未受付の証明ではない。今回送信したIDの読み取りはページの寿命から分離し、アプリ直下の画像・作成処理の監視へ引き継ぐ。単発描画の受付確認にも既存のRunのQueryを使い、別の受付専用キャッシュは持たない。確認できたRunだけを回収へ渡す。履歴の全件走査や汎用ジョブ基盤は追加しない。

操作ごとの接続判定は操作側に保持し、サイドバーは既存結果の表示だけを担当する。表示のための照会や、全機能共通の実行可否は追加しない。

## 制約

公開API・Run・原画像URLと保存形式を再利用する。DB移行、汎用ジョブ管理、独自ビューアーは追加しない。原画像は別タブ、保存と終了はブラウザー標準機能を使う。React内の監視はブラウザーを閉じた後の常駐処理にはならず、サーバーの処理と監視の契約を変更しない。

会話・画像の表示結果と機能検査を、モデルの生成品質の達成とは分けて評価する。
