# モデルと生成セット

## 定義と標準構成

同梱する生成セットは`klein-4b`、`klein-4b-edit`、`klein-9b`、`klein-9b-edit`です。末尾の`-edit`は参照画像による編集を表します。既定は4Bで、9Bは明示的に選びます。モデルの配布元、固定版、SHA256、用途、利用条件は[モデル定義](../../src/komaquill/resources/models/)、生成条件と入力対応は[生成セット](../../src/komaquill/resources/presets/)を正本とします。

各モデルの生成と編集は、同じ規模のDistilled本体、ponpoke版エンコーダー、Party Time、Klein Fixesを共有します。VAEは4B・9Bで共通です。モデル規模の混在は起動前に拒否します。LoRAは標準のLoraLoaderModelOnlyで直列に接続します。取得前に配布条件を確認してください。公開モデルであっても無条件に商用利用できるとは限りません。

`preset.toml`は条件と資源参照、`workflow-api.json`は標準API、`workflow.json`は標準画面を定義します。公式テンプレートの固定版、元ファイルのSHA256、利用条件、変更点は各セットのprovenance.tomlとLICENSE.upstreamに保存します。追加の計算ノードは導入しません。

## 入力と画面

CLI、Python API、App Mode、Node Graphへ同じ資源と生成条件を適用します。App Modeの入力はプロンプト、候補数、編集用参照画像です。LoRA強度、サンプラー、寸法などはNode Graphで編集します。ブラウザーの編集内容はGitへ書き戻しません。生成記録には実行されたグラフを保存します。

更新後は、普段使う作業フォルダーのチェックアウト、Python環境、CLIとVS Codeの読み込み元を揃えます。別の作業ツリーの変更やPRの統合だけでは、起動済みGPUや古いチェックアウトは更新されません。停止後に更新済みの環境から起動し、実行グラフと資源を確認します。

ブラウザーに残るタブ、保存ワークフロー、復元状態と、GPUが配信するテンプレートは別の保存物です。不要な生成器は必要な条件を確認してから標準操作で整理し、再読み込みと再開で戻らないことを確認します。対象のlocalhostに属する保存物だけを扱い、公式のテンプレートカタログや他サイトの保存情報は変更しません。

保存済みワークフローはローカルの素材記録から新しいGPUへ復元されます。GPU側のファイルやブラウザーのタブだけを消しても、復元元が残れば再表示されます。明示的に廃止する場合は、停止を確認したうえでローカルの保存物と索引も同じ対象として整理します。通常のモデル切替では利用者の保存物を自動削除しません。

Kleinでは負プロンプトを使用しません。CLI/APIとJSONに負プロンプトの項目はありません。`subjects`は対象ごとの説明として保持し、全体プロンプトへ結合します。領域や人物同一性を保証する入力ではありません。

`positive_prefix`は生成セットが管理する品質用の既定文です。`quality_enabled`で付加を制御し、利用者の説明と分けて保存します。LLMへモデル固有の品質タグを生成させません。

## 設定と保存

運用設定は[defaults.toml](../../src/komaquill/resources/settings/defaults.toml)、作業差分はkomaquill.tomlです。`[presets.klein-4b]`などで宣言済みの条件を上書きできます。モデルやグラフの構成を変える場合は、一式を作業フォルダーのpresets/IDへコピーします。検証済み設定は起動時に確定し、再開では保存済みの入力、seed、設定を使います。

モデルは`.artifacts/data/models/用途/SHA256/`へ保存します。必要な全資源をローカルで取得・照合してからGPUを確保します。認証が必要なモデルは取得済みのファイルをSSH経由で転送し、GPU側でもSHA256を照合します。資格情報をGPUへ送りません。

候補数は標準潜在画像ノードのbatch_sizeです。一要求の候補とキューへの繰り返し送信を区別します。primary_output_nodeが最終候補を識別し、バッチ位置とバッチのseedを保存します。先頭候補を採用済みとは扱いません。

旧作品の設定スナップショットは保存済みJSONとして読み取ります。現在の生成設定型で再検証しません。旧生成セットによる新規生成や暗黙の代替は行いません。

## 正条件と保存形式

標準のBasicGuiderへ正条件だけを渡します。CFGの設定と負条件の枝はありません。新しい画像入力は版3、コンパイル済み入力は版4、コンパイラーは版7、場面設定は版3です。共通文と個別指示は空の要素を省いて結合します。

過去の入力と設定は専用の読み取り型で検証します。元の条件とグラフを現在の既定値へ置き換えません。保存済み要求の回収は維持し、古い入力を新しい要求として送信しません。旧プリセット名の別名はありません。

## GPUと使用量

`start --gpu A100 --high-ram`またはPython APIの同名引数で明示選択します。指定がなければ環境変数、作業設定、既定値の順に従います。起動後の設定変更は現在のセッションに反映しません。`usage`は残CU、CU毎時、割当数、観測時刻を返します。失敗は型付きの失敗として返し、残量0へ置き換えません。

任意のCU上限を設定すると、残高の基準を作業フォルダーへ保存し、再接続や次のセッションへ引き継ぎます。期限や停止用の予約量へ達した場合と、照会・アカウント・割当に不明点がある場合は追加送信を停止します。

SSH転送は資源ごとのバイト数・時間・SHA256を記録します。再利用はGPU上のSHA256一致が条件です。転送前の速度計測と準備・検証の見積もりが送信期限に収まらない場合は、大容量転送を始めず終了します。
