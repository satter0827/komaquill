# 会話状態・保存受付・長期要約の境界

状態: 採用。日付: 2026-11-01。

## 背景

自由な状態辞書の全置換で服装や持ち物が失われ、過去の場面説明が現在地を上書きしていた。画面が保存後に画像を要求する構成では、編集した値、保存した版、生成中の画像の対応が分かれ、完了の反映も画面からの取得へ依存していた。

小さいモデルでは省略可能な変更差分が応答から抜けた。型として成功しても、本文と保存状態が一致しない場合があった。

## 決定

人物定義、人物別の現在状態、変更差分を共通の小さな型にする。モデルには変更後の全状態を先に返させ、Pythonが検証して差分へ変換する。未指定の人物情報は維持し、明示的な解除と区別する。本文と状態を同じDBトランザクションで確定する。構造の検証を意味の正しさの保証として扱わない。

保存と画像受付はPythonの機能処理へまとめる。同じ操作IDの受付結果を保存し、同じ内容の再確認で保存や生成を繰り返さない。対象、版、用途、進行中操作の制約を短いトランザクションで検証する。通信はその外で行う。

完了照合は画像回収、監視、起動時、明示的な取得から呼ぶ。画像記録がまだない場合と破損した場合をアダプターで区別し、任意のプリセットの照合失敗でGPU停止や正常画像の回収を止めない。失敗と復旧の変化だけを記録する。

一要求の実行・検証・有限の修正には既存のLangGraphを使う。古い確定履歴は[LangMemのsummarize_messages](https://langchain-ai.github.io/langmem/reference/short_term/)で要約し、直近の完全な会話の組を残す。要約の範囲、元本文のハッシュ、モデル、指示、言語を既存のSQLiteへ保存する。通常の一応答を常時二段のモデル呼び出しへ増やさない。

会話・操作・画像との確定を既存DBが担当するため、別のSqliteSaverと永続状態を重複させない。独自の要約エージェント、検索サーバー、汎用キューを追加しない。標準SDKの型、通信、認証をdomainと機能処理へ持ち込まない。

## 影響と制約

公開入力はJSON文字列から型付きの人物・舞台へ変更する。旧APIの別名は追加せず、停止確認、バックアップ、内容ハッシュの照合を伴う明示移行を行う。明確に対応する状態だけを変換し、推測が必要な記録は原文を保持して読み取り専用にする。

要約は追加の呼び出しと誤りを伴う。元本文と現在状態を保持し、要約で置き換えない。人物の役割、動作の主体、年齢、画像の人物数は実出力で別に確認する。実測結果と残る未達は[検証結果](../verification/results/conversation-state-and-images.md)、現在の契約は[設定と作成](../current/creators.md)を参照する。

## 再レビューでの判断

実4Bによる複数の入力形式、行動抽出、ツール呼び出しの比較でも、移動や行動主体の未達は解消しなかった。効果を確認できなかった独自の二段処理は採用しない。要約では各ターンの確定状態と固定した人物の役割を根拠へ追加し、消費する入力とハッシュの契約を対応させる。構造上の成立と意味の正しさは引き続き分けて確認する。

WAIの人物を含まないバナーは、英語の場面抽出と生成セットの用途別条件を併用する。既存の標準ノードへ正負の入力を渡し、新しいノードや生成ループを追加しない。用途と適用した入力を保存し、再開で同じ条件を維持する。

## 文脈管理の更新

自由文の要約と履歴の投影に関する現在の判断は[原文を根拠にした会話](0018-source-backed-conversation.md)を参照する。本文は当時の判断として保持する。
