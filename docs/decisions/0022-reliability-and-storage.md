# 基本動作、保存、検証範囲の再設計

## 判断

Pythonは層を上位、機能をその内側に置きます。Reactはapp、features、shared、生成APIへ分けます。testsは対象・検証範囲・機能の順に配置します。決定的な開発検査をtools、実接続と評価をscripts、環境導入をbootstrapへ分け、逆依存を禁止します。

DBは関係・状態・構造化された確定記録を担当します。SQLiteの外部キー、一意制約、JSON整合性検査、索引を使います。状態の検索に必要な値はJSONから生成し、別の書き込み対象を増やしません。画像・実行条件・LLMのwire記録は不変オブジェクトへ分離し、論理キーとの対応をDBで確定します。

LLMの要求、応答、検証結果は追記する版で残します。使用量は最新の版から導出し、不明値をゼロへ置き換えません。予算はSDKに割り込まずアプリケーションの推論境界で予約し、再起動しても戻しません。

家庭内LANのTLSとComfyUIの転送には標準Caddyを使い、端末単位の承認と失効だけを実装します。ユーザーアカウント、独自の認証サーバー、独自の計算ノードを追加しません。

## 理由と制約

単なるファイル移動では、検査対象の漏れ、DBの参照不整合、送信済み要求の重複、ソース版だけの成功を防げません。依存と保存契約を検査し、配布wheelのCLIからブラウザーまで確認します。失敗と中断をAIが識別できる証跡を残します。

すべてのJSONをオブジェクトへ移すと、状態検索と更新のために別の索引・キャッシュの整合を管理する必要があります。構造化された状態と確定ターンはSQLiteのトランザクションで保持し、自由形式の通信記録とバイナリを分ける構成にします。原本を上書きする移行や通常処理の旧パスへのフォールバックは追加しません。

有限の検査だけでは任意のGPU・モデル・ネットワークの成功を保証できません。通常ゲートと実機検査を分離し、対象版、設定、環境と終了確認を明示して結果を評価します。

WindowsのHTTP実行は標準のSelectorEventLoopを使用します。対応中のPython 3.12では、接続切断時にProactorの後始末が中断する問題を実ログで確認しました。[CPythonの修正](https://github.com/python/cpython/pull/160909)は対象ランタイムに含まれていません。HTTPサーバーと実機確認で同じ実行関数を使い、ソケット通信に不要な非同期サブプロセス対応を要求しません。外部プロセスは既存の同期アダプターで扱い、標準ライブラリ内部へのパッチや例外ログの除外は追加しません。LinuxはUvicornの標準実行を維持します。
