# 生成物を確認して整理する

対象は再作成できる検証環境、キャッシュ、一時データ、役目を終えた検証記録です。作品の削除、DBの再初期化、モデルの入れ替えとは分けて実施します。配置は[生成物の配置](artifacts.md)、正本の保全は[バックアップ](backup.md)を参照してください。

## 削除前に残すもの

- 原因、対象コミットと入力ハッシュ、再現条件、修正、検証結果、未確認事項を文書へ残す。
- 成功した検査の対象範囲、個別結果、実行条件を残す。古い成功を現在版の成功として扱わない。
- 未解決の失敗、受付不明、実LLMの原応答と予算台帳、GPUの終了確認、移行前の原本を保持する。
- 最新の受入結果と、問題を説明できる代表的な画面・トレースを保持する。
- 個人の作品、LLM本文、画面、接続情報は私有の`.artifacts/`へ置く。公開文書には原因と確認結果だけを記載する。

`run.json`だけで判定せず、ブラウザー検査は`index.json`の個別結果と証跡の検証結果も確認します。過去の形式に新しい項目がない場合は、保存されている事実から判断し、不明値を補完しません。詳細ファイルを後で消去した場合は、その記録を別に残し、保存時の証跡検証結果と現在の利用可能性を区別します。

## 候補台帳

削除候補には、解決済みの絶対パス、種類、容量、候補にした理由、保持対象、実行前条件を記録します。容量は論理ファイルサイズであり、ディスク上で実際に解放される容量とは区別します。リンク、ジャンクション、読み取れない場所、用途不明の環境は確認対象へ回します。

台帳の`candidate`は削除の許可を意味しません。`review`と`retain`、台帳にないパスは削除対象にしません。調査後に利用者が削除を禁止した場合は、過去の削除許可を使わず、文書と候補台帳の作成で止めます。

## 実行前の確認

1. 対象と保持物を利用者が確認し、削除の許可を得る。
2. 所有プロセスのPID、開始時刻、用途、ファイル使用状況を再確認する。必要な停止は削除とは別に実施する。
3. パスを再解決し、意図した作業場所の内側にあることと、リンクをたどらないことを確認する。調査後に内容が変わった候補は除外する。
4. 正本、予算、移行原本、未解決の失敗、最新の受入結果が保持されていることを確認する。
5. 候補単位で実行し、成否と実際の空き容量の差を記録する。複数フォルダーの一括原子性は仮定しない。

SQLiteのDB、WAL、SHMは、用途と停止を確認した作業場所の一式として扱います。正本DBの付随ファイルだけを容量対策として削除しません。パッケージ管理のキャッシュは、その環境に設定された保存先を確認して標準の整理機能を使います。

既存の`clean`は既知のキャッシュ、一時データ、配布物を保守的に扱います。すべての検証記録や旧環境を消去できるという意味ではありません。対象を広げる際も、作成元と保持条件が確認できるものに限定します。

## ワークツリー

作業ツリーがcleanでも、未統合コミットやGit管理外の作品・検証結果が残る場合があります。ブランチとコミット、未追跡・無視ファイル、稼働プロセスを別々に確認します。必要なコミットは検証可能なGit bundle等で保全し、必要なGit管理外データも保全してからGit標準のワークツリー削除を使います。フォルダーの強制削除で登録だけを残さないようにします。

## 増加を抑える改修案

以下は未実装の案です。保持条件と受入テストを決めてから実装します。

- 通常の画面検査はPlaywrightの`retain-on-failure`と`only-on-failure`を使い、明示的な画面レビューは必要な成功画面も残す。再試行なしの検査に`on-first-retry`を使わない。[Playwrightの記録設定](https://playwright.dev/docs/test-use-options#recording-options)
- pytest標準の一時フォルダー世代管理を利用する。作業場所内への配置と並行実行の分離を維持し、失敗証跡を退避した後の保持数・保持方針を設定の正本で管理する。[pytestの一時フォルダー管理](https://docs.pytest.org/en/stable/how-to/tmp_path.html#temporary-directory-location-and-retention)
- Nodeのテストで作成する一時フォルダーには標準のteardownを対応させる。削除失敗を黙って無視せず、検査結果と後始末の結果を分けて残す。
- 検証用wheelの環境は、現在の環境と必要な再現対象を選んで保持する。生成されるたびに全世代を無期限で保持しない。
- 検査の所有PIDと開始時刻、実行ID、終端状態を対応させる。強制終了後の観測は追記し、古い記録を成功へ変更しない。

実測と対象別の候補は[2026年11月6日の調査](../verification/results/storage-review-20261106.md)を参照してください。
