# 会話・画像・停止確認の再レビュー

実施日: 2026-11-01（日本時間）。対象: REQ-CHAT-WORKFLOW、REQ-CHAT-STATE、REQ-CHAT-MEMORY、REQ-CHARACTER-PRESETS、REQ-STORY-PRESETS、REQ-PLAY-EXPERIENCE、REQ-CREATOR-ACCEPTANCE。

## 達成状況

保存・選択・会話・専用ボタンでの描画・再開、単一プロフィール、日英の操作、生成物の集約は実装済みである。今回の再レビューでは、応答打ち切りの分類、要約の根拠、バナー条件、Windowsの停止確認を修正した。会話の行動主体や即時移動、要約の忠実さ、画像の年齢と同一性には未達が残る。全要件の実出力の受入を完了とは判定しない。

## 修正と再確認

| 問題 | 原因と修正 | 確認 |
|---|---|---|
| 応答の打ち切りが接続失敗になる | SDKの終了理由付き例外を一般の通信失敗と扱っていた。出力上限と応答フィルターの例外を応答不正へ分類する | 一回だけの呼び出し、履歴保持、安全な失敗記録を回帰検査 |
| 要約の根拠から状態が抜ける | 台詞と描写だけを渡していた。人物の役割と各ターンの確定状態を渡し、内容ハッシュへ含める | 新規の契約版と既存ハッシュの保全、日英の保存・再開を確認。意味の誤りは残る |
| バナーに人物が入る | 空の風景という文章だけでは抑制できなかった。WAIの生成セットへバナー用の正負条件を追加 | 同じ説明・seedの一組で、人物が見える画像から人物の見えない画像へ改善 |
| Windowsの移行確認が止まる | 全Pythonプロセスのopen_filesで停止した。Restart Managerで対象ファイルの利用者を直接照会する | 実プロセスによる保持・解放、移行、照会失敗時の停止を検査。キャッシュ整理も同じ境界へ変更 |

画像の条件は送信前に一回だけ適用し、根拠の文とハッシュを保存する。再確認、再開、用途変更時の競合、負入力を持たないモデルへの非適用を検査した。既存の作品や保存済み生成条件を変更していない。

Windowsの照会はアプリを停止・再起動しない。取得失敗や利用者一覧の変化を「未使用」と推測しない。[Microsoftの標準API](https://learn.microsoft.com/en-us/windows/win32/api/restartmanager/nf-restartmanager-rmgetlist)を使い、Windowsでの[全ファイル列挙の制限](https://psutil.readthedocs.io/stable/#psutil.Process.open_files)を回避する。

## 実4Bと9B

保持済みの同じ履歴、状態、最新の発言を使い、4条件ずつ比較した。9Bの利用は比較だけの明示許可による。アプリの既定モデルを変更せず、自動切替も追加していない。

4Bでは、日英の海への移動が台詞だけにとどまる、コートを預かる文章と状態が一致しない、相手への着替えを自分へ適用する問題を再現した。9Bでは日本語のコート受け渡しと英語の移動状態が改善したが、日本語の移動漏れと英語の人物の取り違えが残った。英語の移動では台詞へ三人称の描写も混ざった。失敗例を選んだ限定比較であり、モデル全体の精度や改善率とは扱わない。

出力形式、行動抽出、ツール呼び出し、応答後の状態の項目名を変える比較でも安定した解消を確認できなかった。効果を確認できない独自の二段処理は採用せず、試作と判断を非公開の記録へ保持した。

## 要約と実WAI

要約ありと全文参照で、日英とも灯台の青い扉を参照できた。保存済みの要約を再起動後に再利用した。ただし元の目的にも同じ事実が含まれるため、記憶精度の向上は立証していない。日本語の要約にはコートを着ている状態と脱いだ状態の混在、英語には指示に反する状態一覧が残った。要約で元の会話や現在状態を上書きしない。

T4とWAIで4画像を生成し、全画像を実際に見て比較した。バナーの一組では用途別条件の効果を確認した。32歳の女性の一組ではLoRAの強さを通常値から無効へ変えても高齢に見える表現が残った。この結果だけでLoRAを原因と断定せず、既定値は維持した。人物の年齢・同一性・雰囲気の遵守は未達である。
