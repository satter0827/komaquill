# 構成と設定

## 処理の分担

CLIが要求の記録とローカル保存を担当し、GPU側のComfyUIが画像を生成します。Colabの認証とランタイム操作には公式Colab CLI、接続にはOpenSSH、生成にはComfyUI標準APIを使用します。

| 区分 | 責務 |
|---|---|
| domain | 要求、状態、設定スナップショット、エラーコード |
| application | 生成、照合、回収、終了の判断 |
| interfaces | CLI引数、入力、英語表示、終了コード |
| infrastructure | HTTP、Colab CLI、SSH、ファイル保存、資格情報、接続の維持 |
| gpu | GPU側の環境準備とComfyUI起動 |

生成・回収はGenerationBackendとRunRepositoryのProtocolを使用します。Workspaceが設定、ワークフロー、出自、保存契約を束ねます。終了調整はShutdownActionsを受け取り、プロバイダーやファイル操作を直接呼びません。具体的な実装は接続・作業フォルダーの入口で組み立てます。DBや別の画面を追加する場合も、業務処理とこれらの契約を再利用します。

## 設定の優先順位

対応するCLI引数、環境変数、komaquill.toml、パッケージ内defaults.tomlの順です。設定は起動時に検証し、保存・回収・終了で同じ値を使用します。変更は次のstartから反映します。認証情報は設定へ含めません。

Pythonと依存の正本はpyproject.toml、uv.lock、.python-versionです。GPU用pylock.worker.tomlはロックから書き出し、URLとハッシュを固定して導入します。ComfyUIとフロントエンドはruntime/versions.toml、モデルと生成プリセットはresources/modelsとresources/presetsで固定します。

## GPUへの転送

GPU確保前に、導入済みパッケージのGPU用コード、固定依存、設定、ワークフロー、必要な文言から転送物を作成します。CLI、Colab制御、作品、モデル、認証情報、Git履歴は含めません。コードと転送物のSHA256を記録し、GPU側で検証して展開します。CLI専用の変更でGPU用コードのハッシュは変わりません。

Gitのコミットは出自の補助情報です。wheelからの起動にGitは不要です。ローカルのモデルを正本として検証し、GPU側は同じ固定リビジョンから取得したランタイム内の一時キャッシュを使用します。

## 保存と終了

要求は送信前、画面からの要求は観測時に記録します。受付不明の場合は再送せずIDで照合します。画像は検証後に一つずつ原子的に保存し、同じロックの下で履歴を更新します。必要な画像が揃うまでsavedへ進めません。複数ファイルを一括で原子的に保存する前提は置かず、途中停止後はチェックポイントから再開します。

終了は回収、ログ取得、GPU終了確認、接続終了、履歴確定、結果保存、所有記録削除の順です。前段の失敗でもGPU終了を試みます。確認できない終了や後始末の失敗では所有記録を保持します。外部サーバーは停止せず、その要求をlostにしません。

## 診断と秘密情報

操作ID、状態変化、経過時間、エラーコードと処理段階を記録します。正常なポーリング、プロンプト全文、認証情報、応答本文、例外本文・変数は記録しません。ログ取得はファイルごとに成否と最終成功日時を残し、失敗時は前回の内容を保持します。

Google認証と公式CLIの管理ファイルは標準のユーザーフォルダー、外部認証はOSの資格情報ストアを使用します。製品の保存先は.artifactsです。古い検査結果は現在の稼働状態を表さないため、現在の確認にはstatusを使用します。

## 資源とGPUの所有

モデル、LoRA、アップスケーラーの定義はresources/modelsとresources/presets、接続は標準workflow JSON、適用処理はinfrastructure/workflows.pyが担当します。生成・保存のユースケースはColabや画面の操作へ依存しません。起動時に資源とプリセットを含む設定全体を確定し、転送物のmanifestと接続記録へ保存します。

Colabの確保・実行・初回転送は公式CLIを使います。状態確認と対象指定の終了には同じ固定パッケージのClientを使い、公式CLIのローカルキャッシュを生存確認の根拠にしません。SSHは固定した公式実装の`_run_proxy_bridge`へ、プロバイダーで照合した一時SessionStateを渡します。この内部関数への依存は一つのアダプターに限定します。公式CLIのSSHコマンドには記録欠損時の自動確保があるため、再接続には使用しません。

RuntimeObservationはrunning、stopped、unknownと観測時刻を持ちます。終了調整はアカウントとエンドポイントが確認されたstoppedだけを受け付け、その後に未回収要求の確定と所有記録の削除を行います。プロバイダーの応答本文や一時トークンは子プロセス内に留めます。

## バックグラウンド監視

監視プロセスは作業フォルダーごとに1つです。OSサービス登録は行いません。起動端末でGoogle認証を完了した後、標準入力を切り離して起動します。PID、プロセス開始時刻、操作ID、確定した設定をstate/monitor.jsonへ記録し、プロセスの取り違えを防ぎます。

起動設定と監視状態、プロバイダーのGPU観測結果は別々に扱います。状態更新で最終観測時刻を更新し、ログへは段階の変化と失敗だけを追記します。監視が失われた場合は原因を推測せず、次のstartまたはstopで所有するGPUを照合します。

worker_execution_timeoutは公式Colab CLIがコード実行を待つ時間です。GPUの利用時間上限や自動終了設定ではありません。準備済みランタイムへの再接続では、所有ID、転送コード、確定設定を照合します。モデルの全体ハッシュ検証は新しい準備時に行います。

## 素材の保全

ComfyUI上の拡張は標準の書き込みと生成要求を観測し、一時領域に不変の版を作ります。ローカル監視は画像回収とは別に素材を回収し、内容と参照記録を保存してから確認を返します。停止時は新しい要求を抑止し、処理中の標準書き込みが完了してから最終回収へ進みます。

新しいrun.jsonの形式バージョンは2、素材・準備要求・モデル台帳は1です。既存の画像・履歴・取得済みログは書き換えません。DBや別の画面へ拡張する場合も、生成・保存の契約と実行環境の制御を分離します。

## ソースの配置

| 配置 | 責務 |
|---|---|
| domain | 状態・設定・モデル・失敗の契約 |
| application | 生成・回収・終了・準備・整理の判断と必要な境界 |
| infrastructure/sessions | 接続、起動、監視、終了の具体的な調整 |
| infrastructure/inspection.py | GPUとローカル記録の独立した状態取得 |
| interfaces/cli.py | CLIの入力と表示 |
| interfaces/comfyui | 標準HTTP拡張、素材観測、配信するJavaScript |
| gpu | 一時環境の準備とComfyUI起動 |
| resources/settings | 運用上の既定値 |
| resources/models | 共有するモデルの固定定義 |
| resources/presets/ID | 生成セットの3ファイル |
| resources/runtime | 固定バージョンとGPU依存ロック |

具体的な依存方向はImport Linterで検査します。ComfyUI用インターフェースはGPUへ配布しますが、CLI・Colab制御・ローカル監視は配布しません。詳細な状態と失敗は[契約](contracts.md)を参照してください。

## ローカルとGPUの保存先

WorkspacePathsはローカルのdata・records・state・runtimeなどを分けます。GpuPathsは一時ランタイムの配置を定義し、GpuProjectと起動前の進捗発行・取得で共有します。ローカルの保全分類をGPU側の進捗・ログへ無条件に適用しません。両者のファイル対応は発行と取得を結ぶテストで確認します。

## 保存と回収の境界

生成履歴はRunRepository、実体ファイルはArtifactStoreを使用します。通信はアプリケーション側で調整し、共有する状態更新ロックを保持したまま待機しません。要求・素材単位の排他と、確定前の状態・セッション再読込みで二重回収と終了後の状態後退を防ぎます。モデルは共通のハッシュ検証を使い、確認済みの不変ファイルを再利用します。
