# 生成物の配置

すべての製品データと開発生成物は作業場所の`.artifacts/`へ保存します。Git、wheel、sdistへ含めません。

| 配置 | 内容 | 消去の扱い |
|---|---|---|
| `data/komaquill.sqlite3` | 作品・要求・関連・確定履歴・再開チェックポイント | 正本。バックアップと停止確認が必要 |
| `data/objects/先頭2文字/SHA256` | 画像、入力、確定条件、LLM通信記録 | 正本。DBと対応を照合する |
| `data/archive` | 変換前の作品・履歴・通信記録の原本 | 閲覧専用。配置とSHA256を変換記録で照合 |
| `data/models` | 保持するモデルと取得情報 | 配布元・SHA256・再取得可否を確認する |
| `data/quarantine` | 検査で見つかった破損ファイル | 自動削除しない |
| `state` | 所有、接続、排他、監視、検証予算の参照 | 実行中・所有不明の記録を削除しない |
| `records/logs` | 安全な運用ログと取得済みログ | 取得失敗で前回内容を消さない |
| `records/reports` | 検証、探索、AI解析用の証跡 | 対象版・範囲・成否を確認して保持 |
| `records/migrations` | 変換前DB、一覧、ハッシュ、変換記録 | 復元に必要な原本として保持 |
| `outputs` | 共有用コピー、再生成可能な分析結果 | 正本と分けて扱う |
| `runtime` | Python、Node、依存、導入済み検査環境 | 所有プロセスを止めてから再作成 |
| `cache`・`tmp` | キャッシュ、一時ファイル、失敗したテスト環境 | 自分の実行の終了を確認して整理 |
| `build`・`dist` | 中間物と配布物 | 元の入力と対応するものを使用 |

実機検査は検証専用の作業場所を作成します。通常テストは作品・設定・ポートを共有せず、失敗した環境を調査用に残します。LLM本文と画像を含む証跡は非公開とし、外部AIへ自動送信しません。

容量を整理するときは、[生成物の確認と整理](storage-cleanup.md)に従って必要な知見・失敗証跡・最新の受入結果を保持し、候補台帳を作成します。検証用の作業場所にも正本と同じ形のDBやモデルが入るため、フォルダー名だけで一括削除しません。

既存アーカイブの保存配置と変換前のファイルは、現在の生成物と混同しません。配置を変更する場合は停止、一覧・SHA256、移動後の照合を行い、通常処理に旧パスへのフォールバックを追加しません。詳細は[保存設計](../current/storage.md)を参照してください。
