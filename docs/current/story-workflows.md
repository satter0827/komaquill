# 段階生成ワークフロー

## 責務

場面の計画は人物・動物・小物・出来事を定義し、生成セットは描画の工程を定義します。CLIとPython APIは同じ処理を使用します。場面内の工程はComfyUIの固定JSONで接続し、アプリケーションは場面間の依存グラフを実行しません。

story-referenceは画像参照による条件付け、story-composeは背景への段階的な配置、story-inpaintは文脈を含む切り出しと局所修正を扱います。追加ノードの正本はresources/runtime/extensions.tomlです。選択したセットに必要な固定版だけを取得し、追加のインストーラーや依存更新を実行しません。

この3系統は実験用です。工程の実装状態と、実画像の合格判定は別に管理します。画質と再現性の確認結果は[検証記録](../verification/results/staged-workflows.md)を参照してください。既定の生成セットは変更しません。

## 入力と条件

image_inputsは画像・マスク、resourcesは追加モデル、parametersは工程固有の値、parameter_boundsは数値範囲、seed_offsetsは工程のseed差分、output_stagesは中間出力の役割を宣言します。入力対応は既存のbindingsを使用し、式やコードを評価しません。

InputArtifactは内容のSHA256、論理キー、元の名前、寸法、用途を保持します。ローカルの絶対パスや接続先へ依存しません。マスクは白が編集対象、黒が保持対象の単一チャンネルPNGで、編集元と寸法を一致させます。

転送前に保存済み内容を再検証し、ComfyUI標準のアップロードと取得APIで配置・内容を確認します。新しい素材のGPU側ファイル名には内容ハッシュを付け、標準画面の選択一覧に現れる入力直下へ置きます。ローカルは内容ハッシュごとの保存を維持します。既存の入力参照は保存形式の版に従い、その値を変えません。

局所修正はマスク内の元画像を消去するVAEEncodeForInpaintを使います。この方式の既定denoiseは完全なノイズ付与とし、低い値を画像の保全方法として使いません。編集対象外は最後のマスク合成で元の画素へ戻します。参照強度を上げても外見の一致は保証されず、Ponyでは髪色や姿勢の転写が強く出ることがあります。

## 固定と再開

RenderConfigは全場面の位置、セット、素材、任意の画像説明・対象別説明・負プロンプト・工程パラメーターを指定します。計画の場面を過不足なく含むことと、全素材の読み取り・型・寸法・設定範囲を送信前に検証します。

各場面のセットのスナップショットと適用済み入力を生成試行へ保存します。再開時に元ファイルや作業設定を読み直して画像条件を作り直しません。条件や編集元を変更する場合は新しい生成試行とします。

候補はバッチ内の位置で対応付けます。背景の反復、局所生成、合成で候補の対応を維持し、別候補を一枚へ重ねません。seedは各工程のバッチ単位で記録します。

## 保存と失敗

素材は既存の入力保存、生成画像は既存のRunと作品保存を使用します。主出力と中間出力は出力ノード・工程・バッチ位置で区別します。本文と場面、生成要求、素材ハッシュ、実行グラフを分析用出力から追跡できます。

要求が失敗しても、履歴に公開された画像を個別に回収します。画像の保存を要求の成功へ置き換えません。生成失敗と回収失敗を分け、再回収によって生成失敗の原因を消しません。履歴に公開されない出力の復旧は保証しません。

旧形式の画像・計画・履歴は書き換えず、過去のセット指紋へ新しいフィールドを加えません。閲覧用出力と分析用出力は保存済み記録から生成します。

## 共通条件とキャンバスの契約

RenderConfigの形式2はcommon_promptを受け付けます。用途は天候・光・画風です。場面のpromptを指定しても共通条件は失われず、品質用プレフィックスとは別に合成します。利用者の指定と適用済みの本文はCompiledImageInputの形式3・compiler_version 5へ保存します。再開時はこの値を使用します。過去の形式や生成セットの指紋を変更しません。

画像スロットのmatch_baseは、配置済み前景などにbaseとの寸法一致を要求する宣言です。マスクの寸法検査と合わせて、全場面を送信前に検証します。前景の輪郭、局所補正、保護領域、雨の遮蔽は異なる用途であり、一つのマスクへ混同しません。宣言の検査だけでは、素材の自然さやノードの画素保持を保証しません。

## 保存と品質評価

新しいRunの形式5は、画像ごとのsaved_atと、最初の主候補の保存が確定したfirst_candidate_available_atを保持します。再回収で時刻を更新せず、補助画像を最初の候補として数えません。過去の記録の不明値は補いません。要求全体のsaved_at、ComfyUIの生成時刻、ローカルの画像利用可能時刻は別の事実です。

画像のSHA256が一致する主候補にはduplicate_ofを表示します。補助画像との一致を候補の重複判定へ混ぜず、画像を削除しません。同じバイト列は選択肢の増加と扱いません。

StorySnapshotの形式3、manifest、story.mdは生成要求に対応する既存の評価を参照します。completeは画像の保存成功です。採否や比較結果は評価記録を確認してください。訂正前の評価も履歴として残し、読めない評価IDは明示します。評価追加後の閲覧用ファイルは明示的なrefreshで再構築できます。

前景合成と低denoise補正は[素材確認の結果](../verification/results/foreground-composition.md)により未採用です。配布用のstory-composeとstory-inpaintを、未検証の比較グラフへ置き換えません。
